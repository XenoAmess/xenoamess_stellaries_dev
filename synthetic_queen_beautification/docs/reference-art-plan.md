# 参考图与合成女王肖像生成方案

## 本次目标与输入

用户在 2026-09-25 指定压缩包 `48a41bd11bc84ce80d7ac48e14d1be4b.zip` 内唯一的 JPG 作为新合成女王形象参考。参考文件已归档为 `assets/reference/cetana-reference.jpg`，1536×1024，SHA-256 `5cf0fbb85d01a0125c6ab07425481bbadde9ebec5166d28e4c1a8c97179f7d86`。其内容是同一角色正面、侧面和背面的三视图：浅色面部、金色眼睛、带角的银金色机械冠、金色环状光晕、深色金属躯体与浅金色垂饰。

本次用户要求生成人物替换图。当前范围是 `asset-audit.md` 中的 10 个肖像 DDS；剧情插画、对话背景、旗帜与图标留在后续阶段，不能把本次结果报告成全部 16 张图片已经完成。

## 新发现：原版肖像是动画网格的 UV 分片贴图

原版 `gfx/models/portraits/synthqueen/synthqueen_portrait_green.dds` 解码后是 1024×1024 的透明 UV atlas，并非一张可直接显示的全身照。脸、躯干、四肢、长发/披片、左右竖形装置与光环位于不同贴图片区，且由原版 `synthqueen_portrait.mesh` 和 `synthqueen_portrait_idle1.anim` 组装及动画。若把参考图或普通全身画像直接保存为同名 DDS，游戏中的角色会被切碎、错位。

静态像素比较确认：`mammalian` 与 `green` 完全相同；其他物种变体与 `green` 的差异集中在大致 `x=595–717, y=15–168` 的面部区域；`empty` 仅有极小差异。

2026-09-25 的 UV atlas 生成尝试已保存为 `evidence/rejected-uv-atlas-attempt-01.png`。图像生成工具输出 1254×1254 RGB，棋盘格已烘焙进画面，片区位置也相对原版漂移，不能给原版 mesh 使用。该候选仅作失败证据，不进入可安装包。

因此改用本仓库灰风 Mod 已使用的 Stellaris 静态 `texturefile` 肖像定义：**同一张新角色的静态肖像**供 `synth_queen` 和 9 个 `cetana_*` 键使用。此方案保留事件和领袖调用的键，但人物不再使用原版动画。为生效需要覆盖原版 `gfx/portraits/portraits/21_portraits_cybernetics_synthqueen.txt`；只改这 10 个肖像定义，并以原版文件基线做逐项结构化差异检查。后续若恢复动态变体，要另行制作符合 UV 的材质或网格。

第一次半身肖像生成和第二次背景提取均输出 1536×1024 的 RGB 图片，把棋盘格烘焙为像素，并未产生 alpha。因而改为向图片生成工具提交 800×350 深炭色横向画布，让其生成一张完整、不透明的外交肖像；取得的候选为 1896×830 RGB，宽高比与 800×350 基本一致。它将确定性缩放到 800×350，作为当前可测试的人物替换。深色背景会遮住原外交房间的一部分，须列为实机视觉验收重点；若效果不可接受，不以该候选发布。

## 生成与装配

1. 用内置图片生成能力，以用户三视图作为人物身份和材质参考，生成一张单人、深炭色纯背景、横向外交窗口的半身静态肖像。保持浅色面部、金眼、机械角冠、暖金环、黑金躯体和垂饰；无棋盘格、文字、水印或额外角色。
2. 逐个目视检查候选的人物比例、面部和盔甲一致性，特别检查环与头冠在横向裁切后的完整性。记录提示词、输入/输出哈希和候选判定。工具本次不能交付真实透明度，不把画出的棋盘格当成透明背景。
3. 只对审核通过的 PNG 做确定性尺寸及 DDS 格式转换，放在本 Mod 专用路径。复制并最小修改原版 `21_portraits_cybernetics_synthqueen.txt`，把 10 个键均指向该文件，不复制原版网格或动画，也不改危机事件。
4. 用 `open_kaishek` 校验覆盖的 P 语言文件；先在游戏中验证 `synth_queen` 和 `cetana_mammalian`，再按 `test-strategy.md` 检查全部键、对话、后期空白状态、存档重载和与灰风 Mod 并用。不能仅凭 PNG 正常显示便宣告肖像完成。

## 验收和风险

- 输出角色需明显继承参考图的脸、冠、光环和黑金机械身躯，并保持适合科幻危机角色的可读轮廓。
- 新静态肖像为完整深炭色背景；实机对话及领袖裁切可接受，背景矩形与原房间/窗口的边界不突兀；原版动态表情/肢体动画不再出现，这是本次方案的已知限制。
- 10 个原版肖像键都能读取替换文件；统一外观是本次有意设计，而非遗漏物种变体。
- 覆盖的原版肖像定义文件可能与其他修改同一文件的 Mod 互斥；需在验收记录中明确。静态方案能否覆盖全部原版使用位置以实机为准。
