# 「吞噬之心」独立 Mod 设计案

日期：2026-10-06。工作基线：`main` / `05490258d332c7a329de5323d038852d090763bc`。状态：设计稿，已完成源码调查和文档检查；尚未实现、未执行 Mod 验收。用户于 2026-10-06 确认 Mod 正式名称为「吞噬之心」、强度定位为「偏强爽玩」、普通星球吞噬周期为 3～5 年，并确认拥有 Nemesis 与「虚境之影」。其余数值仍是首轮原型候选。

## 本轮目标、范围与方法

将用户提出的「吞噬星球给母星增加人口和区划、战争供养单球经济、飞升强化岗位、天灾矿物舰队」细化为独立 Mod。按用户最后追加的范围，覆盖噬岩者、铁心灭绝者和种族洁癖；分别核实原版政体、飞升和资源规则，不假设所有路线共享同一种人口或经济。

本轮只读调查本机 Stellaris 游戏脚本和仓库既有设计研究，形成玩法、数值候选、技术边界、风险与后续验收标准。先建立本文，再创建 `eat_everything_origin/` 文档目录；本轮不创建可加载 Mod、改动既有 Mod、启动游戏、执行实机验收或发布 Workshop。

本机新基线：`C:\SteamLibrary\steamapps\common\Stellaris`，`launcher-settings.json` 为 `Cygnus v4.5.2 (9776)`。此前资料中的 `C:\Program Files (x86)\Steam\...` 和 4.5.1 仅属历史环境。

## 1. 设计结论与主题

建议制作独立起源「吞噬之心」：保留原版灭绝国策，让被吞噬的真实星球成为母星的永久区划容量；人口集中到母星，在正常采矿、发电、工业、科研与凝聚力岗位上生产，再供养下一轮战争。起源占一个起源槽，不额外占国策槽，也不自带灵能飞升或矿物舰船。

建议游戏内描述：

> 这个种族喜欢吃干抹净，包括星球。异族的灭亡只是第一道工序；地壳、海洋和最后一粒尘埃，都将成为母星继续生长的材料。银河可以有无数战场，我们只需要一个家。

三条成长各自承担实际用途：吞星提供空间和人口，飞升提高母星人口的生产能力，武力天灾把主力舰队的造舰资源转为矿物。矿物还要同时支付人口口粮、建设或岗位投入，能源维持舰队与设施；这构成可经营的资源竞争。

本设计从开局提供可见的母星收益，保留正常岗位基础产出。代价来自战争、殖民与消化周期、母星建设和集中防守，不再设计一个要求牺牲科研岗位去维持的强制衰退局势。单球是经营选择：稳定经济集中于母星，允许短期占有和殖民待吞噬星球，允许控制星系、空间站、船厂和轨道设施；不是「任何日期殖民地数量必须为一」。

### 1.1 女王·白绮：族群核心

用户追加指定女王·白绮为族群核心，以新上传 `character.zip` 中的全部 10 张人物图片为原设。女王作为族群意志的集中显现，与绑定母星共同承载「吞噬之心」主题；蜂巢、铁心与洁癖分别采用女王意识、主控意志接口及族群女王的风味解释，原版合法政体与人口体系继续独立适配。

本轮先制作半身肖像与全身立绘供用户审核；保留原设的银白淡紫发、紫粉瞳、眼镜和黑金翼饰，新增碎星冠饰、紫晶心核与女王礼装。用户已否决温柔正面的 V1，现行方向重点表现邪恶、冷漠、对无关生命的漠视、对非我族类的厌恶、为达目的不惜牺牲一切的狠辣果决，以及统治者的霸气和傲气；以冷漠俯视、克制轻蔑、黑金深紫王装和命令姿态重做 V2。透明 PNG 按用户要求由 EvoLink 制作。事件与 CG 围绕新开局、首次成功吞星、母星成长、实际灵飞及武灾矿物舰节点设计，待人物形象确认后展开；人物叙事不自动赋予领袖加成、替换统治者、新增强制牺牲或修改一次性结算合同。逐图调查、提示词、来源与审核状态见[女王美术与事件方案](../eat_everything_origin/docs/queen-baiqi-art-direction-2026-10-06.md)。

### 1.2 女王在玩法中的具体职责

女王是「吞噬之心」的意志与统御者，绑定母星是承载她的王座。首轮采用持续核心人物、事件发言角色与母星交互入口；她的作用覆盖吞星、归心结算、母星经营与战争供养。原版统治者和总督仍按各政体运行，独立女王领袖实体、技能树与复活是后续扩展候选。

| 职责 | 玩家交互与实际作用 |
| --- | --- |
| 王座与王庭整合 | 开局绑定母星，以女王统御解释既有 +2 容量、+10% 母星岗位产出候选；同一开局收益只应用一次 |
| 吞噬敕令 | 玩家在合法源星下令吞噬／拆解；按本族消化站、肃清等待、合法物质 Q 和 3～5 年普通星球周期执行 |
| 归心结算 | 女王结果事件展示真实新增容量、回迁人口、通用制造人口与余料；读取已经完成的结算，不在弹窗里再发一份奖励 |
| 觐见女王 | 母星上的候选只读报告入口，展示王座状态、C/G/D、兑换余料、活动任务与阻塞原因，帮助安排继续吞星或建设现有空间 |
| 万声一心 | 实际合法灵飞完成后，女王成为意志汇聚的叙事焦点，说明已获得的原版模板与岗位能力 |
| 以群星铸刃 | 武灾阶段 2 真实解锁矿物舰时展示完整事件；阶段 3/4 更新船型和维护说明，将母星矿物生产接回战争 |

成长阶段按成功合法物质 C 的 20／60／200 候选阈值呈现「碎星之冠」「群星归心」「万界王庭」，用于人物与王庭报告变化；经济成长仍由第 5 节统一计算。首次吞星按第一颗真正完成的源星单独判定，小星球也有事件；一次跨过多个阈值合并通知，关闭弹窗或重读报告不产生收益。

母星临时失守使王座失联，暂停新敕令与最终结算；夺回同一母星后恢复。母星永久毁灭终止本轮女王核心接口，不向其它星球免费复制成长。冷酷与牺牲意志主要通过命令和对白表现，首轮不额外引入周期献祭、饥饿掉层或停战惩罚。完整角色适配、交互口径、成长和事件合同见[女王玩法职责方案](../eat_everything_origin/docs/queen-baiqi-gameplay-design-2026-10-06.md)；所有新增交互均为设计，尚未实现。

## 2. 灭绝资格与版本范围

用户最初提出「石头人蜂巢噬岩者」，最后扩大到「所有灭绝」，并点名铁心和种族洁癖。据此设计目标覆盖原版可在开局选取的灭绝国策，先以三种传统国策走通完整闭环；同国策的非石质吞噬蜂群也在范围内。

| 路线 | 资格依据 | 人口与母星经济 | 飞升处理 |
| --- | --- | --- | --- |
| 石质噬岩者 | `civic_hive_devouring_swarm` 有效、蜂巢、石质主体 | 沿用原版吞岩的人口/资源随机收益；母星矿物兼顾石质口粮、建设和矿物舰队 | 有「虚境之影」时可走原版灵飞，仍需正常飞升和科技门槛 |
| 非石质吞噬蜂群 | 同一有效国策、非石质主体 | 新增拆解路径；制造当前主体物种人口，保留食物、能量、矿物与合金需求 | 同上；不能在缺 DLC 时伪造蜂巢灵飞解锁 |
| 铁心灭绝者 | `civic_machine_terminator` 有效、机械智能 | 拆解星球材料以制造当前主体机械人口；能源供人口与舰队，矿物供建设/岗位/矿物舰 | 有「虚境之影」可走原版机器灵飞；普通非特殊起源/国策配置的 AP 门槛比非机械多一项 |
| 种族洁癖 | `civic_fanatic_purifiers` 有效 | 同国策的有机、石质及合法机械主体分别使用原版维护体系；不把被肃清的外族直接同化成本族 | 原版允许的灵飞、基因或其它路线；推荐极端排外＋唯心的灵飞配置，最终合法性由原版限制判定 |
| 新版焦土两支 | `civic_scorched_earth` / `civic_hive_scorched_earth` 有效 | 本机 `is_homicidal` 也包含这两支；目标纳入拆解适配，需另查火山母星、食性、焦土改造和区划组 | 保留原版门槛；先完成专门兼容探针再开放，不能以传统三国策结果宣称此分支已兼容 |

使用明确的开局国策集合表达资格，不直接把 `is_homicidal=yes` 当作可选起源条件：4.5.2 的该触发器还包括后期巨兽天灾 perk，不是一个开局国策。仅允许肃清、普通排外、同化者、熵饮者及第三方「灭绝」定义不会自动取得资格；第三方需有独立适配合同。

上述资格保留各原版国策的政体、思潮、物种和 DLC 限制。本 Mod 不赠送 DLC 功能，不取消原版灭绝外交限制，不新增国策和飞升槽。进入游戏后各决议与结算仍复查起源及有效资格，失去有效资格时暂停新项目，不重复发放历史收益。

首轮实现基线仅承诺在当前 4.5.2 上研究；将来可写 `supported_version="4.5.*"` 前，需要检查实际计划支持的补丁。源码事实不替代跨补丁验收。

## 3. 一局游戏的经营节奏

| 阶段 | 玩家行为 | 本 Mod 的回报 | 仍要解决的问题 |
| --- | --- | --- | --- |
| 开局与首战 | 建正常矿电、工业与科研，使用灭绝国策打第一次战争；可先消化保证宜居星球 | 母星已有小幅岗位产出与容量收益；每吞完真实星球继续扩容 | 原版合金舰队、殖民船、部队、能源和国策要求；不等矿物舰才有收入 |
| 首轮吞星 | 征服并真正取得殖民地，保留本族消化站人口，正常肃清异族后完成吞噬 | 母星获得可建区划容量、归还消化站人口及对应路径的新人口 | 消化耗时、临时殖民地的规模与维护、区划建设队列、住房和舒适度 |
| 集中与飞升 | 母星增加矿电与城市/蜂巢/枢纽区划，配置原版科研/凝聚力区域，按正常条件飞升 | 集中人口共享母星设施、稳定度、治理及合法灵能收益 | 飞升、传统与科技机会成本；灵能并非所有岗位无条件同倍率增益 |
| 武灾主力 | 自行选取「化身天灾」，完成威慑与升级项目，在阶段 2/3/4 切换矿物舰 | 生产的矿物直接转化为更多舰队，继续取得吞星目标 | 舰队能源、矿物维护、舰队容量、船厂吞吐；合金仍用于未替换单位和基础设施 |
| 后期 | 巨大母星服务舰队与科研，选择继续侵略或停战经营 | 容量按吞星累计，停战保留所得，无饥饿倒计时 | 防守单点、岗位配置、帝国规模、巨型行星 UI 与性能；进入天灾阶段 5 的后果仍按原版 |

不能把「单球」写成免除帝国规模：人口、已建区划和星系仍有原版规模贡献。临时消化星球也是真实殖民地。首轮不额外赠送人口规模减免、舰容、伤害或船厂速度；先观察这条闭环本身的强度。

## 4. 吞噬流程与人口合同

### 4.1 母星与可食对象

母星绑定本起源开局的真实母星，保存独立星球引用；手动迁都不重新绑定，不重发开局奖励。新人口和回迁人口都明确送往绑定母星，避免原版 `owner.capital_scope` 在迁都后悄悄改变回报地点。

首轮可食对象为本国实际拥有、未被占领且无地面战斗的非母星自然实体殖民地。可以先殖民无人宜居星球再吞噬，付出原版殖民成本；不是只能吃敌国星球。居住站、环世界段、方舟、突触磨炼机、恒星、未殖民的熔融/荒芜等天体和已经破碎的星球不作为食材。转化过的自然实体星球是否可食按实际区划组探针登记，不把可殖民巨构误算成原生星球。

源星至少保留 `100` 实际本族人口作为消化站。若没有，启动决议从母星搬运 `100` 合法、非肃清本族人口；母星不足以搬运时禁用并说明原因，不免费生成种子人口。这样敌方最后一批人口被肃清时，源殖民地不会先自行消失。消化站在完成后回迁，同一批人口搬出与搬回净增为零。

异族继续执行原版权利/肃清。最终销毁前要求不存在仍被肃清的人口；未结束时进入「等待净化」状态，保持现有进度，不重复中间消费和结算，不先删掉异族再领取额外原版肃清收益。具体异族、同族子模板和机械权利必须按当前存档与原版判定，不用人口组数代替人口量。

母星被占领或不再属于本国时，暂停启动与最终结算。消化途中失去源星所有权则中止且不给母星奖励，已发生的原版损毁和原版中间收益保持；禁止恢复已经转给其它国家的任务。只有收回同一母星才能恢复成长，原有扩容量作为物理星球属性保留；被占领者可以夺取这颗大型星球，构成真实防守风险。若母星永久毁灭，不自动向其它星球复制其容量；幸存殖民地可以继续普通经营，但首轮没有「备用母星」迁移功能。

### 4.2 两种吞星适配路径

**噬岩者路径：保留原版核心收益。** 原版 `consume_world` 在途中随机发本族人口、矿物或合金，逐步增加损毁障碍；结束时吃尽余下空间、回迁剩余人口、销毁殖民地并转为 `pc_shattered`。本起源主要新增的是最终母星容量。不会再叠加另一份按星球尺寸赠送的人口礼包，避免把原版随机人口和新通用制造人口双发。完整消费、新人口的实际 `size`、原版冷却与末次补消费的顺序需实机确认；不以源码注释的「每六个月」替代真实一年计时旗标。

噬岩者末次回迁在本起源路径中改为绑定母星，并按本节等待肃清完成；不复制原版「所有人口组无过滤迁往当前首都」作为新泛用规则。保留本族有效子模板，不把已经真实存在的本族人口强行换成主模板。

**其它灭绝路径：新增星球拆解与本族人口制造。** 铁心将星球物质制造为机械单位；种族洁癖和非石质蜂群将它用于培养当前本族。人口来自被毁星球的物质奖励，不是把被肃清外族一比一同化。采用确定性制造规则，在完整吞噬结算时创建当前国家主体模板的人口，普通生长和组装继续运行。新模板读取结算时实际 `owner_main_species`，已经合法取得的灵能等飞升特质随模板保留；不改共享物种定义。

拆解过程首轮不叠加另一套矿物/合金爆发奖励，也不复制原版肃清奖励。候选人口数量见第 5 节。普通主体飞升或政体改变后重新验证权利、模板与合法性；虚拟人口的自动填岗与造人口冲突列为扩展阻塞项，不能悄悄把不存在的虚拟劳动力当成真实新人口发放。

### 4.3 执行与一次性结算

每个源星有持久任务记录：启动者、绑定母星、路径、可用物质快照、进度与完成凭证。建议状态为 `ready → digesting → waiting_for_clearance/blocked_core → settling → consumed`，中止保留可核对历史，重载不从零生成第二个任务。`waiting_for_clearance` 仅在还有肃清人口时使用，`blocked_core` 只等待母星归属/占领条件恢复；都不发新中间奖励。

完成顺序合同：重新验证所有权与母星 → 记录唯一完成凭证 → 吃尽本路径余料/算出应发数值 → 增加母星可建容量 → 回迁真实消化站人口、制造应发本族人口 → 销毁源殖民地、改为破碎星球 → 确认已消耗并结算天灾摧毁目标一次 → 展示实际结果。结算必须在同一个受保护事件链内完成；如果引擎不能保证这条顺序，先做恢复日志和分步骤凭证，不能在已发奖但销毁失败时重新发一遍。

计数不能由通用殖民地销毁事件直接增加：轰炸、弃置殖民地、人口全被肃清、第三方销毁、噬星者毁恒星系均不等于本起源完成吞噬。奖励只来自本起源自己的成功凭证。读档、重复弹窗、月脉冲、迁都、模板更新和刷新修正都不增加成长计数。

## 5. 数值候选与单球容量

强度与 3～5 年周期已由用户确认；时间默认值按该区间落实，其余数值用于首轮原型和自然局对照，尚无实机平衡结论。

| 参数 | 建议初值 | 含义 |
| --- | ---: | --- |
| 母星起始额外可建区划 | `+2` | 只增加总容量，不送已建区划、住房或岗位 |
| 母星起始岗位产出 | `+10%` | 母星普通岗位产出原生加算；不另调岗位维护，不宣称独立乘算或效率 |
| 容量兑换 | 每 `4` 点实际星球物质 `+1` | 同一国家保留余数；收益落在母星可建容量 |
| 通用拆解人口兑换 | 每 `6` 点通用拆解物质 `+100` 人口 | 只用于非噬岩原生路径；保留余数，实际创建 `size=100` 的数量，不是一个人口组 |
| 消化站人口 | `100` | 本族搬运，不作为吞星新人口 |
| 消化时间 | 默认 `T = ceil(12 × Q / 5)` 月 | 本起源两条路径统一；尺寸 20 且无旧损毁时为 48 月，15～25 格对应 36～60 月；允许多个源星并行 |
| 其它永久产出成长 | 无 | 继续成长来自更多可建空间、人口与正常科技/飞升，不按每吞一球再无限增加产出倍率 |

`Q` 为启动时实际物理尺寸减去已有噬岩损毁对应的已消耗尺寸，至少为零；不计人工增加的 `planet_max_districts_add`、现有建筑数量、已建区划数或剩余空岗。`Q<=0` 时不启动新任务；已经到终点的旧任务只处理自己的待结算凭证。尺寸和已有损毁都保存快照，取消后重启不能把已消耗空间当成新食材。源星在启动前合理付费扩大的实际尺寸可以计入，整个真实星球仍只能毁灭一次；处理中尺寸变化不扩大奖励。

本起源专用局势实施采用 4.5.2 原版说明中的可脚本化 `total_progress=T`、阶段 `section_weight`，每个有效推进月 +1，取代早期候选的 `1000 / T` 浮点进度，避免累计舍入导致多等一个月。无旧损毁的 Q=15/20/25 分别为 36/48/60 个有效推进月；更小的剩余食材按公式更快完成，更大星球相应更久。3～5 年是普通星球的消化进度目标，不包含等待异族肃清、母星失守等暂停时间；UI 分别显示剩余消化时间与等待原因，实际月份边界与重载延续仍需用例验证。

原版噬岩局势的 `6 × Q` 月是源码事实，非本起源仍保持该规则。本起源尺寸 20 的进度周期由原版 120 月缩短为 48 月，吞星周转速度提高到 2.5 倍；这是「偏强爽玩」的明确设计选择。噬岩中间消费仍遵守原版真实冷却，终点仅补消费尚未吃掉的实际空间；不会按缩短的月份额外复制奖励次数，也不全局缩短原版冷却。末次集中补消费的正确性与结果展示纳入验收。

噬岩取消已产生永久障碍时，重启仅按尚未消费的物质启动，最后只新增这次合法剩余尺寸的容量。原版中间人口/资源不回收；因此不能宣称本 Mod 消除了所有原版中断获利策略，但本 Mod 的容量和通用制造人口绝不能靠中断刷取。

```text
C = 所有成功吞星凭证的合法 Q 总和（含噬岩与通用路径）
G = 成功通用拆解凭证的合法 Q 总和（不含噬岩路径）
D = 2 + floor(C / 4)                       母星额外总区划容量
P_manufactured = 100 × floor(G / 6)          历史累计制造人口
单次新增 = 成功结算后累计值 - 成功结算前累计值
```

区划余数 `C mod 4`、通用人口余数 `G mod 6` 分开保存，混合路径不互相刷人口。C/G 为国家成功账本，D 同步记录在绑定母星上作为物理扩容；母星易主不从新主人国家账本重算并删掉容量。只有本起源原主人实际拥有绑定母星时，才获得本起源的 +10% 岗位产出，外国占领者不继承此项国别奖励。母星人口净变化另加真实回迁、自然生长/组装并扣除死亡和迁出；不能用 `P_manufactured` 冒充母星当前总人口。

| 样例（原母星尺寸 20） | 吞后累计 C | 额外容量 D | 母星理论总容量，未扣原版障碍等 | 通用累计制造人口 |
| --- | ---: | ---: | ---: | ---: |
| 尚未吞星 | 0 | 2 | 22 | 0 |
| 通用吞 1 颗尺寸 20 | 20 | 7 | 27 | 300，余料 2 |
| 通用吞 3 颗尺寸 20 | 60 | 17 | 37 | 1000，余料 0 |
| 通用吞 10 颗尺寸 20 | 200 | 52 | 72 | 3300，余料 2 |
| 先噬岩 Q=20，再通用 Q=20 的合同压力样例 | 40 | 12 | 32 | 仅通用部分的 300；另有噬岩实际奖励 |

混合样例仅用于证明计数合同，即使正常玩法很少在同国切换路径，也要避免脚本绕过双发。拆分成 Q=3 和 Q=5 的两次通用完成应得到 C=8、D=4、制造人口 100，不能每星先向上取整；消化站往返不改变这 100 的净制造数。

### 5.1 区划真的可用，而不只是显示更大的数字

母星额外总容量采用本机存在的 `planet_max_districts_add` 通道，不反复修改物理 `planet_size`。因此 UI 应显示「原尺寸 20，吞星额外容量 7」，不是宣称球体尺寸变成 27，也不是直接增加五个已建矿区。

仅增加总容量会卡在原矿脉/发电/农业上限。建议母星从开局使用原版明确为 Modders 保留的 `uncapped_mining_districts`、`uncapped_generator_districts`、`uncapped_farming_districts` carrier flags，解除三类资源区划的地貌上限，但它们仍共用真实总容量，仍要付原价、建设时间和维护。这比每吞一球复制源星全部矿脉或自动免费造区划更清楚。旗标只加在绑定母星，源星不受益；须核查原始已有旗标，移除或重建时不能删掉其它来源。

人口还需要实际住房、舒适度、治安/偏离度和岗位。增加容量没有直接增加这些供给，玩家需建正常城市/蜂巢/枢纽区划与资源区划，原版人口仍可能暂时失业和过剩。

本机 4.5.2 已有城市区划、区域、随区划等级放大的科研与凝聚力岗位；优先使用这些原版区域扩大科研、工业和传统供给，不沿用旧版「固定建筑槽装几座研究所」的模型，也不新增基础产出更低的专属科研岗位。开工探针必须证明三种政体的城市/蜂巢/枢纽区划均能把扩容量兑现为岗位，特别是后期科研与凝聚力；若不能，则另立专属区域补足设计，不偷换成无岗位的每月资源补贴。

首轮母星使用标准自然星球区划组。蜂巢世界、机械世界、火山区划组以及都市星球转换分别登记兼容探针；都市星球会失去正常矿电食区划，不能被无条件写成单球矿物闭环的升级终点。超大容量采用持久数值和单一派生修正，不每层添加一个图标或一条矿脉。目标不设人为累计容量上限或递减，但只承诺实际测过的数值范围；现实资源来自有限可吞星球。

## 6. 灵飞与武灾：源码支持的闭环

### 6.1 灵飞是可选的原版成长路线

本机 `ap_mind_over_matter` 的 `potential` 明确包含 `has_shroud_dlc=yes` 分支，注释说明支持 gestalt/machines；缺该 DLC 时分支限制非格式塔、非机械等条件。`has_shroud_dlc` 对应 `Shadows of the Shroud`。官方发布说明也确认蜂巢和机械可灵能飞升，见[Paradox 官方 Steam 公告](https://store.steampowered.com/news/posts/?appids=281990&enddate=1759180360&feed=steam_community_announcements)。这不能写成过时的「蜂巢和铁心绝对不能灵飞」。

普通非合成配置需先有两项 AP，再选灵飞入口；普通机器配置在无特殊豁免时需先有三项 AP。都需满足其它飞升互斥、传统树空间等限制，采用灵能传统还需要 `tech_psionic_theory`。本 Mod 占了起源槽，不能同时选择虚境导师、虚境铸造等另一起源来偷跑这些门槛。尤其原版铁心明确排斥 `origin_shroud_forged`，本案使用的是正常机器灵飞入口。

母星集中人口有利于共享原版灵能设施与稳定度，但「超高岗效」必须按当前岗位、赞主和特质实际核验：现行灵能特质包含科研、凝聚力和灵能岗位的 workforce 奖励，灵能军团还按实际通灵岗位为母星灵能人口增加 workforce，赞主另有矿工或冶金岗位分支。基础通灵 200 满岗时，该建筑渠道的无额外条件脚本增益为 10%，并非免费统一翻倍；更高效率要继续组合原版科技、传统、理事会与赞主。原版劳动力效率可能提高岗位投入，本 Mod 自己的 +10% 则是产出加算，两者分开报告。原版赞主代价、赤字和飞升互斥保持，不额外承诺零维护。

没有「虚境之影」时，蜂巢和铁心仍可用原版合法的其它飞升完成吞星经营；普通合法种族洁癖按原版 DLC/条件可走旧灵能路径。缺灵飞 DLC 不阻断起源基本玩法。

### 6.2 武灾把主力舰队转到矿物，不是全帝国不需要合金

本机 `ap_become_the_crisis` 需要 Nemesis、独立且非监管人/皇帝等条件，普通配置需已经有三项 AP。它会开启原版 `nemesis_path`；本 Mod 不开局赠送、不免费完成升级项目，也不替玩家自动选取。

| 原版舰型 | 解锁阶段 | 未计修正的舰体建造成本 | 基础月维护（能源／矿物） |
| --- | --- | ---: | ---: |
| `crisis_corvette` | 天灾 2 | 300 矿物 | 1／1 |
| `crisis_destroyer` | 天灾 3 | 550 矿物 | 2／2 |
| `crisis_cruiser` | 天灾 4 | 900 矿物 | 4／4 |

这三种船的定义均为 `components_add_to_cost=no`。表是当前源码基础值，不含国策、天灾 perk、舰队位置、超舰容与其它修正，也不宣称装备升级和改装的全部运行时费用已核验。阶段 2/3/4 分别还有 1000/2000/5000 威慑和对应项目完成要求，不是选 AP 当天三种船全解锁。

只计算 20 艘未修正威慑护卫舰，建造矿物为 6000，月维护为 20 能源＋20 矿物。若矿物净产出是扣除人口、岗位、建设与现有舰队后的 100/月，补回这笔建造支出理论需要 60 月；这只是收支样例，不是能打赢下一场战争的保证。

前期普通舰船、殖民船、船厂/星基等基础设施和未替换舰种仍可能需要合金。噬岩者可保留原版吞星合金随机收入，但不能把它写成稳定月收入或保证能支付首战。武灾路线把主力舰队与大量合金生产脱钩，母星仍应保留必要工业。天灾 5 的外交战争、噬星者和最终结局照原版运行；不能靠同时写灵飞和武灾便宣称所有升阶段顺序已实测。

## 8. 实现边界、兼容与性能

建议脚本命名空间 `eep`，所有新增 origin、决议、局势、修正、变量与本地化键带独立前缀。主包预期放在 `eat_everything_origin/mod/`，本轮不创建它；实现时在独立子项目根目录建立独立 `VERSION` 和 `CHANGELOG.md`，先用 `0.1.0-rc.1`，不改主仓其它 Mod 的版本源或复用 Workshop ID。

首个实现面向新开局；不向旧局强行补起源，不从历史破碎星球反推 C/G，也不自动迁移其它 Mod 的成长或人物。将来候选存档升级时，明确保存本 Mod 数据版本和幂等迁移凭证，再更新迁移方案。

推荐噬岩路径用专用吞噬局势，复用当前原版消费效果，按第 5 节的 `total_progress=T`、每月 +1 设置本起源进度，自有完成事件加母星结算。为了让噬岩玩家通过原版吞星按钮也进入同一凭证路径，允许最小覆写 `decision_lithoid_swarm_consume_world` 单一定义：本起源转入专用局势，其它国家完整保留当前原版分支及 120 月的 Q=20 进度。覆写的加载优先级、作用域和资源表必须先验证；不能整目录 `replace_path`，不覆写原版全部岗位、飞升或天灾船只。

不优先采用通用 `on_colony_destroyed` 发奖：本机该回调是 Carrier，并且在 owner/controller 清除前调用，之后还有多种普通销毁原因。即便未来采用只读观察入口，也必须取得明确的本起源成功凭证，不能凭 `being_devoured` 就把途中被炸毁的源星算作完成。没有现成已验证的「原版噬岩完成后供第三方发奖」公共回调；这一点是实施前探针。

通用路径使用独立决议、局势和事件，按政体/当前主体模板创建人口。读取开局母星、当前主体物种、变量乘子、人口转移和 Carrier 作用域的组合均需验证，文档中的逻辑状态名不是未经核验的 Stellaris opcode。

更新以开局、决议启动、局势完成/中止、模板或所有权变化为主；月度仅检查本国活跃任务与绑定母星，作为漏事件恢复。不得每日扫描全银河，也不每月重建全部物种模板或给全银河同名物种加特质。任务数量与临时殖民地数一同记录性能成本，不能靠忽略消化中的星球宣称零多球开销。

最小覆写会与其它修改同一原版决议的 Mod 冲突，兼容说明必须点名。变更吞岩、净化、区划/区域系统、虚拟人口、天灾或强行多起源的 Mod 逐项适配，不提供空泛的「全兼容」。未经过母星区划组验收的焦土等分支不在 UI 里悄悄放行。

## 9. 实施次序、风险与验收闸门

建议依次推进：

1. **接口探针**：当前 4.5.2 工具基线、起源资格、母星绑定、决议路由、原版进度与消费作用域、动态容量、资源区划旗标和科研区域扩张。
2. **核心三国策原型**：噬岩原版收益＋母星容量、非石质蜂群/铁心/种族洁癖的通用人口路径、种子人口往返与唯一凭证；全部保留原岗位。
3. **组合与兼容**：飞升前后、灵能 DLC 有/无、武灾阶段 2/3/4、母星迁都/占领、原版普通吞岩对照；补齐新版焦土两支。达到所有分支闸门前，不能发布「所有灭绝已支持」的声明。
4. **自然局调参**：同种子、同配置与对应原版灭绝起源对照，记录 5/10/20/40/80 年，测试停战、密集吞星、优先飞升、优先武灾和无相关 DLC。

用户已选择偏强爽玩，单星容量＋人口＋原版飞升/灭绝加成的强正反馈属于预期体验。需要重点排查默认 4 年、普通星球 3～5 年周期下临时殖民地积压、母星建设速度跟不上、科研区域无法扩展和矿物/能源维护挤压；原版对照用于衡量收益与节奏，不把强度回调到原版平均水平作为目标。优先修复重复奖励、假容量、卡死与操作负担；若经营闭环仍需调参，先调整尺寸兑换、制造人口和时间，不降低正常岗位基础产出、不加入强制衰退。候选的初始 +2 容量与 +10% 产出继续纳入自然局观察。

任何实现后的 P 语言 Mod 验收，先阅读并使用 `D:\workspace\open_kaishek`。本轮只读发现该本地副本 README 仍标注受限 Stellaris 4.4.6 profile，未找到历史交接提到的 `accept_stellaris_mod.py`；因此未来实施必须先同步/核对工具真实能力，若缺少 4.5.2 所需功能，按仓库规则先完善工具、验证并在工具仓库提交推送，再继续 Mod 验收。本轮不是 Mod 验收，不为设计稿运行不匹配 profile，也不修改工具仓库。

详细探针和验收用例见[验收设计](../eat_everything_origin/docs/acceptance-plan.md)。只有通过工具检查、简体中文实机/经济/存档用例以及自然局证据后，才能宣称实现可玩或验收完成。英文及其它语言只执行规定的静态校验，并明确「静态校验通过」或「运行时不在范围内」。Steam 发布不属于本轮；将来每次正式发布按独立版本 changelog、全新版本号、远端核验与同名标签流程执行，禁止上传到只读上游 `3710613857`。
