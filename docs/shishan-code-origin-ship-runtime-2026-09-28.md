# 舰船航行与实战伤害验收（2026-09-28）

## 目标与范围

在 Stellaris 4.5.1 简体中文、Steam 离线、仅启用「屎山代码」的隔离游戏中，补齐 SC-06 已验证面板数值之外的实际亚光速航行与单次武器命中证据。使用同一艘舰船、同一移动路线或同一战斗目标、同一科技及暂停日期作为各阶段分支的公共基线。

## 航行方法与通过标准

从个体机械帝国 `2203.06.03` 暂停存档选择「加拉索舰队」，在首都星系内对同一处无目标空域下达移动命令，立即保存有命令但尚未推进时间的 `sc06_route_order_base_22030603.sav`。从该存档分别将局势置于第二阶段 `300` 和第五阶段 `950`，保持路线不变；记录同一游戏日后舰队位置或实际到达日。第五阶段亚光速面板约为第二阶段四分之一，实际同段亚光速移动应显著慢于第二阶段。若原版路径规划、加速/减速或 UI 舍入使总到达时间不恰好四倍，结合存档坐标与移动状态报告实际测得值，不能仅凭面板宣告通过。

## 战斗方法与通过标准

构建同一护卫舰武器及固定装甲/护盾/船体目标的暂停基线，分别以第二与第一/第三/第四/第五阶段进入战斗。记录武器类型、目标防御及同一类命中前后的护盾/装甲/船体实际差额，排除暴击、闪避、不同武器、多舰同时命中与其他战斗修正；至少得到一组可核对的实际命中倍率。若游戏战斗日志不提供足够的逐次命中信息，保留 UI 截图和存档中船体状态，并明确尚未通过，继续寻找可控夹具。

测试夹具只写入隔离用户目录的 Mod 副本，绝不并入正式 Mod。夹具从玩家国家事件作用域创建一支自动敌对的海盗舰队，把它放在已标记的测试舰队附近；正常战斗由游戏引擎结算。先使玩家舰队只有一艘、一个武器，再从接敌前的同一存档分别切换局势阶段。若单次命中值可由护盾或装甲的逐日差额分辨，比较同种命中；每次分支复位到同一基线，避免敌方预先受损和随机科技变化。夹具须先用 `open_kaishek` 对隔离副本检查，并检查 `error.log`；若创建敌对目标或单击伤害不稳定，不能把舰队总伤害当作单击通过。

首轮夹具使用原版单门红色激光与无武器海盗站，`open_kaishek` 对隔离副本 `PASS`：21/21 脚本、13 DDS、167 本地化键；运行时舰队 `203` 的舰船 `1000` 仅有 `SMALL_RED_LASER`，目标舰船 `1001` 的初始装甲 `2735`。游戏存档 `fleet_stats.combat_stats` 实际记录武器、`hits`、`misses` 和 `damage_armor`。第二阶段样本为 15 次命中、装甲伤害 `258.1995`，第五阶段样本为 19 次命中、装甲伤害 `96.384`；按命中平均分别是 `17.2133` 与 `5.07284`。由于原版红色激光单击基础伤害在 `6–16` 间随机，两个有限样本的均值比 `0.2947` 不能作为精确 `0.25` 的证据。下一轮只改隔离夹具的单门武器为固定基础伤害 `10`、保留原版红色激光的 `1.5` 对装甲倍率，使每次命中都能与理论 `15` 或 `3.75` 直接比较；正式 Mod 不改武器。对新夹具重跑工具并从相同接敌前基线各测一次。

第二轮首次把自定义武器的 `cooldown` 等数值写进 `weapon_component_template`，包级工具仍给出 `PASS`（22/22 脚本）；但其报告明确注明 `semantic_scope` 仅为语法与包结构，游戏 `error.log` 指出该夹具文件第 9 行 `cooldown` 为意外键。这不属于工具承诺的语义覆盖，也不构成正式 Mod 缺陷。Stellaris 4.5.1 的 `common/component_templates/000_documentation.txt` 和原版 `weapon_components.csv` 表明武器数值以 CSV 为准。夹具改为完整复制当版本体 CSV 并仅追加 `SHISHAN_SC06_FIXED_LASER` 一行，令 `min_damage=max_damage=10`、`armor_damage=1.5`；自定义模板只保留键、图标、类型和标签，再检查游戏日志及实战伤害。此夹具 CSV 仅在隔离目录，不能进入正式 Mod。

## 航行实测：同一起点、路线和日期

`2203.06.03` 暂停基线中的舰队 ID 为 `3`，星系内坐标为 `(17.63,-15.63)`；移动命令的目标为 `(-222.49958,83.32173)`。分别从同一基线将局势进度设为 `300`（第二阶段）和 `950`（第五阶段），正常解除暂停并在 `2203.06.23` 再次保存。两份终点存档仍有同一目标移动命令。

| 分支 | `2203.06.23` 坐标 | 从基线实际位移 | 对第二阶段比值 |
| --- | --- | ---: | ---: |
| 第二阶段，无亚光速阶段修正 | `(-116.76278,39.74999)` | `145.35599` | `1.00000` |
| 第五阶段，亚光速 `-75%` | `(-16.05178,-1.75132)` | `36.42911` | `0.25062` |

两个分支均历经 20 个游戏日，舰队相同、路线相同。第五阶段的实际位移为第二阶段的 `25.062%`，与四分之一的阶段速度预期相符；因此 SC-06 的实际亚光速移动子项通过。存档 `path.date` 保留旧路线规划日期 `2203.10.24`，未拿它推算真实到达时间。证据为[命令基线](../assets/shishan-code-origin/evidence/sc06_route_order_base_22030603.sav)、[第二阶段终点](../assets/shishan-code-origin/evidence/sc06_route_stage2_same_day_22030623.sav)、[第五阶段终点](../assets/shishan-code-origin/evidence/sc06_route_stage5_same_day_22030623.sav)以及[第二阶段画面](../assets/shishan-code-origin/evidence/sc06-route-stage2-2203.06.23.jpg)、[第五阶段画面](../assets/shishan-code-origin/evidence/sc06-route-stage5-2203.06.23.jpg)。三份存档 SHA-256 顺序为 `03091a971e296a871bf971ff4665d5fcb789f83cdbb5c0a99e68518da09436d0`、`20f5b024063174a8f98bf077218d36a2fd69863af6b9800ec87dad3d242af8e8`、`23629b92d7b43924a2ab933cfff234d7e988b3bc20412d39bd933a53d1b298fb`。

第二轮 CSV 首次重启时，游戏日志报 weapon_components.csv 解析失败。逐列核对发现手写夹具行有 26 列，而原版表头与红色激光行均为 25 列；这是隔离夹具错误，正式 Mod 不含该表。夹具改为从原版 SMALL_RED_LASER 行按列替换名称、最小/最大伤害及命中/追踪参数，并用断言核对列数，不再手填整行。重启后须确认错误日志无该表解析错误，方可采集战斗样本。

修正列数后，游戏日志已无 CSV 解析报错，原存档可以载入。随后曾误读 `Get-Process` 的表格输出，以为进程退出；复查发现旧进程仍在运行，且意外又启动了第二个游戏进程。已停止旧进程，保留新的隔离进程。控制台输入还漏掉空格，把 `event shishan_sc06.1` 连成无效命令，因此没有产生自定义武器战斗样本。为缩小夹具变量，隔离副本改回原版红色激光设计，原版 CSV 覆盖测试 CSV，自定义模板文件置为注释。接下来从同一接战前基线各推进更长时间，用更多命中降低随机基础伤害误差；若仍无法达到可判定区间，本项保留待测。

## 红色激光长时样本及夹具扩展

原版红色激光的早期单舰样本在第二阶段 `2203.08.13` 有 `15` 次命中、装甲伤害 `258.1995`，第五阶段 `2203.08.30` 有 `19` 次命中、装甲伤害 `96.384`；平均单次分别为 `17.2133` 和 `5.07284`。两份目标装甲均未耗尽，且对应的原版基础伤害区间经装甲倍率换算后，第二阶段为 `9–24`、第五阶段为 `2.25–6`，区间不重叠。实战确有阶段减伤，但随机基础伤害使小样本均值比 `0.2947` 不能精确代替四分之一。

从同一接战前存档继续长时运行，第二阶段到 `2205.08.20` 累计 `174` 次命中，记录装甲伤害 `2741.3775`、船体伤害 `562.56`；目标的装甲发生耗尽/恢复，故只拿装甲伤害除以全部命中会低估均值，不能称目标已经被摧毁。第五阶段到 `2206.06.01` 累计 `243` 次命中、装甲伤害 `1236.9285`，目标剩余装甲 `1498.0715/2735`；此时帝国已陷入能量、矿物、消费品等短缺，原版短缺惩罚混入舰船伤害。两份长时样本不属于冻结经济条件下的倍率对照，保留为边界证据。

下一轮只在隔离副本扩展 `shishan_sc06.1`：相同设计各生成 12 艘仅有一门原版红色激光的玩家护卫舰和 12 座无武器海盗站，在开战前保持相同存档、相同科技及资源库存；以舰队 `fleet_stats.combat_stats` 的 `SMALL_RED_LASER` 总命中数以及 `base_damage_armor` 与 `base_damage_hitpoints` 总和计算每命中基础伤害。多个靶舰避免第一座耗尽后把装甲伤害误作所有命中的伤害；如果两个分支的短缺提示或其他舰船修正不同，则本轮无效。夹具只放隔离副本，先过 `open_kaishek` 再进游戏；正式 Mod 不加入舰队、武器或 CSV 文件。

## 多舰实战：第二阶段—第五阶段—第二阶段

隔离夹具创建 12 艘单门 `SMALL_RED_LASER` 护卫舰及 12 座无武器靶站；`open_kaishek` 对该副本给出 `PASS`（22/22 脚本、13 DDS、167 本地化键）。从 `2203.06.03` 战前公共存档出发，第二阶段进度 `300` 正常交战至 `2205.03.02`，累计命中 `1598`。游戏在最高速度下推进快于预期，因此此段未满足最初想在三个月内结束的控制目标；只把它用作后续切换的累计计数基线。接着在同一暂停日期把进度设为 `950`，正常交战 27 日；再把进度设为 `300`，交战 28 日。三次设置均由游戏控制台回显局势进度和右侧阶段图标确认。三段期间玩家能量库存保持在约 `1400`，未发生原版资源短缺；舰队仍使用同一原版武器。

| 存档日期及阶段 | 累计命中 | 累计护甲基础伤害 | 累计船体基础伤害 | 本段每命中基础伤害 |
| --- | ---: | ---: | ---: | ---: |
| `2205.03.02`，第二阶段累计基线 | 1598 | 13616.944 | 6987.724 | — |
| `2205.03.29`，第五阶段 | 1666 | 13676.2495 | 7251.208 | `(59.3055+263.484)/68 = 4.74690` |
| `2205.04.26`，切回第二阶段 | 1731 | 13879.1215 | 7886.236 | `(202.872+635.028)/65 = 12.89077` |

第五阶段的实战每命中基础伤害为相邻第二阶段样本的 `36.824%`，明显下降；同一武器切回第二阶段后，均值恢复到长期第二阶段基线的 `12.89404` 附近。第五阶段静态修正确实是 `ship_weapon_damage=-0.75`，但实战并非孤立的 `0.25` 倍；根据红色激光原版随机基础伤害与两个样本，其他同类加成按加法叠加是合理解释，**具体来源尚未逐项拆解，此处是推断**。因此本次验证的是实战伤害会随阶段切换下降并恢复、且存档实际记录了每次命中的数量与伤害；不把 `36.824%` 误写成精确 `25%`，也不据此改动已按设计写入的 `-75%` 修正。若后续要宣称严格的 1:4 实战倍率，须建立没有其他武器伤害加成的隔离国家，并用固定伤害武器重测。
