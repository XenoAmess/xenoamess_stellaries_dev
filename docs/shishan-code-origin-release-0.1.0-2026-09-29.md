## 发布设计

`shishan_code_origin/VERSION` 是唯一版本源；内容描述符、正式 changelog 条目、创意工坊 Change Note 与 Git 标签均使用 `0.1.0`。创意工坊标题为「屎山代码」，说明描述玩法、简中实机与其他九种语言的静态校验范围，以及尚未收尾的矩阵。Change Note 以 `[v0.1.0]` 开头，从 changelog 提炼。主预览使用包内 `thumbnail.png`；不伪造额外实机截图。

发布工具沿用仓库已验证的原生 Steamworks UGC 调用方式。先只读预检版本、文件清单、文件哈希、说明/Change Note 和已登录会话；`CreateItem` 返回新 ID 后立即持久化回执，核对不等于已知其他物品，再提交标题、内容、预览、标签和公开状态。若 Steam 要求接受创意工坊法律协议，必须由用户本人操作，不代替接受。发布后通过公开详情和空缓存下载回读元数据与文件哈希，将新 ID 写入 `shishan_code_origin/workshop/item-id.txt` 与文档；远端核验通过后创建并推送版本标签。仓库已有合成女王的 `v0.1.0`，不能移动或复用该标签；本独立 Mod 沿用仓库已有的产品前缀惯例，使用 `shishan-code-v0.1.0`。

1. PR-02/PR-04 维护与持续优化在自然研究完成时各只结算一次；完成前及完成后强制重复调用均不能增加次数或奖励；原生存档、Steam F12 截图和结算前后比较归档。
2. 正式包 `open_kaishek` 通过，版本一致；九种非简中语言静态校验通过，运行时不在范围内。仓库范围的其他 Mod 旧合同失败不得误记为本 Mod 失败或通过。
3. 创意工坊新物品 ID、公开状态、标题、说明、主预览、Change Note 和空缓存内容与本版发布源一致；已知其他物品未作为上传目标。
4. 发布回执、文件哈希和已知限制归档，相关改动提交推送；远端核验后推送 `shishan-code-v0.1.0` 标签。继续其他未完成场景时，以新版本线管理后续变更。
