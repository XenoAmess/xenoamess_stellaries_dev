# 「屎山代码」起源：首轮平衡性评估

日期：2026-09-26。状态：**静态设计评估，尚无 Mod 实机数据**。依据[需求记录](shishan-code-origin-requirements.md)与[详细设计](shishan-code-origin-design.md)的已确认数值；没有修改需求基线。

## 结论

若目标是与原版挑战起源相近的强度，当前方案仍可能**偏强且两极化**：熟悉机制的玩家能延长开局加成，并在清理后获得永久奖励；没能及时清理的玩家则可能在后期失去研究与经济能力。最新需求已让岗位与非岗位产出互斥地承受同一阶段百分比，移除了先前评估中的双重经济加成，因此「偏强」判断的把握下降，需要简体中文实机对照。它仍是「高收益、高惩罚」的玩法起源。

本机原版 4.5 系列 `common/traits/10_paragon_traits.txt` 的 `leader_trait_the_synth_luminary` 在理事会提供 `+15%` 机械人口岗位效率，同时有每月 `25` 合金的领袖维护费；[Stellaris 官方 4.5 测试版更新说明](https://steamcommunity.com/app/281990/announcements/?l=english)也记录了将这项效果从 `+25%` 岗位资源改为 `+15%` 岗位效率。两者生效条件不同，不能直接相减，但可作量级参照：本设计 I 阶段对岗位产出与非岗位月产出分别给予 `+25%`，另有舰船强化和岗位维护费减免。

## 计算前提

- 无人维护且无维护员时，月速 `1`；完成 `n` 次维护/优化、维护员已分配劳动力为 `J` 时，月速为 `max(0.2, 1+n-0.1×floor(J/100))`。
- 一年按 `12` 个月。下表从进度 `0` 重新起算，不计项目研究期间的时间、建筑建设、人力填岗和其他游戏事件。
- 设计暂把用户所说的「岗位效率」映射为岗位产出；当前原版也存在劳动力效率等不同修正渠道，实施前必须确认具体键及其对研究和资源的实际影响。
- 最新需求要求按来源隔离：岗位来源产出 `P_job` 仅受岗位项修正，非岗位来源月产出 `P_nonjob` 仅受非岗位项修正。两项同阶段百分比相同，因此在忽略其他修正与支出时，I 阶段目标总产出为 `1.25P_job + 1.25P_nonjob`，V 阶段为 `0.25P_job + 0.25P_nonjob`。例如 `P_job=100,P_nonjob=40`，I 阶段应是 `125+50=175`；原先的 `156.25` 岗位收入推演已失效。`J` 只用于表示维护员已分配劳动力。
- 本机原版 4.5 的 `common/relics/relics.txt` 在同一 `triggered_country_modifier` 中分别使用 `planet_jobs_produces_mult`、`station_gatherers_produces_mult`、`station_researchers_produces_mult`；另有 `country_energy_produces_mult` 等按资源划分的键。脚本证明这些修正渠道分别存在，**不能单凭脚本保证非岗位项绝不波及岗位，或保证所有非岗位来源均可修正**。后续需按来源实测。

## 主要失衡点

1. **前期红利仍可能过大且可延长。** I 阶段原本就持续约 `20.8` 年。岗位与非岗位来源各获得一次 `+25%`，不再互相叠加；还有舰船伤害/航速 `+25%` 与岗位维护费 `-25%`。完成维护会把进度归零、赠送正面特质并提高白绮的工程学加成；在阶段边界前研究维护项目，能再次取得约 `10.4` 年的 I 阶段（`n=1,J=0`）。这些永久收益和延长的红利可能盖过维护的递增费用。
2. **岗位可把红利延长到百年量级。** `n=0` 时，只需 `J=800` 已分配维护员劳动力就达到 `0.2/月` 下限；进度 `0→250` 理论上要 `1250` 个月，即 `104.2` 年。详细设计建议每座满岗研究所贡献 `100` 劳动力，条件满足时即为约 `8` 座研究所。建造成本、槽位、能源维护、人口占用和社会学基础产出损失都是真实代价，但目前尚无数据表明这些代价足以抵消长期全帝国红利。每多完成一次维护，还需额外 `1000` 劳动力才能抵消新增的 `+1/月`。
3. **清理可能很早跳过挑战。** `n=0` 时清理要 `8000` 社会学研究点。若第一阶段期间能把平均 `32` 点/月的**有效项目研究进度**全部用于清理，就能在 `250` 个月内完成；这只是临界计算，不代表开局必有该研究能力。若成功，局势立即结束，负面阶段不会到来；主体物种改得永久 `+25%` 岗位产出并失去「屎山代码」的点数惩罚。需要实测项目进度、科技取舍及开局经济，才能判断 8000 是否足够阻止早清理。
4. **拖入后期的惩罚仍可能过重。** IV/V 阶段对岗位与非岗位来源分别减产 `50%`/`75%`，不再双重削减岗位资源；岗位维护费升到 `150%`/`175%`，V 阶段舰船武器伤害和亚光速航速也都降 `75%`。如果社会学产出也被削弱，而清理成本随维护次数上涨，玩家可能在最需要清理时失去研究能力。阶段 V 的持续惩罚尤其可能成为实质上的失败状态；目前设计没有明确的救援通道。
5. **长期收益无硬上限。** 白绮工程学加成每次 `+5%`，在 `n=28` 为 `+150%`，之后继续增加；社会学惩罚则封顶 `-75%`。项目还能逐层赠予机械、有效的非机械正面特质，再进入可重复的 `+1%` 增益池。清理后永久 `+25%` 岗位产出，持续优化仍可继续累积收益。10% 复发和线性递增研究成本构成代价，但是否足以抑制大帝国后期反复优化，尚无数据证明。

## 建议与验收重点

优先验证**来源互斥**与**第五阶段仍能完成清理**，再调白绮上限。现有百分比先按用户确认值保留；若实机对照仍显偏强或过难，再根据结果提出候选数值。应给玩家明确的局势速度预警，并验证阶段 IV/V 仍能研究「清理屎山」。

以后实施 Mod 时，用同一 Stellaris 版本、同一机械帝国初始配置、同一难度和简体中文，对照无起源与本起源，并分别测试：

1. 不维护、尽早清理：能否在阶段 I 结束前完成；前 `20` 年经济、科技、舰队差距。
2. `J=0/800/1800`：实际已分配劳动力、月速、阶段 I 持续时间、八座研究所的真实机会成本。
3. 恰好在阶段 I 末维护一次：多维持多久，获得特质与白绮增益后净收益多大。
4. 延迟至阶段 III/IV/V 才清理：各阶段实际月度资源、社会学项目进度、赤字与回收时间；确认没有不可逆的研究死锁。
5. `n=5/10/28`：白绮生效与死亡时的研究速度、正面特质累积、持续优化复发的代价。
6. 单独启用岗位项、单独启用非岗位项、同时启用两项，对比同一岗位、空间站及其他固定月收入的产出与帝国净收支，确认每笔收入只受其中一项影响；检查资源种类与来源覆盖缺口。

验收仍遵守仓库规定：先用 `open_kaishek` 检查 P 语言 Mod；运行时只测 `l_simp_chinese`。本文件是静态评估，没有运行游戏或声称 Mod 已通过验收。
