# 「屎山代码」创意工坊页面 v0.1.1 改版

## 目标与范围

用户指出已发布页面的 BBCode 机制说明过短，缺少穿插的实机截图，并要求 BBCode 入库。本轮在修复白绮待复活决议提示后，以新正式版本 `0.1.1` 更新既有物品 `3810136486`。页面源文件继续使用并提交 `shishan_code_origin/workshop/description.bbcode`；截图使用此前简体中文单 Mod 实机证据，保留源文件与页面使用清单，不把测试存档或夹具混入 Mod 内容目录。

## 设计

说明分段交代开局限制与物种特质、五阶段数值及边界、持续资源的单次覆盖口径、维护员速度公式、维护和清理项目的动态费用与奖池、重构后持续优化与复发、白绮的增减益与复活，以及版本和实际验收范围。避免承诺未验证的边界，公式与数据以现行脚本为准。把与各段玩法相关的真实游戏截图穿插在说明中，优先选择清晰、无测试控制台覆盖、无其他 Mod 的截图。图片源文件及 BBCode 中引用的发布地址建立可审计对应关系。

发布链路先完成简体中文修复回归、静态和 `open_kaishek` 检查，再建立正式 changelog 和 `[v0.1.1]` Change Note；提交推送发布源后更新已拥有的创意工坊物品，核验说明、截图、版本和包哈希，最后创建推送版本标签。发布期间 Steam 保持在线所需的最短时间，结束后恢复离线。

## 验收标准

1. BBCode 入库，分段准确说明实际机制，读者仅靠页面可理解关键公式、收益、代价和复发风险；与脚本、changelog 一致。
2. 页面至少有 5 张不同玩法场景的真实游戏截图，穿插于相关段落；每张截图源文件、URL、用途与文件哈希均记录在库；公开页面能实际显示图片。
3. 待复活提示和复活后对话的简中实机回归通过；十种本地化键齐全，其他九种语言静态校验通过、运行时不在范围内；正式 Mod `open_kaishek PASS`。
4. `0.1.1` 发布到物品 `3810136486`，远端 BBCode、变更说明、预览、截图和内容哈希与入库源一致；只读上游物品 `3710613857` 不受影响；发布后再继续其他测试。
