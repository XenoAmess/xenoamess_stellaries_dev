# SC-04 正式减速系数与 4800 名维护员验收（2026-09-29）

## 目标与范围

补齐现行验收矩阵的 `n=0,J=4800`、`n=1,J=5800` 边界。`J` 是两种维护员岗位在本国所有星球的**实际已分配劳动力**，不能以空岗位容量、手写存档字段或直接改写脚本值代替。已有 `J=99/100/199/200/300` 及隔离减速系数的 `0.2` 下限实测证据保留。

## 隔离夹具方案

只在新的简体中文单 Mod 用户目录中复制当前正式 Mod 和既有可重载存档。隔离副本以一个临时行星静态修正增加目标机械政体对应的维护员岗位容量，不改 `common/script_values/shishan_code_values.txt` 中正式的 `base=5`、`mult=0.1`、`min=0.2`，也不改正式研究所。使用 Stellaris 4.5.1 原版人口效果增加主体机械人口，使游戏自己分配岗位；如其他岗位或人口权重妨碍精确边界，只调整隔离夹具中的人口和岗位容量，不直接篡改存档的岗位劳动力。所有夹具文件、命令和变化前后哈希单独记录；正式 Mod 树及其运行副本不应被覆盖。

先在 `n=0` 下取得 `J=4700/4799/4800/4899/4900` 等实际岗位面板读数，至少验证 `4799` 仍大于 `0.2` 而 `4800` 为 `0.2`。再以完成一次真实维护项目后的 `n=1` 状态取得 `J=5800`，验证下限仍为 `0.2`。若精确人口难以稳定，至少用 `J=4800` 和 `J>=5800` 并记录实际 `J`，不得把“容量 4800/5800”写成实际分配人数。

## 验收标准与证据

游戏岗位面板、存档人口组与岗位结构三处一致；`n=0,J=4800` 的局势 UI 月速为 `+0.2`，从可重载基线自然跨月至少一次后进度增量为 `0.2`。`n=1,J=5800` 同理；应与正式 `max(0.2,5+n-0.1×floor(J/100))` 精确相符。保留基线和结果 `.sav`、Steam F12 简中截图、SHA-256、游戏日志与 `open_kaishek` 的夹具及正式 Mod 报告。试验结束恢复/检查正式运行副本逐字节等于仓库 Mod，并明确区分“数值公式实机通过”和“正常游玩造 48/58 座研究所的平衡观察”。若引擎无法稳定分配该规模岗位，记录为待测，不据隔离系数夹具宣布正式 `J=4800` 通过。

## 首次隔离探针与夹具修订

首次静态修正同时写入 `job_shishan_code_maintainer_drone_add=4800` 和 `job_shishan_code_maintainer_add=4800`，`open_kaishek` 为 `PASS`（20/20 脚本），控制台确认给首都增加两个各 `4800` 的岗位池并创建 `6500` 机械人口。跨日后岗位面板出现一个 `4800` 的专家岗位和一个 `4800` 的复合子个体岗位，局势虽然显示 `+0.2`，但这是约 `9600` 岗位容量的混合样本，**不能**用于 `J=4800` 结论。该局势截断只是一个无效的过量岗位探针。两类岗位不能在同一个机器智能测试国同时放大。下一次从原始存档重载前将夹具改成只提供 `shishan_code_maintainer_drone`，重新通过工具检查并启动新进程；新增人口须经日结算才会分配，暂停日立即读取的 `+5.0` 不构成失败。
