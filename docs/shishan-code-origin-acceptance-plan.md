# 「屎山代码」独立 Mod：测试与验收方案

状态：**设计完成，尚未执行**。依据[需求记录](shishan-code-origin-requirements.md)与[详细设计](shishan-code-origin-design.md)；此方案定义将来 Mod 实施后的验收，不代表已创建或通过测试。记录日期：2026-09-26。

## 1. 目标与通过条件

验收要证明起源在两类机械帝国中可玩、局势和项目按公式运行、每笔持续产出只获得**岗位或非岗位中的一项**阶段修正、白绮可以按规则死亡和复活、奖励及存档状态不会丢失。正式结论需同时具备：适用游戏版本的 `open_kaishek` 检查通过、本 Mod 静态合同通过、简体中文单 Mod 实机加载通过、以下必测场景通过、关键状态的存档重载通过。任一必要条件失败，结论为未通过或阻塞，并保留证据。

本轮只有文档，因此所有运行项均为**未执行**。平衡性对照用于判断数值是否应调整；不以玩家胜率或随机样本比例替代功能验收。

## 2. 固定输入与隔离

| 输入 | 每轮必须冻结或记录 |
| --- | --- |
| 游戏 | 游戏版本、`stellaris.exe` SHA-256、启用 DLC、游戏脚本基线哈希。游戏更新后重新核对修正键、岗位模型和脚本 profile。 |
| Mod | 独立 Mod 目录整树 SHA-256、Git 提交、描述符和依赖；只启用本 Mod 与验收专用夹具，不启用现有「无限岗位」或其他玩法 Mod。夹具不进入正式发布包。 |
| 环境 | 隔离 userdir、简体中文 `l_simp_chinese`、非铁人、固定难度与初始帝国配置；记录屏幕分辨率、游戏速度、时间暂停状态、随机种子或可复现的抽签序列。 |
| 对照 | 与被测帝国相同的物种、政体、星球、已分配劳动力、建筑和科技；仅改变起源或单独开关测试修正。保留每个对照存档，不直接拿不同开局的帝国资源总量相减。 |
| 证据 | 每个场景保存前后截图/OCR、动作记录、`error.log`/`game.log`、测试断言结果、存档文件 SHA-256 与必要的 `gamestate` 片段；结果记录输入指纹和失败最小复现。 |

复用[Stellaris 实机自动化经验](stellaris-runtime-testing.md)中的隔离启动、物理扫描码、OCR 与存档证据方法；先确认目标游戏版本仍适用。推进时间使用“解除暂停—短时推进—再次暂停”的闭环，并用日期和状态复核。开发夹具可设置进度、`n`、已分配劳动力、研究资源和抽签结果，以缩短测试；需同时保留至少一条不经跳阶段夹具的自然时间推进路径，避免只测夹具自己写出的状态。

## 3. 验收闸门与执行顺序

1. **脚本可行性探针。** 在正式编码前以最小可抛弃样例验证：岗位与非岗位持续产出能否按来源互斥修正；影响力、凝聚力、三类研究和 DLC 资源如何按来源覆盖；动态项目研究成本；局势末段驻留与归零；领袖死亡、成长保留与复活。探针结果回写本仓库文档，无法隔离收入来源时先修订实现方案，不能退回双重加成。
2. **P 语言工具闸门。** 根据 `open_kaishek` 仓库使用说明，选择与实际游戏版本和本 Mod 脚本范围匹配的 profile，检查起源、局势、项目、特质、建筑、岗位、事件、on_action 和引用。当前已调查到的 Stellaris 4.4.6 profile 主要覆盖决议/地块等受限切片，**不能据此声称本起源全量静态验收**。如 profile、验证器或验收所需能力不足，先在该工具仓库按其规则修复、测试、提交并推送，再回来重跑；工具未通过时停止 Mod 验收。
3. **本 Mod 静态合同。** 校验所用资源/修正键与目标版本相容、起源条件、全部脚本和本地化引用、三种项目成本公式、数值边界、奖励白名单、重复注册及非发布夹具泄漏。英文及其他翻译仅做键完整性、文件头/编码、引用、原始 key 泄漏风险与简体中文占位检查；结论只能写“静态校验通过，运行时不在范围内”。
4. **单 Mod 简体中文加载与实机。** 隔离启动并检查本 Mod 可归因的加载/运行错误，再按下表执行功能场景；运行时 UI、OCR、存档重载只用 `l_simp_chinese`。
5. **报告与回归。** 每个 ID 记录 `PASS`、`FAIL`、`BLOCKED` 或 `NOT RUN`，列明预期、实测、日志/截图/存档指纹。修复后重跑失败场景和受影响的邻接场景；游戏版本或关键 DLC 组合变化时重跑来源隔离、局势、项目与语言闸门。

## 4. 必测场景

### 4.1 起源、局势和岗位

| ID | 操作与通过标准 |
| --- | --- |
| SC-01 资格 | 在帝国创建器分别选择机械智能格式塔和个体机械主体物种，起源可选并成功开局；有机主体物种不可选。主物种起始仅有一个「屎山代码」；相同物种模板的可用特质点比对照少 `6`，特质上限多 `3`。 |
| SC-02 初始 | 开局只有一个「大厦将倾」，进度 `0`、`n=0`；研究所立即可建，静态核对无本 Mod 单星球数量上限，实机在有建筑槽位时同一星球能建至少两座；其他帝国不获得起源专属项目/建筑。 |
| SC-03 阶段边界 | 固定其他条件，检查进度 `0/249/250/499/500/749/750/949/950/1000` 的阶段与五类修正。边界从左闭区间切换，旧阶段修正消失；第五阶段跨多个月继续存在，直到维护或清理。 |
| SC-04 速度 | 检查公式 `max(0.2,1+n-0.1×floor(J/100))`。`n=0,J=0/99/100/199/200/800` 应分别得到 `1/1/0.9/0.9/0.8/0.2`；`n=1,J=0/100/1800` 应得到 `2/1.9/0.2`。`J` 必须取所有星球该岗位**已分配劳动力**，空岗位容量不计；UI 速度与实际月推进一致。 |
| SC-05 研究所 | 在同星球保留一座原版社会学研究建筑，只增减本研究所：仅本建筑提供的社会学岗位转为维护员，岗位数与已分配劳动力正确；每个等效岗位的社会学基础产出比相应原岗位少 `1`，其他建筑岗位与正常资源消耗不变。两类机械帝国各测一次，存档重载后不多出岗位或减速。 |
| SC-06 舰船与维护费 | 固定舰型、武器、提督、科技和航行环境，对照无阶段修正时的武器面板伤害、受控战斗的实际命中伤害与同段航行时间；I/III/IV/V 阶段分别核对武器伤害与亚光速航速 `+25/-25/-50/-75%`，不能只看局势说明。固定同一岗位与劳动力，核对维护费 `-25/+25/+50/+75%`；第二阶段各项回到基线。 |

### 4.2 资源来源隔离：硬验收

对每一种目标资源建立来源清单，逐项标出是否存在岗位、采集/研究站、巨构建筑、帝国固定月产出及启用 DLC 条件；没有某类原版来源时以来源审计为证标 `N/A`，不得编造可用来源。至少在每个适用来源类别中取得一个可观察样本；涉及影响力、凝聚力、三类科研、战略资源与 DLC 资源时分别保留覆盖证据。用同一暂停存档分别运行“仅岗位项”“仅非岗位项”“两项同时”三种受控场景，核对**单项前后差值和两项同开结果**。阶段 I、III、V 至少各做一轮；对受精度或其他原版加成影响的资源，用同一来源详情和月结算差值核算，冻结其他修正并记录 UI 舍入，不凭顶部净收入一个数字推断来源。

| ID | 操作与通过标准 |
| --- | --- |
| RS-01 岗位 | 对能量、矿物、合金、凝聚力和三类科研点等有岗位来源的资源检查：岗位项只影响岗位产出；打开非岗位项后同一岗位结果**不再变化**。岗位基础产出 `100` 的纯净样例，I 阶段目标 `125`、III 阶段 `75`、V 阶段 `25`，而不是 `150/156.25` 等叠加值。 |
| RS-02 非岗位 | 采集站、研究站、巨构建筑、帝国固定月产出分别验证：非岗位项只影响对应持续生产；单独打开岗位项时这些来源不变。非岗位基础产出 `40` 的纯净样例，I/III/V 阶段目标 `50/30/10`。每一资源和来源都需有结果或列明不能覆盖的实现缺口；缺口不得记为通过。 |
| RS-03 合并与排除 | 同资源纯净样例 `P_job=100,P_nonjob=40`，I/III/V 阶段总持续产出分别为 `175/105/35`，每笔只修正一次。附庸上缴、贸易协定和每月市场交易不受非岗位项放大；一次性资源奖励、库存上限与维护费也不进入产出池。岗位维护费按阶段独立检查 `-25/0/+25/+50/+75%`，净收支允许因维护费变化而不同。 |
| RS-04 其他加成 | 在已有原版岗位/空间站增产修正、白绮科研速度、不同物种混合劳动力条件下复测，确认本起源自身不跨来源重复生效；科研**产出**与科技**研究速度**分别记录。单纯出现其他原版修正造成的叠加不算本起源来源隔离失败。 |

### 4.3 项目、奖励与重构

| ID | 操作与通过标准 |
| --- | --- |
| PR-01 成本与结算 | `n=0/1/2` 时，维护成本 `2000/3000/4000`、清理成本 `8000/10000/12000`；重构后持续优化成本 `4000/6000/8000`。项目显示值等于实际消耗的社会学研究进度，不按一次性能源或库存支付；成功后才使 `n+1` 并刷新下一次成本。 |
| PR-02 维护 | 在阶段 I 和 V 各完成一次维护：仅一次成功结算、进度归 `0`、月速增加 `1`，清理成本增加 `2000`，主物种恰好获得一次合法正面奖励；第五阶段切回第一阶段修正。取消、研究中断或重复触发结算不改变 `n`/特质/进度。 |
| PR-03 清理 | 分别从早期和第五阶段完成清理：局势消失，移除「屎山代码」且添加唯一「重构完成」；主物种岗位产出获得 `+25%`，非岗位阶段修正消失，项目名称改为「持续优化」。再次查看/重载不重复发放特质或重新出现局势。 |
| PR-04 优化与复发 | 用可记录抽签的验收夹具强制一次未复发和一次复发：每次优化成本按当前 `n` 计算、成功后 `n+1` 且发一次奖励；未复发时保持无局势与「重构完成」；复发时移除「重构完成」、恢复「屎山代码」，仅一个局势从 `0` 开始，维护/清理项目和当前 `n` 成本恢复。静态核对复发分支标称概率为 `10%`，不以少量随机样本的命中率作为硬闸门。 |
| PR-05 奖励池 | 审计当前游戏与启用 DLC 的候选白名单：机械正面特质优先、抽尽后才抽对机械人口实际生效的非机械正面特质，两层都抽尽后才进入四类可重复「优化迭代」；同一层各候选抽取权重相同。用确定性夹具覆盖层切换、冲突/已持有跳过、每种迭代结果、重复抽中叠加；验证每次只发一个有效奖励，主体物种及其实际人口模板得到数值，其他物种和帝国不被误改。 |

## 5. 平衡性观察与报告边界

使用同版本、同 DLC、同难度与尽量相同的机械帝国配置，对照无本起源、正常游玩本起源的“尽早清理”“定期维护”“拖至第五阶段”三条路线，记录前 `20` 年经济/科研/舰队、首次清理时间、维护员机会成本、第五阶段是否仍有能力完成清理。`J=0/800/1800` 和 `n=0/1/5/10/28` 的理论时间与实际时间分开记录。平衡观察可能促成新一轮数值设计，但不得在原合同未改时把“感觉还行”写为功能通过。

报告须分清 `STATIC`、`LOAD`、`SCENARIO` 与平衡观察；注明未执行项和工具/游戏版本限制。若来源隔离、第五阶段可清理、复活保留成长、原本应有效的奖励实际生效任一项失败，不能宣称 Mod 验收完成。`open_kaishek` 无法运行或无法覆盖本 Mod 时，按仓库规则先处理工具缺口并如实报告阻塞原因。
