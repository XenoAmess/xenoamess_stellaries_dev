# Stellaris 实机自动化经验

本文记录本项目在 Stellaris 4.4.6 上已经实测确认的 UI、存档和日志行为。它们属于 Stellaris 专有实践，不同步到 CK3 方言知识库。

## 输入优先级

1. 优先发送物理扫描码。普通虚拟键在 Stellaris 中可能没有效果；已确认 Esc 使用扫描码 `0x01`，回车使用 `0x1c`，空格使用 `0x39`，F7 使用 `0x41`。
2. 有稳定文字目标时使用 OCR 点击，例如主菜单的“保存游戏”“读取游戏”和“退出到桌面”。
3. 只有对象没有快捷键或稳定文字入口时才使用坐标，例如具体星球、窗口关闭按钮和决议列表滚动条。
4. 2560×1440 截图可能在查看器中缩放到 2048×1152。动作坐标必须使用原图/OCR JSON 坐标，不能从缩放后的预览图直接抄坐标。
5. 直接启动后若 Stellaris 窗口已前台但画面透明、仍露出桌面，发送物理 `Alt+Enter`（扫描码 `0x38` + `0x1c`）可强制切换显示模式并恢复绘制。运行 `20260906T041510Z` 已复现并用此方法恢复；恢复后再继续截图，不能把透明帧判为游戏未启动。
6. OCR 点击会在鼠标悬停后同时识别决议卡片标题与提示框中的重复标题。若 action 记录的命中坐标落在决议窗口之外，点击并未执行决议；应先把指针移出提示区域，再按已由 OCR 固定的卡片坐标点击，并以状态变化和日志复核。
7. 需要清除提示框但保留当前窗口时，可在窗口外安全区域执行 `scroll 0`，只移动指针而不点击；点击空白区域可能直接关闭决议或殖民地窗口。
8. 不应仅凭发送 F5 就宣称快速存档成功；运行 `20260906T053229Z` 未观察到 F5 生成文件。回归夹具应通过暂停菜单进入“保存游戏”，并在文件系统中核对 `.sav` 的名称、字节数和 SHA-256 后才记录成功。

## 方舟殖民地导航

- F7 的“殖民地和星域”列表不列出游牧方舟殖民地，不能把“列表为空”解释为方舟不存在。
- 可靠入口是展开右侧概览的方舟组，选择方舟实体，再点击殖民地名“首都方舟”。若“首都方舟”子项尚未展开，可先点击星图中的方舟实体，使右侧条目展开后再按文字进入。方舟载体使用 `pc_ark` 并复用标准“决议”窗口，但 4.4.6 实机日志证明该窗口执行决议时 root scope 是 `ship`，不是普通殖民地的 `planet`；新增 flag/effect 必须支持两种 scope。
- 决议窗口的鼠标滚轮在当前布局中不可靠；拖动窗口最右侧滚动条滑块可以稳定遍历长列表。目录证据应以多张有重叠编号的截图覆盖，避免滚动跨度造成漏项。

## 效果与存档断言

- 4.4.6 的“地产”页用于分公司/宗主持有关系，不是通用星球特征页，不能用它断言 `add_deposit`。
- 对方舟的可靠效果断言是：决议队列出现且倒计时完成、适用区划上限或岗位数变化、存档 `gamestate` 中出现 deposit 键、重载后相同数值仍保持。
- 存档是 ZIP 容器，可只读检查其中的 `gamestate`。检查时同时断言 deposit 名称和出现次数，避免仅凭字符串存在误判。
- 中文输入法可能把自动输入的 ASCII 存档名转换为全角标点。本地夹具应按实际文件哈希定位存档，或先切换英文输入法；不要把预期文件名作为唯一成功条件。

## 日志归因

- 隔离 userdir 仍可能从启用文件中看到已订阅但本机缺失的其他 Workshop 路径。只有当前被测 Mod 的加载、脚本或运行错误才使 `LOAD-GREEN` 失败。
- `error.log` 的存档修复信息必须与重载后的 UI 数值和 `gamestate` 一起判断。若目标 deposit 仍唯一存在且效果保持，不能仅凭一次通用修复消息认定目标 deposit 丢失；该消息仍需记录并在后续回归中追踪。
