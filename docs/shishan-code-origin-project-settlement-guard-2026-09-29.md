# 特殊项目重复结算防护（2026-09-29）

## 发现与目标

PR-02 验收方案要求维护项目取消、中断或重复触发结算时不额外增加 `n`、局势重置次数或奖励。静态审查发现 `shishan_code.10` 目前仅检查起源与“尚未重构”，`shishan_code.30` 仅检查“已重构”；若在项目成功后再次直接触发对应国家事件，两者会再次 `change_variable` 并发奖。正常引擎只发送一次 `on_success`，但事件本身没有防止重复调用。清理事件 `shishan_code.20` 的“尚未重构”触发条件在首次结算后已变为假，具备一轮的一次性防护。

目标是在不改变项目费用、研究队列、随机奖励和白绮对话的前提下，让维护与持续优化的国家结算事件只接受对应项目的成功回调，并在处理时立即消费一次性凭证。不能把普通科技改选当作项目中断：已归档的原生存档证明它不会抢占队首。

## 设计与范围

在 `SHISHAN_CODE_MAINTAIN` 与 `SHISHAN_CODE_OPTIMIZE` 的 `on_success` 中，调用结算国家事件前分别设置临时国家旗标 `shishan_code_maintain_success_pending` 与 `shishan_code_optimize_success_pending`。两个国家事件的 `trigger` 增加对应旗标，但真正的结算主体必须包在 `immediate` 的 `if = { limit = { has_country_flag = ... } ... }` 内；进入该块第一步移除旗标，然后沿用既有计数、奖励、局势和对白流程。项目取消不会设置旗标。对应事件被再次直接调用时，已消费的旗标不在，不能重复结算。两类项目下一轮真实成功会再次设置旗标，因此不限制可重复次数。

第一版仅在 `trigger` 中检查旗标，已被实机证伪：隔离游戏控制台执行 `event shishan_code.10` 时，控制台把缺失旗标标红，但仍执行事件的 `immediate`，同日 `n:2→3`、局势 `14→0`，多发正面特质并播放维护完成弹窗。因此不能把 `trigger` 当作对控制台直接调用或外部强制事件的结算防线；必须在效果体内再次判断。该失败试验发生在正式修复前的候选脚本隔离副本，不能当作最终通过。

这只防止额外**国家事件调用**；恶意外部脚本伪造项目 `on_success` 整段效果不在本 Mod 的权限边界内。正式 Mod 原有 `shishan_code.20` 及其他触发事件不改。

## 验收标准

1. 改动前以隔离简体中文存档与控制台重现直接重复调用：`n` 与奖励确实再次变化，作为缺陷基线；该操作不用于证明自然项目成功。
2. 改动后正式 Mod 经 `open_kaishek` 通过，项目成功到国家事件的旗标授予、消费与触发条件静态一致；重复直接调用事件不改变 `n`、奖励、局势、白绮修正或项目费用。
3. 使用正常研究完成维护及持续优化的隔离简体中文路径，确认首次结算仍各成功一次、下一轮项目重新出现且可继续成功；归档原生存档、游戏截图和报告。先前版本存档可能没有新旗标，但旗标由新的项目成功回调即时创建，不要求迁移存档。
4. 正式包、部署副本与测试夹具严格区分；实机完成后重新部署正式内容并复查哈希与 `open_kaishek`。非中文语言仅做静态校验，运行时不在范围内。

## 本轮结果

- 维护项目研究中存档 `pr02-n2-research-switch-2229.10.15.sav` 为 `n=2`、局势进度 `14`。修复前强制 `.10` 可错误结算，截图及存档以 `pr02-duplicate-before-fix-*` 归档；仅在 `trigger` 加旗标也被控制台绕过。
- 最终脚本中，研究中强制 `.10` 后存档 `pr02-guard-direct-maintain-2229.10.15.sav` 保持 `n=2`、进度 `14`、队列和主物种特质不变。正常科研于 `2229.11.02` 触发「维护完成」弹窗，撤除临时研究加速后的 `pr02-guard-natural-maintain-2229.11.03.sav` 为 `n=3`、局势进度 `0`、下一轮维护可用；再次强制 `.10` 的 `pr02-guard-post-natural-duplicate-2229.11.03.sav` 与之在次数、特质、项目、局势和白绮层数上一致。
- 重构后从 `pr01-optimize-n1-in-progress-2229.07.27.sav` 出发，完成前强制 `.30` 没有弹窗。正常科研于 `2229.08.02` 触发「持续优化完成」，撤除临时加速后的 `pr01-guard-natural-optimize-2229.08.03.sav` 为 `n=2`、无局势；再次强制 `.30` 的 `pr01-guard-post-natural-duplicate-2229.08.03.sav` 与之在次数、特质、项目、局势和白绮层数上一致。
- 两条自然完成存档都没有测试加速修正引用。正式包 `open_kaishek PASS`：19/19 脚本、13 DDS、172 本地化键。此轮证明重复**国家事件**调用被拦截；正式包部署哈希与整体验收矩阵仍在发布前后各自核对。

## 发布后续测：重构中断排队维护

从真实研究中的双项目队列存档出发：维护已累计研究点，清理在同一学科队列中等待。隔离简中单 Mod 游戏里以受控 `shishan_code.20` 回调模拟清理先行结算，观察局势结束时研究中的维护是否被引擎取消、保留或允许完成。先保存重构后状态，随后跨过至少一个社会学月结算并重载；核对 `n`、主物种特质、全国重构岗位修正、局势、队列和成功凭证旗标。此探针不算自然清理项目成功，只用于查明项目状态被外部局势终止时的引擎行为。若维护可能在重构后成功，须补充正式 `on_success` 条件，确保不留下以后复发时可误用的凭证；修复前先更新本节设计和验收标准，并用 `open_kaishek` 及正式单 Mod 复测。

### 探针结果

- 在正式 `0.1.0` 单 Mod、简体中文隔离环境中载入 `pr02-n2-research-switch-2229.10.15.sav`。基线为 `n=2`、局势进度 `14`、社会学队列：维护项目 ID 5 已研究 `28.33912/4000`，清理项目 ID 6 等待中。
- 暂停状态下受控执行 `event shishan_code.20`。即时存档 `pr02-interrupt-cleanup-2229.10.15.sav` 显示维护 ID 5 已从项目表和科研队列移除，`n` 仍为 `2`，主物种已改为 `trait_shishan_refactored`，全国岗位修正已有一层。此时局势与等待中的清理 ID 6 暂留在序列化状态，因此不把即时存档单独当作最终清算结果。
- 推进至 `2230.01.01` 的存档 `pr02-interrupt-month-2230.01.01.sav` 显示局势数为 `0`，原维护 ID 5 和清理 ID 6 都不在项目表或社会学队列；下一轮 `SHISHAN_CODE_OPTIMIZE` 已可用但未在研究。`n=2`、主物种重构特质与全国岗位修正均保持；白绮基础修正一层、工程学与社会学阶梯各两层。三个存档的 `gamestate` 均无 `shishan_code_maintain_success_pending` 或 `shishan_code_optimize_success_pending`，没有遗留一次性结算凭证。
- 同一隔离游戏成功重载 `2230.01.01` 存档，简中游戏界面显示局势不再存在。此结果证明**外部触发清理回调时**正在研究的维护被中断且未额外结算；它不代替清理项目自然完成、双项目竞速和其他取消组合的实机验收。

## 后续实测方案：第五阶段正常完成维护

从 `n=2`、已有真实维护研究进度且未重构的正式单 Mod 存档分出第五阶段测试支线。在游戏国家作用域把局势进度设为 `950` 后保存基线；该操作只设局势进度，不直接触发维护结算。为缩短等待，可在**隔离部署副本**中增加无 BOM UTF-8 的测试静态修正，仅提高社会学研究产出；原仓库正式 Mod、Workshop 包和存档主线不注入夹具。确认维护项目通过正常科研月结算结束并显示简中对白，保存即时结果。移除测试修正、退出夹具进程，再以重新部署的正式单 Mod 重载终点存档；核对 `n=2→3` 一次、进度归零、月速按 `+5+n` 与劳动力规则由 `+7` 变 `+8`、主物种只获一次合法奖励、旧特质仍在、下一轮维护与清理费用分别为 `5000/14000`，并核对无测试修正引用。另用同日期第五阶段基线核对阶段负面修正已切换为第一阶段正面修正。正式包仍需 `open_kaishek PASS`。若研究完成或回载出现差异，先记录缺陷与最小修复方案，再改正式代码并按新补丁版本发布规则处理。

首次操作发现两个夹具控制边界：一条带空格的长控制台命令在当前中文输入状态实际只输入了末尾 `50`，使进度暂变为 `50`；F12 输入截图和存档核对后改用已验证的短命令 `effect every_situation={set_situation_progress=950}`，正式锚点 `pr02-stage5-maintain-anchor-2229.10.15.sav` 确认真实进度为 `950`，误设的 `50` 存档不用于验收。隔离副本追加无 BOM 测试修正后，正常研究于 `2229.11.02` 弹出「维护完成」，UI 月速 `+7→+8`。但同一社会学队列里还排着清理项目；关闭维护弹窗后，游戏继续推进到 `2229.12.02`，测试科研加速使清理也完成。这个试跑只能证明第五阶段维护自然完成的瞬时事件，不能把随后清理结算的存档当作纯维护终点。下一轮从同一正式锚点重载，先用暂停控制确保关闭维护弹窗时游戏不再推进，再移除加速并保存。若引擎无法在弹窗开着时撤除加速，改在其关闭后同一暂停日期操作，不允许跨到下一社会学结算。
