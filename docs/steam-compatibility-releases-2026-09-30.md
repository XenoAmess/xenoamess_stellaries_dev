# Stellaris 4.5.1 兼容维护版本逐个 Steam 发布

## 目标与范围

用户在完成五个 Mod 的兼容维护后明确要求“有更新的，都给我一个一个发布到steam”。本次只发布三个发生更新的包，按下列顺序更新既有公开物品，不新建重复物品：

| 顺序 | Mod | Workshop ID | 候选版本 | 正式版本 |
| --- | --- | --- | --- | --- |
| 1 | 无限岗位 | 3797257579 | 1.2.1-rc.1 | 1.2.1 |
| 2 | 灰风美化 | 3800996999 | 1.0.2-rc.1 | 1.0.2 |
| 3 | 合成女王美化 | 3807768508 | 0.1.1-rc.1 | 0.1.1 |

牢大 0.1.2 和屎山代码 0.1.3 已发布且生产内容未改，不重复上传。原无限岗位 3710613857 及灰风灵感来源 2976454692 均为只读，禁止作为上传目标。用户文件 console_history.txt 不纳入提交。

## 设计与实施方案

1. 发布前保存三个目标及只读上游的匿名 Steam 详情、历史 Change Note、内容 manifest 与说明指纹；核验目标身份与正式版本未发布。
2. 晋升各 VERSION、descriptor、当前验收合同与运行时夹具指纹；不修改已验收的玩法、肖像或 DDS。建立正式 changelog，Change Note 从该条目提炼并以 [v版本] 开头。
3. 页面文案以仓库 BBCode 为真源，保留无限岗位原说明前缀、归属授权和历史截图，明确当前 4.5.* 支持、4.5.1 简体中文复测与实际验收边界。
4. 增加本次三个包的专用更新/核验入口，复用现有 Steamworks DLL 调用；只允许以上三个既有目标；检查推送过的提交、版本与内容指纹、远端发布前快照，保存提交状态以避免无证据重复上传。
5. 使用 C:\workspace\open_kaishek 对正式包执行整包静态验收，运行必要版本/包树测试。此次仅版本晋升与发布文案改变，沿用上一任务同字节内容的 4.5.1 简体中文重点实机和同版本新档重载证据，不重复扩张实机矩阵。
6. 先提交并推送发布源，再依次上传，每个成功提交后核验公开详情、完整 Change Note、预览保持及空缓存重新下载后的全部文件字节。通过后沉淀发布证据、提交推送并创建版本标签，再继续下一个。

## 验收标准与限制

- 正式版本与 descriptor 一致，supported_version 为 4.5.*，三个 Change Note 均以正确版本开头且与正式 changelog 一致。
- Steamworks 返回成功、目标 ID 正确且不需要新协议确认；匿名详情显示公开、未封禁、完整说明一致、内容 manifest/更新时间变更。
- 空缓存下载的文件列表及 SHA-256 与正式上传源一致；如平台规范化描述符末尾换行，必须显式记录并验证语义及唯一差异。
- 三包的已有美术和非元数据脚本无变化；只读上游更新时间、内容与说明指纹保持不变；本轮不声称女王自然危机全流程通过，非中文仅静态校验通过。
- 如 Steam 会话离线，按既有发布经验恢复在线连接；如无法恢复或上传结果不确定，先读回远端和状态，不直接重复提交。
- 发布成功后每个版本建立并推送对应 Git 标签。多包共享仓库时先检查标签唯一性；如裸 v版本 已被另一包占用，不覆盖历史标签，使用 Mod 名称命名空间并记录理由。

## 实施记录

- 初始 HEAD 为 910b455，origin/main 一致；仅有用户未跟踪文件 console_history.txt。
- Steam 初始离线，正常关闭后在 Steam config 目录保存原 loginusers.vdf 备份，只临时将唯一账号 WantsOfflineMode 从 1 改为 0，再正常启动；Steamworks 已读回在线登录。
- 匿名 Steam Change Note 网页返回 HTTP 429；公开详情接口与 Steamworks 可用。发布前记录该限制并核对既有发布历史及远端内容身份，发布后以 Steam 客户端同一公开改动说明页的截图和复制出的完整正文读回 Change Note，不把本地发送文字当作远端读回证据。
- 共享仓库已有 v0.1.1（其他包历史发布），合成女王采用 synthetic-queen-v0.1.1，灰风沿用 gray-wind-v1.0.2，无限岗位使用 v1.2.1；不覆盖任何历史标签。
- 当前兼容验收详情见 [全项目兼容报告](stellaris-latest-compatibility-2026-09-30.md)。
- 正式包 open_kaishek 通过：无限岗位 4/4 P 文件、64 键十语言；灰风 8/8、4 DDS；女王 2/2、1 DDS。初次给美术包传入 content folder 而未提供外置 VERSION，报告 MOD_METADATA_MISSING；改用工具文档规定的 package root 后通过，没有修改工具或 Mod 内容。
- 仓库现有测试 39/39 通过，发布脚本 py_compile 和 git diff --check 通过。发布前 snapshot 已记录三个候选包的全部文件哈希，非描述符文件与正式包逐字节相同。
- 正式发布源、快照与静态证据先提交推送；随后按顺序更新既有物品。发布结果与下载比对待实施后写入。
- 首次无限岗位预检发现：匿名接口的原作者正文用 CRLF，仓库 BBCode 用 LF。预检在提交远端前拒绝了这种字节前缀差异，没有上传。发送时保留远端原作者正文的 CRLF 原字节，再追加仓库 LF 的维护说明；核验按同一明确变换比较，避免把换行差异误报为原文被修改。最终传输文案须仍低于 8000 字节。
