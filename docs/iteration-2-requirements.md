# 迭代 2 正式需求基线

## 1. 文档信息

- 状态：已确认，可进入实现
- 确认日期：2026-09-09
- 基线来源：《迭代 2 候选需求分析：居住站区划与人口发展》及用户确认
- 目标候选版本：`1.2.0-rc.1`
- 目标游戏：Stellaris Pegasus `4.4.6` / `4.4.*`
- 运行时语言边界：只允许简体中文；其余 9 种官方语言仅做静态翻译验收

## 2. I2-001 补齐居住站资源区划容量

- 优先级：P1
- 类型：兼容性修复

需求：

1. 计划 09 每次完成后，除既有普通行星效果外，在居住站增加 `2` 个反应堆区划容量。
2. 计划 10 每次完成后，除既有普通行星效果外，在居住站增加 `2` 个航天采矿湾容量。
3. 计划 04、05、06 每项每次完成后，仅在居住站增加 `2` 个总区划槽位与 `2` 个研究区划容量。
4. 居住站专用效果以 `uses_district_set = habitat` 为边界，不扩散到普通行星、方舟舰或其他 district set。
5. 不增加自定义 district，不虚构居住站农业容量键，不改变既有计划的成本、耗时、岗位、效率和重复规则。

静态验收：

- 对应五个 deposit 的映射、数值和 habitat 条件具有自动化合同。
- 计划 09/10 的普通行星 modifier 保持原值；计划 04/05/06 不获得无条件的总区划加成。
- `open_kaishek` 必须识别并 fail-closed 校验 `uses_district_set`；Mod 三个生产脚本入口全部 `VALIDATED`。

运行时验收（本轮明确延期，不启动游戏）：

- 简体中文居住站逐项验证总容量、目标容量、非目标容量、重复叠加和存档重载。
- 普通行星及方舟执行回归，确认无跨 district set 泄漏。

## 3. I2-002 人口增长与组装扩展计划

- 优先级：P1
- 类型：新增玩法
- 产品形态：新增计划 14，通过决议添加永久 deposit；不是新的可建造 district。

需求：

1. 新增 `decision_14_extend_population_development`，沿用折叠菜单和现有载体兼容 trigger。
2. 决议消耗 `1000` 矿物，执行 `180` 天，AI 权重为 `0`，允许重复执行。
3. 每次添加一个 `mod_extend_population_development` deposit。
4. 每个 deposit 提供：住房 `+600`、人口自然增长速度 `+10%`、机械人口组装速度 `+10%`。
5. 使用 `logistic_growth_mult = 0.1` 与 `planet_pop_assembly_mult = 0.1`；不添加人口增长或机械组装平值，不为零基础通道凭空制造人口。
6. 新增四个本地化键，并为 Stellaris 4.4.6 官方全部 10 种语言提供译文；仅简体中文进入未来实机验收。
7. I1-005“按人口动态扩展岗位”继续保持不做，本需求不得按人口数量动态改岗位。

静态验收：

- 计划 14 的唯一性、条件、成本、耗时、deposit 引用和三个 modifier 数值具有自动化合同。
- 15 个计划及 15 个 deposit 在 10 种语言中各有名称/说明对，键集合完全相等。
- 非中文文件通过 BOM、文件头、编码、引用、可读字符和简体中文占位泄漏检查。
- Mod 完整通过仓库测试与 `open_kaishek` 静态验收。

运行时验收（本轮明确延期，不启动游戏）：

- 后续只在简体中文下验证有机、机械、双通道、蜂巢、失控机仆、居住站和方舟矩阵。
- 每次 `+10%`、重复后 `+20%`、两个 deposit、存档重载和日志均需形成证据闭环。
- 在完成上述实机矩阵前，只能声明“实现完成、静态校验通过、运行时待验收”。

## 4. 非目标与操作约束

- 本轮不得启动 Stellaris、Paradox Launcher 或任何会抢占前台的 GUI。
- 不做 OCR、鼠标/键盘自动化、截图或存档写入。
- 不发布 Steam，不更新 Workshop 页面，不创建正式版标签。
- 不覆盖原版区划文件，不调整计划 00—13 的既有数值（I2-001 明确列出的 habitat 增量除外）。

5. 提交并推送本仓库；最终报告明确区分静态通过与运行时延期。
