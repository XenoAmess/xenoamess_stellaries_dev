# 全项目 Mod 最新正式版兼容检查

日期：2026-09-30。用户要求检查本项目各 Mod 的兼容声明，验证并维护到群星最新正式版本。

后续用户已授权将有更新的三个包逐个发布到 Steam；正式版本晋升与远端结果见 [逐包发布记录](steam-compatibility-releases-2026-09-30.md)。下文保留此次兼容调查的候选版本与原始实机证据，不改写历史测试身份。

本轮已完成五包的最新正式版兼容检查。全部声明覆盖 `4.5.*`；三个旧声明包已建立新候选，灰风覆盖文件已重新对齐原版。五包工具静态检查与仓库 39 项测试通过；三个改动包完成下文限定的简体中文实机复测。Steam 远端版本不在本次维护操作中更新。

## 目标与范围

- 检查五个生产包：无限岗位、灰风美化、合成女王美化、合成女王替换·牢大、屎山代码。
- 官方 Steam 公告截至检查日最新正式版本为 Stellaris 4.5.1「Cygnus」（358e），2026-09-24 发布；本机 `launcher-settings.json` 同样为该版本。来源：[官方公告](https://store.steampowered.com/news/posts/?appids=281990)。正式版和测试分支分开判断。
- 无限岗位、灰风美化、合成女王美化声明 `4.4.*`，需要更新；牢大替换及屎山代码已声明 `4.5.*`，仍核对当前生产包。
- 用户原有未跟踪文件 `console_history.txt` 不纳入任务提交。
- 本机无 D 盘，使用已存在的 `C:\workspace\open_kaishek` 工具副本；这一路径替代已在既有验收文档记录。

## 设计方案

1. 先使用 open_kaishek 当前 4.5.1 整包验收入口检查生产包，阅读工具能力边界；如发现缺陷，先在工具仓库文档、修复、验证、提交并推送，再继续 Mod 验收。
2. 对覆盖原版整文件的灰风包逐项核对当前安装原版与最小视觉补丁；检查无限岗位依赖的决议、地块、岗位 modifier、殖民载体和人口机制；合成女王两包核对十个肖像键、编码与资源路径。必要时维护脚本。
3. 为改动的三个包使用新的 PATCH 预发布候选版本，更新 VERSION、descriptor、当前合同、验收夹具及 changelog；保留历史报告和已发布版本的测试证据。
4. 只使用简体中文隔离 userdir 做 4.5.1 实机回归。4.4 旧档不得作为 4.5 新版验收种子，按官方人口组变更说明创建当前版本新档。非中文翻译仅静态校验。
5. 更新当前兼容说明与验收报告；本任务是仓库维护，不操作 Steam 发布，也不复用已发布版本号。

## 验收标准

- 五个生产包的兼容声明均覆盖当前正式版；Mod VERSION 与 descriptor 完全一致。
- open_kaishek 整包检查通过，工具能力限制和结果可追溯；不能把 lossless 解析或静态通过写成完整运行时认证。
- 修改包的原版依赖、编码、资源引用及非中文本地化静态检查通过；适当的仓库测试通过。
- 修改脚本的核心行为在 4.5.1 简体中文实机中验证；保存、重载采用同版本新档。未覆盖的功能明确记录，既有全矩阵缺口不伪称补齐。
- 任务相关更改、调查结论与测试证据存入 docs，提交并推送当前跟踪分支。

## 调查与结果

- 首轮现有测试 39 项，37 项通过：灰风原版最小差异失败，说明 4.5.1 原版灰风事件确有改变；无限岗位既有树哈希漂移失败（合同 `294f…`，本次改动前实际 `2a61…`），新版冻结时必须记录真实树。
- open_kaishek 首轮三个旧声明包的全部 P 脚本均零解析诊断。工具因仅支持语言子目录而遗漏无限岗位平铺翻译，且误要求纯美术包提供本不存在的新文本；无限岗位 VERSION 位于综合仓库根也缺少显式入口。暂停 Mod 验收，先按工具库 `docs/stellaris-package-layout-compatibility-2026-09-30.md` 修复并验证这些目录合同问题。
- 工具修复及空白分隔行追加修复已分别提交并推送 `97b4ec8`、`68db949`；每次均通过全仓库离线静态验收，包级正反测试 9/9。工具同时拒绝旧 supported_version，仍不宣称未注册 opcode 的运行时语义认证。
- 灰风原版差异：`gray_goo_events.txt` 两处主星查询改回当前原版 `has_planet_flag`，销毁居住站前补回 `clear_consecration_effect`；Distant Stars 异常类别四处星体 flag 查询恢复当前原版。`gray_goo_effects.txt` 原版无新增差异。撤销视觉补丁后，三个覆盖文件都与本机 4.5.1 原版逐字相同，已有最小差异测试通过。
- 合成女王原版定义 SHA-256 为 `9a2ccd43d297112176092e62a9e488b63a8ca271915d028b84e14491724fee18`，与 4.4.6 历史基线相同。两个人物替换包的十键、问候声、UTF-8 无 BOM 和 DDS 引用保持有效。
- 新版本为无限岗位 `1.2.1-rc.1`、灰风 `1.0.2-rc.1`、合成女王 `0.1.1-rc.1`；牢大 `0.1.2` 与屎山代码 `0.1.3` 保持现有生产版本。
- 五包 open_kaishek 静态 PASS：无限岗位 4/4 P 文件、64 键/10 语言；灰风 8/8 P 文件、4 DDS；合成女王及牢大各 2/2 P 文件、1 DDS；屎山代码 19/19 P 文件、13 DDS、173 键/10 语言。无新增文本的三个美术包本地化检查明确为不适用。
- 现有仓库自动化测试 39/39 PASS；九种非中文语言静态校验通过，运行时不在范围内。
- 最新实机探索运行 `20260930T040528Z` 仅启用无限岗位且使用简中。当前桌面只有 1024×768，游戏初始化却选 1920×1080，画面透明、无法观察 UI；尝试物理 Alt+Enter 未恢复。开始仅在隔离 userdir 调整窗口模式和分辨率后重试。此探索不算运行时通过；缺失未启用 Workshop 描述符日志与该 Mod 无关。
- 显示排查进一步复现既有牢大验收报告中的 ImageGrab 旧桌面问题：改用 Steam 物理 F12 取得实际 GPU 帧后，确认 1024×768 窗口中已经显示 4.5.1 简中主菜单与更新提示，桌面截图不能作为失败或成功依据。后续使用本地临时薄包装复用现有 harness 的物理输入、进程、隔离 userdir 与 OCR，F12 截图按新文件生成时间复制归档；点击须将 GPU 客户区坐标经 `ClientToScreen` 转为桌面坐标。验收要求是实际 GPU 帧、存档和日志互相印证，不能用旧 ImageGrab 图冒充游戏画面。
