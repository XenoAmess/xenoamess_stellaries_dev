# 「屎山代码」按物种特质数量无限成长：补丁协同设计稿

日期：2026-10-04。状态：设计草案，未实施。依据为本轮用户明确提出「按照物种特质数量，给与增益。特质越多，增益越多，无限叠加」，以及[用户反馈与整体改版稿](shishan-code-origin-feedback-redesign-2026-10-04.md)。

## 1. 目标与选定机制

机制名建议为「补丁协同」：主体物种积累的不同模块彼此协作，每个有效特质额外提供 `+3%` 全国岗位产出。特质原有效果保留，协同从开局生效，清理后和局势复发时都继续生效，不依赖白绮存活。只有持有「屎山代码」起源的国家获得此项修正。

采用岗位产出加成，覆盖科研、凝聚力与普通岗位资源，直接回应报告中的科研、经济、传统和奖励偏弱问题。单一全国岗位产出修正沿用本 Mod「重构完成」的作用口径；不额外增加劳动力效率、岗位维护费或人口维护费，不放大非岗位生产、库存、资源转移及市场收入，也不额外提高舰船武器伤害和航速。

无限成长包含两个相连部分：

1. 有限奖励池未耗尽时，数量来自物种实际持有的合格特质；每多一个特质，协同收益继续线性增加。
2. 有限奖励池耗尽后，重复维护/优化仍提供「协同补丁」层数，每层相当于一个额外有效特质。层数集中记录，不为每层新增一个物种图标，也不假称原版有无限种不同特质。

选择线性增长而非每层乘 `1.03`，使每次完成的额外收益明确。没有人为层数上限、收益上限、递减系数或有限档位表；仍受研究投入、费用递增及局势风险约束。这里的「无限」指玩法不设硬上限，不承诺引擎有限数值精度可以表达数学无穷。

## 2. 特质数量怎么算

### 2.1 实体特质数 `U_s`

对主体物种谱系的每个实际人口模板 `s`，按不同实际特质键计数：

- 正面、负面、零点费用、飞升、事件及第三方 Mod 赋予的有效玩法特质均计数。原有负面效果继续存在；数量收益不代表负面特质自动变为正面。
- 「屎山代码」和「重构完成」各计一个。二者是同一状态位的互斥替换，清理/复发时数量保持不变；若异常同时存在，只计一个并记录异常。
- 已验证的机械兼容映射计一个；如果同一映射与对应原版键意外同时存在，已知等价对只计一个。其它特质不按显示名称合并，避免不同 Mod 同名但不同效果被误判。
- 专门承载协同的图标、临时调试或恢复用标记、无玩法效果的身份标记及宜居偏好标记不计数。不要仅按 `cost=0` 排除：那会错误排除维护赠送特质。
- 原四类迭代特质作为重复成长的存储载体，通过第 3 节的真实层数计数，不再把图标另算一个实体特质。
- 领袖特质不参与物种数量。显示了几个图标、特质点总费用、可选栏位上限和已经完成多少次维护，都不能直接代替 `U_s`。

排除项必须是有理由的内部类别或明确键清单。未知的第三方玩法特质默认按一个计入；不要只枚举当前 39 个奖励候选，否则开局自选、飞升和其他 Mod 的真实特质会漏算。计数结果、排除规则应在 UI 中可解释。

负面特质也计数是有意设计：复杂的补丁结构可以产生协同，同时玩家仍承担原本缺陷。若某个原版负面特质的损失小于新增协同收益，这是新玩法允许的取舍。需要观察开局堆负面的路线，但不在实装中偷偷改成只计正面特质。

### 2.2 混合模板：按实际人口加权

推荐按主体物种谱系在本国实际存在的人口加权，而非直接读取一个没有人口的主模板，或把全部模板特质相加。

```text
P_s = 本国属于模板 s 的实际人口数量，所有模板使用同一人口口径
U = Σ(P_s × U_s) / ΣP_s
T = U + R
补丁协同岗位产出修正 B = 0.03 × T
```

`R` 为国家保存的共同重复成长层数，定义见第 3 节。若本国没有任何主体物种谱系人口，`T=0`、协同不生效；保留历史 `R`，等谱系人口重新存在时再恢复。

只有本国主体物种及其有效后继谱系人口参与加权。外国同物种人口、无人口模板、未完成殖民的人口占位和待应用改造模板不参与；外来物种不参与计数。收益作用于本国所有岗位，外来物种岗位可受益，这与现有重构完成全国岗位修正一致，是选定的作用范围。

这里选择全国共享协同，允许主体物种开发出的优化帮助整个国家；不是承诺每个外来物种都按自己的特质数分别计算。不能同时发放全国修正和同幅度主体物种修正。

例如，800 人口采用 10 特质模板，200 人口采用 5 特质模板，且 `R=0`：`U=9`，全国岗位产出 `+27%`。把后 200 人口也改为 10 特质模板后才变成 `+30%`。另建十个没有人口的模板，收益仍为 `+27%`。

增加特质的收益随实际覆盖人口比例生效：给只占谱系人口 `20%` 的模板加一个特质，全国增加 `0.6` 个百分点；给全部谱系人口加一个特质则增加 `3` 个百分点。相同人口配置下，增加任意实际模板特质不会降低收益；改变人口占比可能改变平均值，这是实际改造覆盖面的反馈，不是收益递减。

就业、空岗、岗位效率和劳动力加成不改变人口权重。必须从实际人口读取 `P_s`，不能用岗位数量或有效劳动力权重让产出加成反过来提高自己的计数。

## 3. 奖励池耗尽后如何真正继续增长

### 3.1 新存档

初始 `R=0`。维护与持续优化继续按有限的机械池、兼容池顺序提供特质选择；在有合格候选时，不因为玩家不喜欢选项提前改发重复层数。

普通特质在本国有实际人口、且能合法接受该特质的主体谱系模板中发放；已有或相互冲突的模板不重复添加、不强行替换。候选至少要能覆盖一个实际模板。成功后根据真实覆盖人口重算 `U`，由实际增加的数量获得收益；不把一次普通项目固定换算成 `R+1`。具体发奖与候选状态见整体改版稿第 4 节。

有限候选全部耗尽后，每次成功结算直接令 `R` 增加 1。统一的「协同补丁」图标用于展示层数，本身不另计实体特质。未来每次重复成长都确定性地增加全国岗位产出 `3` 个百分点，项目费用和局势风险继续按已有合同运行。

新版本停止继续抽取旧四类随机 `1%` 迭代，替换为固定增加一个协同层数。避免玩家在已经抽完实体特质之后，仍为住房或某类岗位的微小随机变化付出大量科研。此项是对旧奖励层的明确改版建议，必须在实施版更新日志里说明。

### 3.2 从现有 `0.1.3` 迁移

旧存档已有四类国家变量：`shishan_code_iteration_output`、`shishan_code_iteration_energy`、`shishan_code_iteration_assembly`、`shishan_code_iteration_experience`。

第一次迁移时，把四个合法非负整数计数之和作为历史 `R`，新版本追加层数从此继续累加；每一旧层对应一个有效特质层，不再重复统计四个载体图标。原有四类迭代效果和特质保留，不追溯删除玩家已有收益；新版本不再增加这些旧计数。不能用历史完成次数 `n` 填充 `R`，否则已奖励的实体特质会再次被计成虚拟层数。

迁移必须保存版本标记且只执行一次。变量缺失按 0 处理；负数、非整数、计数与特质载体不一致的异常存档应记录具体问题并做有据可查的修复，不静默重抽奖励或把 `n` 全额补偿为层数。原有实体特质仍由当前实际模板计算 `U_s`。

现有奖励池耗尽证据中四项计数为 `7/5/11/4`，历史 `R=27`；这只是迁移层数示例，原生存档实际模板的 `U_s` 要重新按本设计排除载体和标记后计算，不能把原报告的 43 个特质直接再加 27。

迁移不假称修改旧存档的开局特质点已经消除了此前选入的负面特质。首版改造预算放宽后，玩家仍按实际模板修改规则移除或保留它们。

## 4. 数值与叠加合同

建议每个有效特质 `3%`，同层等权，普通层与重复层使用同一个系数。

| 有效特质数 `T` | 协同岗位产出 `B` |
| ---: | ---: |
| 1 | `+3%` |
| 5 | `+15%` |
| 10 | `+30%` |
| 20 | `+60%` |
| 40 | `+120%` |
| 100 | `+300%` |
| 1000 | `+3000%` |

选择 3% 是本轮设计建议，目的在于让几十种特质产生明显的中后期收益，而非再加入一项难以感知的 1% 随机奖励。只提供岗位产出一条主增长通道，避免同时叠加科研速度、组装和战斗等多条无限倍率。

本机制贡献的是岗位产出修正值，不是对最终月度净收益再乘一次。仅考虑本 Mod、忽略原特质自身的效率效果及其它修正时，岗位产出说明式为：

```text
岗位产出 = 基础岗位产出 × (1 + 阶段生产修正 + 重构产出修正 + 0.03T)
```

实装时必须确认引擎不同经济类别的继承与同一来源的修正组合确实符合此合同，不能仅凭两个 modifier 名称推断一定加算。

- 新版 I 阶段、`T=10`、未重构：说明式中 `100 → 155`。
- 已重构、没有局势、`T=20`：`100 → 185`。
- 新版 V 阶段、`T=10`：`100 → 92.5`；岗位维护费另按 `+37.5%` 计算。不能因为产出接近基准就宣布经济已经恢复。
- 同等条件下新增一层重复成长，基准岗位产出 100 时，本机制额外贡献 3，且没有由协同引入的维护费变化。

这几项只是修正合同的隔离计算，不预测玩家存档里的最终值。特质自身效应、帝国规模和科研速度分别结算。非岗位产出不吃协同；第三阶段减半后某条纯空间站收入只受该阶段一次 `-12.5%`。

删除一个被计数的实体特质后，应撤销对应数量收益；再次添加仅恢复当前数量，不积累历史层数。已有 `R` 是成功项目奖励，不因清理、复发、死亡、改造、改名或读取存档而增加或清零。

## 5. UI 与玩家理解

推荐在起源简介、局势说明、重构后保留的管理入口和奖励结果中展示协同，不强求玩家从控制台变量判断收益。保留原名称的兼容特质也应显示该数量规则。

单一模板示例：

> 补丁协同：实体特质 12，额外协同层数 8，有效特质数 20。全国岗位产出 +60%。每新增一个覆盖全部主体物种人口的特质，或完成一次奖励池耗尽后的优化，再增加 3 个百分点；没有收益上限。

混合模板示例：

> 主体物种平均实体特质 9.0，协同补丁 4 层，有效特质数 13.0。全国岗位产出 +39%。部分模板新增特质按其实际人口覆盖比例生效。

可查看人口模板的数量与占比、计入/排除的特质，以及重复层数来源。显示值可以四舍五入，内部计算不提前向下取整；不得用 K/M 等简写隐藏增长变化。数量修正、原特质效果和局势阶段需可分别辨认。

收集成长在清理后继续展示。领袖死亡时只暂停她自己的科研效果，协同面板和增益保持；局势复发也不清空玩家已收集特质和重复层数。

## 6. 状态、刷新与性能

只存在一个按当前 `T` 计算的协同修正。刷新逻辑赋予当前正确值，不通过每个月再添加一个永久修正累积收益。

开局、首次迁移、奖励选择/重复层结算、清理、复发及本 Mod 引起的模板修改后刷新；外部改造、移民、组装、人口移除等变化在可用回调处刷新，并以月脉冲兜底。载入存档后立即或至迟下一个月脉冲恢复正确值，不能再发奖励。

遍历本国实际人口并按主体谱系模板汇总，每月最多进行一次全量对账；其它结算可按已知变更刷新。不要逐日扫描银河、所有无人口模板或所有国家。若引擎不支持高效的模板汇总，先做性能探针再决定缓存，不牺牲真实人口口径换成最大特质模板。

奖励票据、候选选择、`n` 增加和 `R` 增加使用各自有凭证且仅一次的结算。待选择时，不得因为月度项目修复逻辑重抽、补发或使一次研究同时得到实体特质和虚拟层数。旧迭代层转换采用迁移标记，不能每月再次求和追加。

多人/AI 的候选选择和自动处理也必须消费同一票据。AI 可从已生成的合格候选中按经济适用性选一项；不额外抽签、不免费获得全选项。用户玩家正常查看和选择不设置强制超时。

实施前首先做这些探针，并回写实际结果：

1. 分别比较原始 `num_traits`、存档 trait 列表和 UI，确定偏好、底盘、零点费、状态与隐藏特质的计数差异；验证可读出的真实数量，补齐明确排除与等价去重。不能臆造 `every_trait` 语法。
2. 找到模板谱系识别和实际人口数量的可用渠道，覆盖个体机械、机械智能、子模板、外来物种、虚拟人口与飞升替换；确认未应用模板不进入权重。
3. 验证全国动态岗位产出修正接受分数 `T` 和大数值，普通资源、科研、凝聚力及 DLC 岗位都只多一份产出；岗位和人口维护费不变。不能改用已知会同时增加维护的效率修正冒充完成。
4. 验证同一岗位在阶段 I/III/V、重构、协同不同值下的真实组合；若引擎经济类别造成乘算，先在设计中明确等价实现，再施工，不默默更改计算合同。
5. 验证候选持久保存、多选一 UI、待选状态与项目恢复的关系；先确认该版本脚本表达能力，再选具体事件结构。
6. 验证旧四类迭代冻结和迁移的精确行为。已有能量维护/住房减免的极大旧层数可能受引擎下限影响，保留效果不等于它们也能数学无限降低消耗；新的无限主收益始终是产出。

推荐实现路径是原生数量读取、模板人口汇总、变量和一个动态全国岗位产出修正。具体脚本表达式留待探针确认；本稿不把 CK3 方言或未验证的触发器当作 Stellaris 已可用语法。本轮未发现或宣称新的 Paradox 共通规则，因此没有 CK3 知识库同步改动。

## 9. 本轮文档验收与待实施边界
