## 1. 目标、范围与交付

新建独立起源 Mod，内部前缀 `shishan_code`，目录名 `shishan_code_origin/mod`。玩家选择机械主体物种的帝国后，依次经历早期红利、代码崩坏、维护与重构，并通过短事件链获得白绮。设计覆盖起源、物种特质、局势、特殊项目、建筑与岗位、领袖、剧情、本地化、UI 和验收。原设计轮次不含 Workshop 发布；2026-09-29 用户追加发布指令，发布范围和结果见[独立发布记录](shishan-code-origin-release-0.1.0-2026-09-29.md)。

原有「无限岗位」Mod 的目录、版本、描述符和 Workshop 物品均不属于这个新 Mod。新 Mod 日后单独持有版本源、描述符、更新日志和发布身份。

### 1.1 世界观与玩家可见简介

起源名：**屎山代码**。起源卡底部显示「**警告：具有挑战性的起源**」。建议简介：

> 我们曾是创造者造来服侍他们的机器。仓促写成的底层代码低效而危险；每个新问题都被补丁盖住，直到无人再能看清它的全貌。许多年前，创造者消失了。我们独自维持这座摇摇欲坠的大厦，终于在一次又一次修复之后，勉强走到太空时代的黎明。

此段是按用户设定整理的文案草稿；英文及其他语言在实现时翻译。不要把创造者失踪的原因解释为白绮杀害或背叛，以免与既有设定冲突；事件链保留悬念。

## 2. 帝国建立与起始状态

1. 起源可选条件：主体物种为机械类；机械智能格式塔和非格式塔个体机械帝国均可选。实际脚本须针对当前游戏版本分别验证 `MACHINE`、`ROBOT` 等原版物种类别和帝国创建器的可见性；不能只用「是否机械智能政体」代替物种检查。
2. 起始主体物种只拥有一个专属「屎山代码」特质。它占用 `6` 个可用特质点；该物种可选特质上限另增加 `3`。这两个效果均需覆盖帝国创建、开局与后续物种改造，且只作用于本起源主体物种/其模板谱系，不意外赠予所有附属机械物种。
3. 起始国家建立唯一「大厦将倾」局势，初始进度 `0`、累计维护次数 `n=0`、状态为 `ACTIVE`。同一国家同时最多有一个该局势。
4. 起源只提供本设计列出的特殊规则；不默认改变母星、初始舰队、行星资源、传统或科技。兼容性以实际原版起源可选条件矩阵验证。

## 3. 「大厦将倾」局势

### 3.1 五阶段

区间按左闭右开解释，恰好到达边界时进入后一阶段：

| 阶段 | 进度 | 岗位来源产出 | 舰船武器伤害 | 非岗位来源月度产出 | 岗位维护费 | 亚光速航速 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| I「危险的红利」 | `[0,250)` | `+25%` | `+25%` | `+25%` | `-25%` | `+25%` |
| II「脆弱的平衡」 | `[250,500)` | `0` | `0` | `0` | `0` | `0` |
| III「错误蔓延」 | `[500,750)` | `-25%` | `-25%` | `-25%` | `+25%` | `-25%` |
| IV「连锁故障」 | `[750,950)` | `-50%` | `-50%` | `-50%` | `+50%` | `-50%` |
| V「大厦将倾」 | `≥950` | `-75%` | `-75%` | `-75%` | `+75%` | `-75%` |

「岗位效率」按所有岗位产出理解。为解释来源，记 `P_job` 为已分配岗位劳动力产生的资源，`P_nonjob` 为不经岗位产生的持续月度资源，例如空间站采集与研究、巨构建筑、帝国固定月产出。两类是**核算口径**，不是要求实现两组独立修正。因为两类在每阶段的目标百分比完全相同，当前 Mod 对每种资源只施加一次全国生产修正，使任意一笔合格持续产出至多获得一次本起源阶段倍率。在不计其他修正及维护费时，目标结果是 `阶段后总产出 = (1 + 阶段百分比) × P_job + (1 + 阶段百分比) × P_nonjob`。例如 I 阶段岗位基础产出 `100` 与非岗位基础产出 `40` 分别变成 `125` 与 `50`，合计 `175`。

资源种类目标仍包含基础经济资源、战略资源、影响力、凝聚力、三类科研点及已启用 DLC 提供的月度资源。「月度产出」指持续生成的资源；按用户确认，附庸上缴、贸易协定和每月市场交易均不纳入上述合格生产。维护费、库存上限或一次性奖励也不当成被放大的产出，且不对扣除支出后的账面净额直接乘百分比。各资源的原版来源与修正继承链必须逐项审计，研究点在 UI 中可能有科研速度与产出两种口径，测试需区分。原版 `common/relics/relics.txt` 还使用过 `planet_jobs_produces_mult`、`station_gatherers_produces_mult` 和 `station_researchers_produces_mult` 等来源键；这些键**没有与本起源的全国生产修正叠加使用**。若实机发现全国生产键遗漏了合格来源或放大了应排除的转移收入，必须另设计经过来源测试的等价方案。

当前开发候选版利用两个来源在每阶段的百分比完全相同这一事实：每种资源只设置一次 `country_*_produces_mult`，没有另加 `planet_jobs_produces_mult` 或空间站阶段修正。若该单一生产键覆盖岗位与非岗位持续生产、且不覆盖资源转移，计算上与上式等价，并消除了本 Mod 自身两项加成相加或相乘的可能。原版脚本出现该键只能证明它存在，不能证明其精确来源范围；此实现仍是待验收方案，RS-01—RS-04 必须用纯岗位、纯非岗位和混合来源实测，任何漏覆盖或转移收入误放大都要先修复。

2026-09-27 资源覆盖复核：4.5.1 原版 `common/strategic_resources/00_strategic_resources.txt` 定义了 `sr_living_metal`、`sr_dark_matter`、`nanites`、`minor_artifacts`，且游戏生成的 `logs/script_documentation/modifiers.log` 明列四个对应的 `country_*_produces_mult`。它们是可持续生产的稀有资源，此前候选版漏列；四个有数值的阶段都须补上与同阶段其他资源一致的百分比。静态键存在不证明采集站、岗位和固定收入都实际受影响，仍按 RS-02 实测。原版同表还列出贸易价值、仅特定政体可见的生物质以及危机专属计量资源；这些特殊资源的生产和转换边界尚须核对，不能把普通月度资源覆盖结论外推到它们，也不能靠同时给贸易价值和转换后的能量加成造成重复增益。

2026-09-28 贸易资源复核：4.5.1 的 `trade` 已是 `common/strategic_resources/00_strategic_resources.txt` 中的可交易月度资源，原版修正目录提供 `country_trade_produces_mult`，十种官方语言也都已有 `mod_country_trade_produces_mult` 显示词条。实机存档的经济明细将岗位贸易生产记在 `planet_traders`、`planet_maintenance_drones`，将玩家设置的每月出售矿物所获贸易另记在 `trade_income.monthly_trades`；后者不是岗位生产。原版 `common/economic_categories/00_common_categories.txt` 中 `monthly_trades` 无 `country` 父类，而贸易岗位与贸易路线从 `country` 类别继承。为覆盖持续生产的贸易资源，四个有效阶段各加一次 `country_trade_produces_mult`，幅度与同阶段资源一致；不得另加贸易价值或市场交易专用修正。验收须对照同一贸易岗位/路线在第二阶段和有效阶段的生产数值，并比较市场交易条目是否保持独立；若实测交易收入被放大，必须改为来源限定实现。

四个新使用的修正键在 4.5.1 原版英文词条中没有对应的 `mod_country_*_produces_mult` 显示文本。Mod 须为十种官方语言补齐显示词条；资源名称使用原版 `$资源键$` 引用，简体中文源句中的“月度”由 MiniMax 翻译到其余九种语言，再做静态键与占位审计。

原版 `common/economic_categories/00_common_categories.txt` 把 `planets`、`stations`、`megastructures`、`country_base` 接在 `country` 类别下，岗位、采集/研究站因继承链处于其中；`monthly_trades`、`subject_tax`、`trade_policy` 则没有 `country` 父类。该类别结构给“生产键覆盖普通持续产出、每月市场交易和附庸税不继承”的静态证据，但引擎对收入的实际结算仍要实测；贸易协定的贸易值路径也未由此完全确认。不能据此单独给 RS-01—RS-04 判通过。

这五类加成作为同阶段修正同时生效；阶段转换需移走前一阶段效果，仅保留当前阶段效果。阶段 V 应一直保持到维护归零或清理成功，不因进度条到端点自动结束。原版局势文档说明可使用 `permanent = yes` 保持局势，但终点具体数值与 UI 钳制仍需实机确认；建议可见进度上限 `1000`，达到后固定停在末段。

### 3.2 月度进度与岗位

定义 `n` 为该帝国已成功完成「维护屎山」及「持续优化」的总次数；定义 `J` 为全帝国「屎山维护员」岗位面板当前**已分配的劳动力**总量，空缺岗位容量不计。局势存在时：

```text
月度进度 = max(0.2, 5 + n - 0.1 × floor(J / 100))
```

计算实例：`n=0,J=0` 时 `+5.0/月`；`n=0,J=100` 时 `+4.9/月`；`n=1,J=100` 时 `+5.9/月`；再多劳动力也不能低于 `+0.2/月`。`J` 跨所有所属殖民地汇总；科研所建成但无人上岗时没有减速。当前 Stellaris 岗位面板区分已分配劳动力与岗位最大容量；实施前还需验证当前版本 `num_assigned_jobs` 返回的单位与面板一致，不得把 `100` 空缺容量算进 `J`。

维护完成时先记录本次成功，再使 `n ← n+1`，把局势进度设为 `0`，下一次月度结算开始用新速度。`n` 永久保存在帝国状态中，重载或局势复发后仍保留；局势终结期间没有月度进度。复发时从 `0` 重新进入 I 阶段，并按保存的 `n` 继续计算速度。若日后希望复发清零 `n`，需另行调整需求。

## 4. 社会学特殊项目与状态机

所有研究成本的单位都是**社会学研究点**，不是一次性扣除科研库存。`n` 取开始该次项目时的已完成次数，项目成功后再递增。项目在国家范围内出现，同一时刻不得出现两个可同时完成并重复结算的同类实例；取消或失败不增加 `n`、不重置局势，也不发放特质。成功与存档重载须保持幂等。

| 状态 | 玩家显示名称 | 本次研究成本 | 完成效果 |
| --- | --- | ---: | --- |
| `ACTIVE` | 维护屎山 | `M(n)=2000+1000n` | `n+1`；进度归零；刷新月速和清理成本；按三层奖励池给主体物种正面效果；播放白绮维护台词。 |
| `ACTIVE` | 清理屎山 | `C(n)=8000+2000n` | 结束局势；移除「屎山代码」；添加「重构完成」；解锁持续优化；播放白绮清理台词。 |
| `REFACTORED` | 持续优化 | `O(n)=2×(2000+1000n)` | `n+1`；按同一三层奖励池发放正面效果；每次独立掷 `10%` 复发概率，触发则回到 `ACTIVE`；平常使用维护台词，复发使用专属台词。 |

`REFACTORED` 无局势；`ACTIVE` 有局势。清理后的「重构完成」对应全国所有物种岗位产出 `+25%`，不会无限叠加，也不增加岗位维护费。持续优化引发复发时，**移除「重构完成」、重新附加「屎山代码」**，再从 `0` 启动局势与「维护屎山」「清理屎山」项目；费用继续采用当前 `n`。再次清理时重复相反的特质切换。已通过维护获得的其他正面特质和「优化迭代」增益保留。

2026-09-28 实机修订：同日对照发现 4.5.1 的物种 `pop_bonus_workforce_mult=0.25` 同时增加岗位产出与按劳动力计算的岗位维护费。用户明确选择改为**全帝国所有物种的岗位产出 +25%，岗位维护费不变**。因此「重构完成」特质承担状态和界面呈现；清理回调另向国家添加唯一、永久的 `planet_jobs_produces_mult=0.25` 修正，复发回调移除。该修正不得与局势阶段修正并存；反复清理不得叠加；存档重载须保持；非岗位来源、人口维持费与岗位维护费不得受该修正影响。此段取代上一段“主体物种岗位产出”的适用范围。简中和其余九种官方语言的特质描述及修正名称须同步更新，其余语言调用 MiniMax 翻译并做静态校验。验收以同日清理前后岗位 UI 的产出/维护费和存档非岗位来源为准。

2026-09-28 复活经验边界补充：引擎文档只提供受经验获取倍率影响的领袖 `add_experience`，没有直接设置当前经验的领袖效果。复活脚本先用 `add_experience=1` 测出新领袖的有效倍率，再反算所需投入；当有效倍率恰为零而死亡前当前等级经验仍非零时，必须临时给予新领袖一个正经验获取特质，通过绑定该领袖的三个按日隐藏事件重新探测倍率、补齐经验并清除临时特质。校准期间如再次死亡，优先保存原目标经验，不把临时特质写进备份。正常倍率路径、等级、其他特质和 `500/200` 成本不得改变。使用隔离测试夹具把白绮的经验获取压到零、保留非零当前经验，实际死亡、复活、恢复期间再次死亡与重载后核对数值及临时特质清理。

2026-09-28 首轮实机事实：测试特质给予领袖经验获取 `-1000%`，临时恢复特质给予 `+1000%`，两者相抵后，单独执行 `add_experience=1` 仍没有增加当前经验；付费复活虽然准确扣费、保留等级及原有特质，当前等级经验却从 `317.52` 变为 `0`。这说明 `+1000%` 不足以突破零倍率。下一轮把只在复活计算期间使用的正修正提高到 `+10000%`，仍用一次实际经验探针测得有效倍率并反算投入；若探针依然为零，再调查可用的直接经验恢复效果，不以未通过的结果充当验收证据。

2026-09-28 第二轮实机事实：临时特质提高至 `+10000%` 后，单独给带有 `-1000%` 测试特质的白绮添加临时特质并执行 `add_experience=1`，当前经验仍为 `0`；实际付费复活路径亦仍为 `0`。引擎生成的效果文档只有 `add_experience` 和等级设置，没有直接设置当前经验的效果，但提供 `exile_leader_as` 保存领袖、`set_leader` 复职。下一探针从非零经验的活领袖直接流放并复职，检查经验是否原样保留；若成功，再验证能否在真实死亡事件内流放原领袖并走同一付费复职入口。`+10000%` 临时特质方案不得作为最终实现保留，除非后续证据显示它确实恢复经验。

2026-09-28 活领袖探针：同一名白绮从 `317.52` 当前经验的存档出发，执行 `exile_leader_as` 后在同一国家用 `set_leader` 复职，领袖 ID、等级、特质和 `317.52` 经验均原样保留；复职后没有遗留待复活标记或流放备份。接下来把死亡回调改为直接流放原领袖，不再先克隆；付费复活改用 `set_leader`，并在隔离存档中再次核对真实死亡回调是否允许直接流放。只有该路径通过，才移除旧的经验反算及临时特质实现。

兼容先前候选版的已重构存档：在本起源国家的月度脉冲检查状态标记与全国修正是否一致，缺失时补上，复发状态仍残留时移除；正常游戏中清理/复发回调仍立即同步，不等待月度脉冲。以旧候选版的重构存档载入新版本并跨月、以及新版本清理后立即重载各测一次。

对玩家而言，维护项目在清理后改名为「持续优化」。实现上可使用两个互斥项目键、共用效果例程，确保局势前后 UI 中只出现相应名称；这比尝试运行中修改项目键可靠。成本必须在项目卡片上显示准确公式结果，后续完成时重新生成下一次可研究项目。原版特殊项目文档支持 `cost` 块和社会学研究部门，但尚未证明其成本块能直接读取无限增长的国家计数变量；实现前必须做最小脚本验证。如果该版本不能表达动态科研成本，需先制定等价实现并让 UI 与实际成本一致，不能用固定成本冒充公式。

2026-09-29 文案修订：持续优化未复发时使用独立的「持续优化完成」弹窗；白绮在场时只描述新代码的稳定运行，不在已经重构的状态继续说旧核心仍在呼吸。维护完成仍使用原维护对白池，优化复发仍使用复发对白池。三组入口各自只开一个弹窗。

### 4.1 三层正面奖励抽取

特质奖励按**不可回退的三层抽取顺序**执行：

1. 优先从当前版本原版的正面机械特质池抽取。候选必须为主体物种可用、效果为正、与已有特质不冲突、当前模板未持有。
2. 机械池没有候选后，只从原版**对机械物种确实生效的非机械正面特质**中抽取。逐项核对原有效果：若原键仅因物种类别限制而不能赋予机械模板，可制作保持原效果的机械兼容映射；有机繁殖等对机械人口无效的效果不入池。每个候选入池前都须验证机械主体物种获得实际数值收益，不能只在 UI 上多一个失效特质。
3. 前两层均没有候选后，才进入下述「优化迭代」随机小幅增益池。

每层先构建合格集合，再等概率抽取；抽中后必须能在主体物种和其受控人口的实际模板上观察到，不能只变更无人口使用的虚拟模板。各层遇到已持有或互斥特质时跳过，不能把危机/叙事唯一特质或负面特质误入池。原版特质的 DLC 条件和版本变动需要逐个核对。事件赠予的特质不能因为帝国创建时的点数/特质槽已用完而静默失败；超过普通设计额度时须在物种模板上如实显示。

4.5.1 的 `common/traits/04_species_traits.txt` 核对表明，当前第二层列出的 19 个原版正面特质全部仅允许 `BIOLOGICAL LITHOID`，不允许 `MACHINE ROBOT`。因此第二层以 19 个脚本专用机械兼容映射交付：各映射保留原特质的名称、图标及数值修正，拥有自己的键、机械物种许可和互斥判定；不改变原版特质定义。维护奖励选择时检测映射键与对应原版键，避免原版特质经其他机制赋予后重复抽中。映射不能以同名图标代替数值生效证明，须分别验收代表性岗位、领袖、住房/维护费和陆战修正；在可用游戏环境恢复前标记为待实机验证。

前两层候选均耗尽后，每次从下列小幅增益中**等概率随机获得一种**；同类效果允许重复累计，四个计数器独立持久化，故不会再耗尽。下列百分比是本设计的建议数值，实施前可按实机平衡微调：

| 优化迭代结果 | 每抽中一次的主体物种增益 |
| --- | ---: |
| 计算路径精简 | 岗位产出 `+1%` |
| 供能调度优化 | 人口能量维护费 `-1%` |
| 空间调度优化 | 人口住房使用 `-1%` |
| 认知缓存拓展 | 科研岗位产出 `+1%` |

4.5.1 首次隔离加载确认原建议的「人口组装速度」与「领袖经验获得速度」修正键不能置于可按国家变量叠加的 `triggered_species_modifier` 类别中，故按上述两项同量级替换；新效果仍需实机检验。若某种效果不能作为主体物种修正准确生效，应替换为同量级、可静态和实机验证的物种正面效果，并回写本设计，不得偷偷转为全帝国增益。四类累计来源要在物种面板或项目结果中可追踪。随机选择与物种修改需记录到事件说明，避免玩家不知道获得了什么。

## 5. 「屎山维护研究所」与岗位

建筑从**游戏开局**解锁，只在此起源帝国的可殖民载体上可建；每颗星球**不限建造数量**，但仍受正常建筑槽位与合法载体限制。建议采用当前原版一级研究所的建造基线：`400` 矿物、`360` 天、每月 `2` 能量维护，并由每座研究所提供 `100` 维护员劳动力容量。这样每座满岗研究所恰好提供 `-0.1/月` 的局势减速；空岗无效。此为设计数值，实施时需与目标游戏版本原版值重新核对。建筑仅将**自身提供的**社会学科研岗位替换为同数量「屎山维护员」岗位，不修改该星球其他科研建筑。非格式塔机械帝国对接原版社会学专家岗位；机械智能格式塔对接其社会学计算岗位。两种政体都必须出现正确的自定义岗位与本地化。

维护员保留原对应岗位的资源消耗、职业阶层和除社会学外的正常产出，社会学研究**基础产出恰好少 `1`**；阶段、科技和帝国加成再按游戏常规作用于这个基础值。建筑自身不直接给月度局势减速；只有实际上岗的维护员进入 `J` 计算。若原版岗位单位按 workforce 表示，需把「少 `1`」映射为每个实际岗位等效的基础产出差额，并在岗位详情里验证。

## 6. 白绮：传奇领袖与剧情

### 6.1 获取与身份

开局短事件链建议 3 个节拍，全部由起源触发且每帝国只执行一次：

1. **遗失的维护日志**：游戏开始后短延迟弹出；发现创造者消失前留下的补丁记录和另一位维护者的签名。
2. **最后的值守者**：修复日志索引，找到继续运作的机械智能白绮；解释她将系统失控归咎于自己，但不替玩家规定创造者失踪原因。
3. **负疚者·白绮**：给予唯一可招募/自动加入的传奇行政官，总督定位；无资源门槛、无随机失败，避免核心角色因玩家错过事件而消失。她使用固定中文名及英文名 `Vivhite`，独立肖像/图标待美术方案确定。

领袖拥有不会因年龄死亡的专属不朽特质。事故、战斗、事件等非年龄死亡仍触发复活入口。她的全国效果以「存活且受雇」为条件，担任哪个星区总督、是否空闲均不影响全国效果。白绮禁止玩家主动解雇；实现时须验证当前版本是否有原版不可解雇领袖的配置或等价手段，并在领袖界面检查解雇操作不可用。她因事故、战斗或事件死亡时效果停止并按既定规则进入复活流程。唯一身份标记阻止刷出第二个白绮。

### 6.2 全国科研修正

当白绮符合生效条件时：

```text
工程学研究速度 = +10% + 5% × n
社会学研究速度 = -min(75%, 5% + 2.5% × n)
```

`n=0`：`+10% / -5%`；`n=1`：`+15% / -7.5%`；`n=28`：`+150% / -75%`；之后社会学仍固定 `-75%`，工程学继续增长。这里的「研究速度」是国家级科技研究速度，不等于每个岗位的研究点产出；局势的月度资源修正另外结算。完成清理不重置 `n`，因而不削弱她已经累积的能力；她因事故、战斗或事件死亡期间移除全国修正，复活并受雇后按保存的 `n` 恢复；仍受雇但没有任职的空闲状态不使效果失效。

### 6.3 复活与交谈入口

确认是白绮意外死亡时，显示一次复活事件，并保留一个无时间限制的「重启白绮」入口；玩家暂时缺少资源时，未来仍可支付 `500` 能量币和 `200` 合金恢复她的服务。复活后保留死亡前的等级、经验、所有已获特质及专属科研效果；临时星区任职位置是否恢复以岗位可用性为准，但若不能自动回到原岗位，须在事件中提示玩家重新任命。复活绝不重置 `n`，也不能重复收取成本或复制领袖。若真实死亡事件无法原样保留领袖对象，需先验证等价重建方案，不能以降低等级或清除特质代替。

玩家可通过国家决议或事件链入口「与白绮交谈」主动打开零成本对话。她存活且受雇时可重复访问，随机展示一条日常台词；不把对话藏在纯随机弹窗里。项目完成的台词在结算事件展示，既使玩家看到结果，也避免同一月出现多条重复弹窗。

## 9. 已知设计风险与实施前验证

1. `n` 每增加一次月速就 `+1`，而每 `100` 已分配维护员劳动力只抵消 `0.1`，即一次维护的额外速度需要 `1000` 已分配劳动力才完全抵消；这是原始数值的直接结果，需在 UI 讲清楚并在实机体验时观察难度。
2. 来源隔离是硬验收条件：岗位与非岗位月产出不能交叉覆盖。已知原版存在不同产出键，但尚未确认所有资源与收入来源均可用脚本独立限定；验收要测实际产出与月收支，不能只检查脚本文字。
3. 无限次数的成本递增、物种正面特质有限、原对象复活后的等级与特质保留均有实现风险，必须在正式编码前验证并记录等价方案。
4. 第二层非机械正面特质只纳入可验证有效的候选；具体白名单需按目标游戏版本审计。「优化迭代」四项 `1%` 数值是设计建议，实施前应复核平衡与修正键可用性。

## 11. 白绮原对象复职作用域（2026-09-28）

实机用真实死亡回调将原白绮流放并付费复职，存档确认领袖 ID `33554525`、等级 5、已有特质和当前经验 `317.52` 全部保留，且资源准确扣除 `500` 能量币与 `200` 合金。这解决了克隆加经验路径在经验增益为零时丢失当前经验的问题。

但 `set_leader` 直接在国家作用域执行会把复职者任命为**帝国统治者**；复职存档的 `ruler` 从 `452984860` 变成 `33554525`。这不符合白绮为传奇行政官的要求，也使连续死亡测试失真。原版 `origin_events_1.txt` 在首都星球上以 `assign_leader` 分配 `official`；下一步验证在首都星球上分配已流放的白绮能否恢复为受雇总督且保持原统治者，再检查第二次死亡、再次付费、重载与备份引用清理。未通过前不能将原对象复职视为完整修复。

首都星球直接 `assign_leader` 探针失败：白绮成为星球 `governor`，但仍留在 `saved_leaders`，也没有进入国家 `owned_leaders`，属于悬空分配。随后对一个无领袖舰队执行 `set_leader = <备份>`，白绮原 ID 和 `317.52` 经验进入 `owned_leaders`，`saved_leaders` 清空，统治者仍是 `452984860`；由于她是行政官，该舰队没有留下领袖指派。正式修复应通过可用的无领袖舰队复职；无此舰队时建立并销毁临时空舰队作为兜底。验收必须核对两种路径都不更换统治者、不遗留舰队或备份、可第二次死亡和复活。

临时**空**舰队的正式事件试验失败：付费选项关闭，但未扣费、领袖未回到 `owned_leaders`，说明空舰队在领袖复职前未成为有效承载对象。改为先选现有无领袖舰队复职；若需无舰队兜底，临时舰队必须包含一艘可用设计的临时舰船。付费和清理备份都必须以实际进入 `owned_leaders` 为条件。

2026-09-28 连续死亡否证：临时单舰复职后的存档确实保留原 ID、`317.52` 经验、原统治者及正确扣费；但再次对受雇白绮执行 `kill_leader`，包括先执行 `set_immortal = no`，均没有触发第二次死亡。复职对象存档的 `leader_flags` 从死亡前 `455` 变为 `487`，去掉不朽后仍为 `485`；多出的位可能表示死亡状态，此解释是推断。原版生成效果文档中的 `activate_saved_leader` 看似可直接归还保存领袖，但实测以 `@root` 和实际存档键 `shishan_code_vivhite_backup0` 调用，执行后 `owned_leaders` 不含白绮，`saved_leaders` 仍含原对象。原版 `localisation/99_README_SAVED_LEADERS.txt` 明确该效果作用于 `create_saved_leader` 创建的国家保存池，与 `exile_leader_as` 的流放机制不同。故流放原死亡对象复职不能作为正式实现；回退到可重复死亡的克隆方案。其当前经验在领袖经验获取被完全钳为零的极端情况下仍无法复原，此边界必须如实列为未通过，继续寻找可行的原生脚本解法，不能把保存 ID 的单次复职视为满足复活合同。

详细存档与分支证据见[连续死亡与零经验倍率探针](shishan-code-origin-vivhite-revival-probe-2026-09-28.md)。

2026-09-28 克隆复活复测还发现：连续两次真实死亡与付费复活均可触发，第二次从 `500/300` 准确扣到 `0/100`，存档 `owned_leaders` 只有一名新白绮；但已消费的流放备份仍以 `shishan_code_vivhite_backup0` 留在 `saved_leaders`，即使不再有待复活标记。原版生成效果文档提供国家作用域 `kill_exiled_leader = <key>/<key@scope>`，原版事件也用它删除未返还的流放对象。正式复活结算需先撤去备份的白绮身份标记，再以此专用效果移除流放条目，并 `clear_global_event_target` 清除全局指针；实机保存、重载后都应没有该键和已死亡旧白绮引用。此修复不得改变已确认的两次扣费与唯一受雇白绮。

备份清理已在新脚本的付费复活、存档和游戏内重载中通过。零经验倍率进一步探针确认：隔离副本给克隆白绮添加 `species_leader_exp_gain = 100` 临时领袖特质后，在下一条独立控制台命令中增加基础经验，确实可以得到经验；再单独移除临时特质，现有经验仍保留。但**同一条效果块**内添加特质、增加经验、移除特质，最终经验不增加。因此如果使用临时经验增益方案，必须拆成独立事件结算，并在存档重载、重复死亡、特质回收方面验收；不能将同一效果块内的临时特质当作已验证解法。

按日事件链的隔离试验已将零倍率克隆体从 `0` 恢复到 `317.51909`，死亡前为 `317.52`；末段自动移除临时特质和恢复变量，已消费备份亦无残留。正式实现需让三个后续事件绑定**本次复活领袖对象**，在领袖身上保存目标经验和测得倍率，避免国家级延迟事件错误引用下一次复活者；若恢复期间再次死亡，死亡回调应优先保存尚未恢复的目标经验，流放备份不得保留临时加速特质。正常经验倍率路径继续即时恢复。验收标准为零倍率、正常倍率、恢复中再次死亡与保存重载均保持等级、原有特质及当前经验，临时特质在完成后消失，最终经验与死亡前差异不超过存档浮点精度。
