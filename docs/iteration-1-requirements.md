# 迭代 1 需求文档

## 1. 文档信息

- 项目：无限岗位（Steam Workshop ID：`3710613857`）
- 迭代：Iteration 1
- 状态：需求基线（2026-09-06 范围修订）
- 需求来源：[Steam Workshop 页面及其 23 条评论](https://steamcommunity.com/sharedfiles/filedetails/?id=3710613857)
- 整理日期：2026-09-06

## 2. 迭代目标

本迭代聚焦评论区中反复出现或影响可用性的需求：适配方舟舰和游牧帝国殖民地、改善决议菜单、补充机仆岗位与英文文本。按人口动态扩展和数值再平衡已由用户明确决定不做。

## 3. 范围内需求

### I1-001 方舟舰与游牧帝国殖民地支持

- 优先级：P0
- 类型：兼容性 / 功能
- 来源：方舟舰无法展开菜单、希望方舟舰拥有更多岗位、希望支持新游牧帝国殖民地等多条留言。

需求说明：

1. 本 mod 应识别方舟舰以及新游牧帝国使用的殖民地类型。
2. 符合条件的方舟舰或游牧殖民地应能正常打开本 mod 的决议入口。
3. 玩家应能在这些殖民载体上使用适用的岗位扩展功能。
4. 现有普通殖民星球的功能不得因适配而退化。

验收标准：

- 方舟舰和游牧帝国殖民地上可以进入决议菜单，不出现入口缺失、无法展开或空菜单。
- 至少一轮完整测试证明决议可以执行，效果可以正确添加，岗位可以生成。
- 普通帝国、蜂巢帝国和机械帝国的既有行星决议仍可正常使用。
- 游戏日志中不出现由本功能引入的脚本错误。

待确认：

- 方舟舰应开放全部现有岗位决议，还是只开放适合其机制的子集。
- 方舟舰特有岗位与现有 13 类岗位之间的映射。

### I1-002 可折叠的决议菜单

- 优先级：P1
- 类型：界面 / 易用性
- 来源：决议列表占用空间过长以及“没有折叠”的多条留言。

需求说明：

1. 本 mod 的决议入口应支持展开和折叠，避免全部岗位决议长期占满行星决议列表。
2. 折叠状态不得改变决议的可用条件、成本、提示信息或实际效果。
3. 折叠机制应同时适用于普通殖民星球和本迭代新增支持的方舟舰/游牧殖民地。

验收标准：

- 默认状态下不会同时展示全部岗位决议。
- 玩家可以明确地展开和收起本 mod 的决议组。
- 展开后所有适用决议均可访问；收起后不会遗留重复入口。
- 重复展开、收起以及重新载入存档后，菜单状态不会导致决议永久丢失。

### I1-003 机仆活体陈设岗位决议

- 优先级：P1
- 类型：新增内容
- 来源：为失控机仆增加活体陈设岗位决议的留言。

需求说明：

1. 为失控机仆政体增加专门提供活体陈设岗位的决议或岗位扩展效果。
2. 非失控机仆政体不应看到或执行该专属决议。
3. 决议的重复执行规则应与本 mod 现有岗位扩展设计保持一致。

验收标准：

- 失控机仆可以看到并执行该决议。
- 执行后活体陈设岗位数量按设计值增加，并能被合格人口正常填充。
- 其他政体不会获得无效岗位或错误入口。
- 中文和英文界面均有完整名称、说明和效果文本。

待确认：岗位数量、矿物成本、执行时间和岗位效率修正。

### I1-004 英文本地化

- 优先级：P1
- 类型：本地化
- 来源：英语版本是否可用的留言；当前发布说明仅声明简体中文本地化。

需求说明：为现有功能和本迭代新增功能提供完整的 `l_english` 本地化。

验收标准：

- 英文环境下，所有决议、地块、菜单入口、说明和效果文本均显示可读英文。
- 不显示未解析的本地化键或简体中文占位文本。
- 简体中文本地化不退化。

## 4. 明确不实施的需求

以下需求保留评论来源和历史分析，但已由用户在 2026-09-06 明确决定不做；不进入设计、编码或验收，也不作为迭代 1 完成条件。

### I1-005 按人口动态扩展岗位

- 优先级：P2
- 类型：玩法扩展
- 来源：希望按人口规模生成岗位，并覆盖全部产业的留言；评论以“每 100 人口”为示例。
- 状态：不做（用户明确移出迭代 1）

需求说明：

1. 提供一种随行星人口规模扩展岗位供给的机制。
2. 岗位覆盖范围应包含主要基础产业、工业、科研、行政与安全类别，而不是单一产业。
3. 该机制不得造成无限刷新、负数岗位或人口变化后的重复叠加错误。

验收标准：

- 达到约定的人口阈值时，岗位数量按确定的公式变化。
- 人口增加、减少、迁移及存档重载后，岗位数量保持一致且可预测。
- 不同政体获得与自身相匹配的岗位类型。

历史待确认项（仅保留记录，不再推进）：

- 是否采用“每满 100 人口增加一组岗位”的固定阈值。
- 各产业的岗位比例、上限以及该机制与现有固定岗位决议的关系。

### I1-006 岗位数量、决议时间与效率再平衡

- 优先级：P2
- 类型：数值平衡
- 来源：增加岗位数量、缩短决议时间、降低岗位效率的组合建议；另有留言认为无限增加岗位的资源成本已经偏低。
- 状态：不做（用户明确移出迭代 1）

需求说明：

1. 评估并调整单次增加的岗位数量、决议执行时间和岗位效率加成。
2. 调整方向应允许“更多岗位、更快完成、较低效率”的玩法。
3. 对成本强度存在相反意见，不应在缺少测试数据时单方面继续降低成本。

验收标准：

- 实现前记录当前实际数值，并确认评论中的建议是否已被后续版本部分实现。
- 确定的目标数值集中定义，避免同类决议出现非预期差异。
- 数值测试覆盖早期、中期和后期行星，确认没有明显的资源溢出或不可用情况。

历史待确认项（仅保留记录，不再推进）：最终岗位数、低于当前 180 天的目标执行时间、效率加成及 1000 矿物成本是否调整。

## 5. 回归测试项

### I1-R01 蜂巢岗位可就业

历史留言曾报告版本更新后，蜂巢政体新增的科研岗位和行政岗位无法上人；作者随后回复已修复。本迭代不将其作为新功能，但必须纳入回归测试。

验收标准：蜂巢人口可以正常填充本 mod 提供的科研和行政类岗位，且岗位名称、类别与产出正确。

### I1-R02 决议菜单与第三方 UI mod

历史留言曾报告更新后菜单无法展开，报告者后来确认原因是其他 UI mod。因此该问题不作为本 mod 的已确认缺陷。

处理原则：

- 首先在不启用第三方 UI mod 的基线环境复测。
- 若仅在特定 UI mod 组合下出现，应记录冲突对象和复现条件，不应误判为本 mod 基础功能失败。

## 6. 不纳入本迭代的内容

- 评论区中的纯赞美、情绪表达和示例链接。
- 修复第三方 UI mod 自身的缺陷。
- 未形成具体行为或验收标准的泛化强度诉求。
- `I1-005` 按人口动态扩展岗位。
- `I1-006` 岗位数量、决议时间与效率再平衡。

## 7. 验收矩阵

至少覆盖以下组合：

- 政体：普通帝国、蜂巢帝国、机械帝国、失控机仆、游牧帝国。
- 载体：普通殖民星球、方舟舰/游牧殖民地。
- 语言：简体中文、英文。
- 场景：新游戏、既有存档、执行决议、重复执行、存档重载。

## 8. 工具与交付要求

1. P 语言 mod 的最终验收必须先通过 `D:\workspace\open_kaishek`。
2. 如果验收工具存在缺陷或缺少本迭代所需能力，应先修复、完善并验证该工具，将工具改动提交并推送到其远端，然后继续验收本 mod。
3. 静态验收通过后，还必须完成游戏内验收矩阵；静态工具不能替代运行时验证。
4. 实现完成后应同步更新本知识库、mod 描述和版本变更记录。

## 9. 完成定义

迭代 1 只有同时满足以下条件才可宣告完成：

- 所有 P0、P1 需求通过验收。
- `I1-005`、`I1-006` 已明确移出实施范围，不构成完成阻塞项。
- 两项历史问题通过回归测试。
- 简体中文与英文环境均无缺失文本。
- `open_kaishek` 验收通过，游戏内验收矩阵通过。
- 相关代码、文档和工具修复均已分别提交并推送到对应远端。
