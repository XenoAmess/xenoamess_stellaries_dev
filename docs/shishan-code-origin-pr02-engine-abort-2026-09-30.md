# PR-02 研究中项目被引擎中断（2026-09-30）

## 目标与范围

验收方案要求研究中断不会把「维护屎山」误算为成功。已有实机证据覆盖玩家在 UI 中取消、清理结算后旧项目自动清除、国家完成事件重复调用；本项单独验证 Stellaris 原生 `abort_special_project` 效果作用于正在研究的维护项目。普通科技改选不会抢占队首，不能把它当作中断。

## 方法与通过标准

从正式单 Mod 简中[双项目队列基线](../assets/shishan-code-origin/evidence/pr02-dual-projects-after35d-2229.10.15.sav)载入。基线中 `n=2`、局势进度 `14`，维护 ID 5 在社会学队首且已累计 `28.33912/4000` 研究点，清理 ID 6 排队。先保存同日副本，再在玩家国家作用域调用原版 `abort_special_project = { type = SHISHAN_CODE_MAINTAIN }`，同日保存中断后存档。检查维护项目和社会学队列状态，推进一天以上让取消事件及项目管理完成，再保存并正式单 Mod 重载。

中断本身必须不增加 `n`、不重置局势进度、不授予物种奖励、不改变白绮阶梯、不设置 `shishan_code_maintain_success_pending`。清理项目不能意外成功；维护应重新可用，或如原版引擎永久删除则由已有初始化事件重建。跨日局势自然进度单独计量。保留 Steam F12 截图、原生存档和 SHA-256，并以只读解析审计关键字段。正式 Mod `open_kaishek` 必须通过。此测试不把人工原版效果调用误称为自然随机中断。

## 第一轮实机结果与缺陷

2026-09-30 正式 `0.1.2` 单 Mod、简中、Steam 离线隔离局载入基线。控制台执行的原版语法为 `effect abort_special_project = { type = SHISHAN_CODE_MAINTAIN }`；控制台明确输出「特殊项目维护屎山已终止」。同日 `2229.10.15`、六日后 `2229.10.21`、跨月 `2229.11.12` 均保存为原生存档。只读解析表明维护 ID 5 从项目表和社会学队列移除，清理 ID 6 保持在队首；维护次数始终为 `2`，最后完成项目仍是旧的 `SHISHAN_CODE_OPTIMIZE`，主物种特质及白绮全国效果阶梯完全相同；局势进度同日 `14`、跨月自然增长到 `21`，没有误发奖励。

**发现可用性缺陷：** `2229.10.21` 和 `2229.11.12` 均没有重新生成维护项目。项目定义中的 `on_cancel` 会安排事件 `shishan_code.11` 供 UI 取消后恢复，但本次实测的原版 `abort_special_project` 路径没有触发该恢复；这是 Stellaris 4.5.1 此路径的实测语义，不能把 `on_cancel` 视为所有中断的统一回调。现有 `on_monthly_pulse_country` 事件 `shishan_code.60` 只维护重构后的全国修正，没有检查项目缺失。

修复方案：在既有月度事件 `shishan_code.60` 内，无项目成功结算待处理旗标时调用已存在的 `shishan_code.11`，沿用该事件以 `has_special_project` 做的幂等项目恢复。这样正常项目、玩家取消、引擎中断和重构后的持续优化都由同一条件判断恢复，最迟下一次月脉冲重新可用。已发布的 `0.1.2` 包保持不变；修复先作为尚未发布的 `0.1.3-rc.1` 预发布候选验收。验收需从上述缺陷存档在修复候选单 Mod 中重载，跨月确认维护重新出现且恰好一次，不影响清理队列、次数、局势或白绮；再次执行中断并复核，`open_kaishek` 必须通过。修复完成前 PR-02 此子项记为失败，整体验收不能宣称通过。

审计工具 `tools/shishan_code/audit_pr02_engine_abort.py` 将只读解析上述原生存档，逐份记录 SHA-256、日期、项目 ID/状态、社会学队列、维护次数、上次完成项目、局势进度、主物种特质、白绮及重构修正。断言首次中断不发奖励，正式版跨月仍缺项目（缺陷复现），候选版下一月恰好恢复一个维护项目、清理继续研究、后续月度不重复；再次中断后新 ID 恢复且其余状态不变。输出结构化 JSON 至证据目录；工具须对缺失或不一致的证据返回失败，不把首轮正式版的已知缺陷误报为候选通过。

## 候选版复测结果

2026-09-30 将正式版缺陷存档 `2229.11.12` 放入只启用 `0.1.3-rc.1` 的简中隔离目录，从游戏菜单加载并正常推进。`2229.12.04` 的原生存档显示维护 ID `7` 恢复为可研究且仅一个，清理 ID `6` 仍在社会学队首，已有 `56.67824` 研究点；UI 同时显示「清理屎山，研究中」和「维护屎山，可用」，维护费用保持 `4000` 社会学。之后自动保存的 `2230.01.01` 和手动保存的 `2230.03.28` 中，维护仍恰好为 ID `7`，没有每月重复创建，局势进度依次自然为 `28→35→49`。再次在暂停状态使用相同原版效果中断可用的维护 ID `7`，控制台再次输出「特殊项目维护屎山已终止」；推进至 `2230.04.11` 后项目恢复为唯一的 ID `8`，清理继续研究，局势为 `56`。

[结构化审计](../assets/shishan-code-origin/evidence/pr02-engine-abort-audit-2026-09-30.json)对八份原生存档的 9 项断言全部通过，包含首次正式版缺陷复现、候选版月度幂等、再次中断恢复以及没有误发奖励。原生存档、首次与再次控制台截图、[第一次恢复 UI](../assets/shishan-code-origin/evidence/pr02-engine-abort-recovered-ui-2229.12.04.jpg)、[再次恢复 UI](../assets/shishan-code-origin/evidence/pr02-engine-reabort-recovered-ui-2230.04.11.jpg)均已入库，审计 JSON 记录 SHA-256。候选版 `open_kaishek` 为 `PASS`：19/19 脚本、13 DDS、173 个本地化键；其他九种官方语言**静态校验通过，运行时不在范围内**。隔离游戏 `error.log` 只有启动时对其他已订阅但未下载创意工坊目录的警告，没有本 Mod 解析或运行错误。

**结论：PR-02 原版引擎中断子项在尚未发布的 `0.1.3-rc.1` 候选版通过；公开 `0.1.2` 仍有该已知缺陷。** 本结果不替代 PR-02 的其他组合场景或整体 Mod 验收。
