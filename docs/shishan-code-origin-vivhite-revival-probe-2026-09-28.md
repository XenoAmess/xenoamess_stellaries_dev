# 白绮复活的连续死亡与零经验倍率探针（2026-09-28）

本轮在仅启用本 Mod 的简体中文隔离局中，将白绮当前等级经验保留为 `317.52`，再用只存在于隔离副本的测试特质把领袖经验获取降低 `1000%`。先前的克隆复活路径可准确保留等级、已有特质并按 `500` 能量币、`200` 合金扣费；但此时 `add_experience` 即使加临时 `+10000%` 修正也不能把当前经验从零恢复到 `317.52`。正常经验倍率和原本当前经验为零的路径已有独立通过证据。

为试图保持精确当前经验，测试了在真实死亡回调中流放原领袖，再付费复职：

1. 国家作用域 `set_leader` 将白绮任命为帝国统治者，不能采用。
2. 首都星球 `assign_leader` 只留下总督引用，白绮没有进入国家 `owned_leaders`，不能采用。
3. 舰队作用域 `set_leader` 可使第一次复职保留原 ID、等级、特质和 `317.52` 经验，且原统治者不变；正式事件中用一艘临时船作为兜底也能正常扣费。然而该对象再次执行 `kill_leader`，包括先执行 `set_immortal = no`，均不触发第二次死亡。存档中其 `leader_flags` 相比死亡前多出一位；死亡状态是合理推断，但尚无引擎文档直接命名该位。故不能用首次成功复职代替重复死亡的验收。
4. 游戏自带效果 `activate_saved_leader` 分别使用 `shishan_code_vivhite_backup@root` 和实际保存键 `shishan_code_vivhite_backup0`，控制台执行后均未将白绮放入 `owned_leaders`，流放备份仍在 `saved_leaders`。原版 `localisation/99_README_SAVED_LEADERS.txt` 指出该效果针对 `create_saved_leader` 建立的国家保存池，并不适用于 `exile_leader_as`。

隔离探针存档保存在本机用户目录 `_1558924572` 下的 `vivhite_activate_saved_probe_22270303.sav` 与 `vivhite_activate_literal_confirmed_22270303.sav`，未加入发布包。正式 Mod 已撤回本轮原对象流放复职实现，回到能处理后续死亡的克隆路径。**当前经验非零、经验获取完全归零**的组合仍是 WH-03 未通过边界；不应将白绮复活整体标为通过。下一步优先验证是否存在不受经验获取倍率影响的原生脚本效果，或能否在不丢失已获特质的前提下临时移除零倍率来源。

## 克隆路径的第二次死亡与备份清理

将隔离游戏恢复到正式克隆脚本后，从同一带 `-1000%` 经验获取测试特质的白绮存档出发，连续两次执行真实 `kill_leader`，两次都出现「白绮的备份」，也都可以付费复活。为隔离准备一次性补入 `500` 合金后，第一笔费用把能量/合金从 `1000/500` 扣为 `500/300`，第二笔从 `500/300` 扣为 `0/100`。第二次存档的 `owned_leaders` 只有一个复活白绮 ID `67109010`，等级与测试特质保留；当前等级经验却仍为 `0`，与上一节的未通过边界一致。

第二次存档 `vivhite_clone_twice_zero_gain_22270303.sav` 发现 `saved_leaders` 仍保留已消费的 `shishan_code_vivhite_backup0=67109009`。原版生成效果文档说明 `kill_exiled_leader` 可按自定义键杀死流放领袖；在隔离局中手动执行 `kill_exiled_leader = shishan_code_vivhite_backup@root` 后，`vivhite_cleanup_effect_probe_22270303.sav` 的 `saved_leaders` 区块消失，`owned_leaders` 的白绮仍为 `67109010`，资源仍为 `0/100`。另有一个全局备份目标键尚须清理。正式脚本已改为先移除备份身份标记，再调用 `kill_exiled_leader` 和 `clear_global_event_target`；`open_kaishek` 对新脚本返回 `PASS`（19/19 脚本、13 DDS、165 本地化键）。

新脚本隔离实机复核：从 `vivhite_tempfleet_baseline_copy_22270303.sav` 出发，补入 `500` 合金，真实 `kill_leader` 触发「白绮的备份」，再支付 `500` 能量币与 `200` 合金。支付后库存 `1000/500→500/300`。`vivhite_cleanup_source_22270303.sav` 的 `saved_leaders` 区块不存在，`shishan_code_vivhite_backup0` 和 `shishan_code_vivhite_pending_reboot` 均出现零次，`owned_leaders` 只有一名新白绮。游戏内载入该存档，再存为 `vivhite_cleanup_reload_22270303.sav`，三项清理状态与受雇领袖仍相同。因此已消费备份和全局目标的清理通过保存、重载；零经验获取倍率下当前等级经验仍未恢复，不能据此将 WH-03 全项判通过。

下一步隔离探针：原版机械物种特质中存在 `species_leader_exp_gain = -1`，因此经验获取归零不是纯粹人为边界。尝试给克隆体临时赋予大幅正向 `species_leader_exp_gain` 领袖特质，恢复经验后立刻移除；目标是保留原有特质集合、等级和当前经验，且最终不留下临时特质。先仅在隔离 Mod 副本验证，证实有效后再修改正式 Mod、更新静态检查和回归连续死亡。

隔离副本的 `+10000%` 领袖经验获取临时特质已经验证有效，但必须跨独立效果结算。先给复活白绮添加特质，再用下一条控制台命令执行 `add_experience = 10`，存档经验从 `0` 变为 `912.6`；第三条命令移除临时特质后，存档经验仍为 `912.6`，临时特质已消失。相反，同一效果块内顺序执行添加、增加 `1` 点基础经验、移除特质，经验保持原值；在复活选项同一效果块内执行完整倍率探针，最终经验也为 `0`。这表明不能在一条效果链中完成整个恢复。现仅在隔离副本试验三个按日调度的隐藏事件：第一天在临时特质已生效后探测倍率，第二天按探测结果补齐当前经验，第三天移除临时特质；正式 Mod 尚未采用该方案。
## 按领袖作用域分日恢复的实机结果

隔离副本增加三个隐藏领袖事件：付费克隆时记录目标经验并添加临时经验获取特质；第一天探测实际倍率，第二天按倍率补足当前等级经验，第三天移除临时特质与变量。这样延迟事件随新白绮本人保存，不会误操作后续克隆体。`vivhite_xp_leader_mid_22270305.sav` 在第二天保留了 `317.51909` 经验和待清理标记；游戏内载入后推进至 `vivhite_xp_leader_reload_done_22270308.sav`，经验仍为 `317.51909`（原值 `317.52`，误差小于 `0.001`），临时特质、目标变量、已消费备份与待复活标记均为零。

再载入中间存档，在校准完成前通过真实 `kill_leader` 触发第二次死亡并再次支付 `500` 能量币、`200` 合金。`vivhite_xp_repeat_during_restore_22270311.sav` 仅有一名受雇白绮（新 ID `50331741`），仍为 5 级、经验 `317.51909`，保留原有特质，临时校准特质、变量与备份全部清除。正式实现应采用同样的领袖事件链，并为临时特质提供全部官方语言本地化；合入后还须对正式副本重复工具与实机验收。

正式脚本已采用该领袖事件链，临时特质更名为 `leader_trait_shishan_xp_restore_boost`。中文新增两个本地化键；其余九种官方语言均由 MiniMax 候选翻译审校后写入，候选 JSON 保存在本机 `_runtime/shishan_code/`。`open_kaishek` 返回 `PASS`（19/19 脚本、13 DDS、167 本地化键），翻译审计八种非中非英语言的英文原文残留与汉字占位均为零，兼容特质审计 19 项通过。正式脚本同步到仅启用本 Mod 的简中隔离局后，从同一零倍率且非零当前经验基线真实死亡并付款；[正式结果存档](../assets/shishan-code-origin/evidence/vivhite-formal-xp-restore-2227.03.09.sav)中经验为 `317.51909`、等级为 5，原有特质仍在，临时特质、恢复变量、备份及待复活标记均为零。隔离连续死亡[结果存档](../assets/shishan-code-origin/evidence/vivhite-repeat-during-restore-2227.03.11.sav)另证实恢复中再次死亡不会复制领袖。非简中语言**静态校验通过，运行时不在范围内**。
