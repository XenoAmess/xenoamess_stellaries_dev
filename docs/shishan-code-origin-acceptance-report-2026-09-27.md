## 当前阻断与恢复动作

维护完成事件出现后，旧游戏窗口停止刷新。结束进程并重新启动时，Mod 与无 Mod 的全新隔离目录都停留于空白客户区，无法进入主菜单；无 Mod 对照也在窗口化、另一渲染器配置、禁用 `-debug_mode` 和图形驱动重置后复现。经用户授权重启 Windows 后，Event Log 服务恢复，但两次新的无 Mod 启动仍停留在黑色或白色空白窗口。旧成功会话的 `system.log` 也以 `Done creating device` 结尾，故该日志末行不作为故障阶段的判断依据。证据和各隔离目录见[实机发现](shishan-code-origin-runtime-findings-2026-09-27.md)。这排除了“只有本 Mod 导致新进程不能启动”的判断，却不能排除旧会话停止刷新与 Mod 有关。当前不能宣告整体验收通过。

游戏 UI 恢复后，先用无 Mod 对照确认可进入主菜单，再从保存的 `autosave_2226.07.01.sav` 继续；优先完成 RS-01—RS-04、清理/优化和奖励生效，其次补边界、岗位与两类机械帝国。每项保留实机截图、日志、存档和结果；若来源隔离不成立，先修正实现并重跑，不降低已确认合同。
