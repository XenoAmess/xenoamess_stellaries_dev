# 新增UI梳理与决议体系整改

用户要求将觐见女王改成决议，排查其它新造UI并统一手动操作入口。此要求取代此前0.2.1-rc.1的按钮尺寸修复方案；该候选只通过静态检查、尚未完成修复后实机，不宣称已完成。下一候选移除整份星球GUI覆盖，使用原生决议和原生事件／局势界面。最新用户指令将本项升为最高优先级，障碍清除和UI回归后置；Steam离线、只启用本Mod、简中实机。

| 对象 | 现状／作用 | 整改设计 |
| --- | --- | --- |
| `interface/planet_view.gui` | 唯一新增GUI文件，整份覆盖原版8500余行；额外插入觐见按钮，造成已确认的父边界裁切 | 删除整个覆盖文件，让星球页、建筑详情、管理页与清障操作使用当前原版GUI |
| `eep_audience_button`／`common/button_effects/eep_buttons.txt` | 自造按钮与全局选中对象／玩家国效果接口 | 删除按钮和专用button_effect，改成原生`decision_eep_audience` |
| `eep.100`王庭报告 | 原生country_event窗口，使用CG及动态账簿；原有“呈上消化战记”手动选项 | 保留原生报告展示与关闭；入口改母星决议，移除二级手动操作入口 |
| `eep.101`源星战记 | 原生country_event窗口，读取指定源星 | 在处于吞噬任务的源星提供“查看吞噬战记”决议，仅显示该星球报告 |
| 女王介绍／成长／灵飞／矿物舰／失联复归事件 | 游戏原生事件通知，非自造GUI组件 | 保留自动通知及原生确认，属于既有叙事机制 |
| 吞噬局势与继续／中止方案 | 游戏原生situation／approach控件，非新造窗口 | 保留进度与原生局势控制，不另造按钮 |
| `interface/eep.gfx`与肖像／CG DDS | 精灵资源注册、原生图标／人物／事件配图，未定义GUI布局 | 保留美术，不覆盖原版GUI |
| 手动吞噬与原生噬岩决议适配器 | 已使用决议体系 | 保留既有规则；新增自动吞噬开启／关闭也采用决议 |

实施前合同：只保留原生手动入口，不新增`.gui`或`effectbuttonType`。觐见决议仅自有绑定母星及合格玩家可见，调用已有eep.100，不改变C/G/D、人口、消化任务或奖励。源星战记仅有本Mod活动任务的自有源星可见，正确设置eep_report_source后调用eep.101，母星／外星球不误报。两个自动吞噬开关为全帝国决议，默认关闭，详见[设计](auto-devour-decisions-design-2026-10-15.md)。无费原生决议的科研库存重建行为已有原版对照证据；本次用户明确选择决议体系，保留该已知行为的实机结果，不私自发放科研补偿或隐藏差额。

验收标准：open_kaishek包检查通过；确认生产包GUI文件／effectbutton／专用button_effect均为零，所有原生美术引用保持；母星觐见／源星战记／自动开关决议可见性、执行、关闭及重载逐项有证据。障碍清除、建筑拆除、管理页及原生决议／改造按钮在1024×768／0.75和1920×1080／1.0复核；其它九语言仅静态校验通过后报告，实机不在范围内。此报告先记录设计与调查结果，实施／验收进展后续回写，不预写通过。
