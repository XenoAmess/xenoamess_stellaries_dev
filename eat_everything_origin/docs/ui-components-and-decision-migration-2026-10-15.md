# 新增UI梳理与决议体系整改

用户要求将觐见女王改成决议，排查其它新造UI并统一手动操作入口。此要求取代此前仅通过静态检查的0.2.1-rc.1按钮尺寸方案；本次0.3.0-rc.1已移除整份星球GUI覆盖，使用原生决议和原生事件／局势界面，并完成下文两配置专项。按用户优先级先做本项，再后置障碍清除与UI；Steam离线、只启用本Mod、简中实机。

| 对象 | 现状／作用 | 整改设计 |
| --- | --- | --- |
| `interface/planet_view.gui` | 唯一新增GUI文件，整份覆盖原版8500余行；额外插入觐见按钮，造成已确认的父边界裁切 | 删除整个覆盖文件，让星球页、建筑详情、管理页与清障操作使用当前原版GUI |
| `eep_audience_button`／`common/button_effects/eep_buttons.txt` | 自造按钮与全局选中对象／玩家国效果接口 | 删除按钮和专用button_effect，改成原生`decision_eep_audience` |
| `eep.100`王庭报告 | 原生country_event窗口，使用CG及动态账簿；原有“呈上消化战记”手动选项 | 保留原生报告展示与关闭；入口改母星决议，移除二级手动操作入口 |
| `eep.101`源星战记 | 原生country_event窗口，读取指定源星 | 在处于吞噬任务的源星提供“查看吞噬战记”决议，仅显示该星球报告 |
| 女王介绍／成长／灵飞／矿物舰／失联复归事件 | 游戏原生事件通知，非自造GUI组件 | 保留自动通知及原生确认，属于既有叙事机制 |
| 吞噬局势与继续／中止方案 | 游戏原生situation／approach控件，非新造窗口 | 保留进度与原生局势控制，不另造按钮 |
| `interface/eep.gfx`与肖像／CG DDS | 精灵资源注册、原生图标／人物／事件配图，未定义GUI布局 | 保留美术，不覆盖原版GUI |
| 手动吞噬与原生噬岩决议适配器 | 已使用决议体系 | 保留既有规则；新增自动吞噬开启／关闭也采用决议 |

实施前合同：只保留原生手动入口，不新增`.gui`或`effectbuttonType`。觐见决议仅自有绑定母星及合格玩家可见，调用已有eep.100，不改变C/G/D、人口、消化任务或奖励。源星战记仅有本Mod活动任务的自有源星可见，正确设置eep_report_source后调用eep.101，母星／外星球不误报。两个自动吞噬开关为全帝国决议，默认关闭，详见[设计](auto-devour-decisions-design-2026-10-15.md)。无费原生决议的科研库存重建行为已有原版对照证据；本次用户明确选择决议体系，保留该已知行为的实机结果，不私自发放科研补偿或隐藏差额。

验收标准：open_kaishek包检查通过；确认生产包GUI文件／effectbutton／专用button_effect均为零，所有原生美术引用保持；母星觐见／源星战记／自动开关决议可见性、执行、关闭及重载逐项有证据。障碍清除、建筑拆除、管理页及原生决议／改造按钮在1024×768／0.75和1920×1080／1.0复核；其它九语言仅静态校验通过后报告，实机不在范围内。此报告先记录设计与调查结果，实施／验收进展后续回写，不预写通过。

## 当前实施结果

生产包已删除整份planet_view.gui与eep_buttons.txt；`.gui`、`effectbuttonType`和专用button_effect均为零。觐见、源星战记、全帝国自动吞噬开关已使用原生决议；eep.100仅保留关闭选项。保留的eep.gfx只注册精灵，事件CG、人物肖像与局势采用游戏原生窗口。追加的母舰模型.asset／隐藏图形文化注册舰体外观，船坞使用原生主宰界面，也没有新增GUI控件。

v6简中单Mod1024×768／0.75已有女王／源星报告、自动开关及工业废土真实付款和120日完成证据；原始报告、图片和存档见[evidence/1015-2026-10-15/v6-runtime](evidence/1015-2026-10-15/v6-runtime)。后续v13母舰原生船坞／舰船详情／舰队管理器实机可操作，结果见[船坞专项](evidence/1015-2026-10-15/v13-shipyard-runtime/shipyard-proof.json)。最终两配置结果见下节，不能把专项扩大为所有UI通过。

追加母星迁移、取消拆解及恢复本星球自动吞噬均已实现为原生决议。既有局势中止方案复用同一取消效果。迁移35项、取消及跨月恢复28项范围检查已通过；[取消实机证据](evidence/1015-2026-10-15/v17-final-runtime/cancellation-proof.json)保留原失败及误操作记录。两配置UI结果另列，不以功能专项代替全部游戏界面检查。

## 最终候选的两配置操作结果

v17同一生产树在1024×768／0.75与1920×1080／1.0，实际切换基础设施／管理页、打开实验室详情与原生拆除确认框。选择取消保留建筑，选择确认仅移除指定实验室；清障实际扣300能量、原生队列左键取消后全额退回。[1024的15项证据](evidence/1015-2026-10-15/v17-final-runtime/ui-1024-proof.json)与[1920的19项证据](evidence/1015-2026-10-15/v17-large-ui-runtime/ui-1920-proof.json)保留原SAV、图片和误操作，不把无效坐标点击写成Mod失效。

女王报告在两配置从母星决议打开并正常关闭，1920还实际执行源星战记决议，显示维米里恩Q20、16/48有效月；操作后库存及人口组严格保持，仅刷新报告缓存。原生报告窗口属于保留的事件展示，并非重新增加自造GUI。大分辨率原生建筑详情与决议列表另占右侧栏，小分辨率使用现有侧栏，按钮应按实际原生布局定位。

已确认并修复的是原女王按钮父容器裁切及整份GUI覆盖风险；最终两配置单独启用本Mod，未复现无法拆除建筑。管理页背景仍具有原生界面半透明显示效果；当前通过结论针对实际切页与操作，不承诺任意分辨率、所有游戏窗口或其它Mod组合的像素布局均无问题。实际清障与双民用队列完工的最后回归结果见[本批验收报告](acceptance-1015-result-2026-10-15.md)。
