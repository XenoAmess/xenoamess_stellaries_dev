# 吞噬之心：实施前探针与验收设计

日期：2026-10-06。承接[设计案](../../docs/eat-everything-origin-design-2026-10-06.md)和[源码调查](game-script-research-2026-10-06.md)。本文保留制定时的验收合同；制定时游戏用例未执行。2026-10-07已执行证据与待补项见[离线实机进度](runtime-acceptance-progress-2026-10-07.md)，完整验收与发布仍未完成。

2026-10-08发布顺序变更：用户明确要求全部政体保持开放，完成焦土蜂巢验收后先发布，并在公开说明中列清已验收范围／推荐路线；发布后继续其它测试与修复。首发适用合同、明确延期项及范围报告门槛见[焦土蜂巢优先首发合同](scorched-hive-first-release-2026-10-08.md)。下表完整33项仍是最终验收目标，延期项不得标PASS；首发只取得焦土蜂巢范围的通过，不宣称全部政体完整验收。

2026-10-08实测澄清：下表原版Q20“120月”来自数学表达式的制定时预测。172235非本起源原生决议开始后实际首月步长8.5，而非数学8.333333，详见源码调查的新精度记录。原版对照合同的目标仍是保持官方行为一致；必须记录真实自然完成边界并在真正无Mod环境积极复核，不能为凑120而改变原生分支，也不能仅凭当前单月数据宣布EAT-05／27完整通过。EEP的Q15／20／25为36／48／60有效月合同不变。

用户已确认偏强爽玩、普通星球吞噬 3～5 年，并拥有 Nemesis 和「虚境之影」。设计默认 `T = ceil(12 × Q / 5)` 个有效推进月，20 格无旧损毁为 48 月；尚无实机耗时或平衡结论。

## 1. 固定环境与执行顺序

实施前更新需求、最终选定参数、独立预发布版本与变更记录。先读取 `D:\workspace\open_kaishek` 自身的使用说明，确认它支持本机 `Cygnus v4.5.2 (9776)` 和实际 EXE 指纹，再按该说明执行工具验收；不照抄其它机器的失效入口或路径。

本轮本地工具副本只确认有受限 4.4.6 profile、未找到历史验收入口。因此未来需要同步/复核；若实际缺功能或有缺陷，暂停 Mod 验收，先在工具仓库记录方案、完善工具、验证并只提交推送工具相关改动，再继续。不得把 parser round-trip、离线算术或旧 4.5.1 报告等同于 4.5.2 引擎验收。

静态工具通过后，在隔离环境以 `l_simp_chinese` 启动，记录 EXE、源码指纹、DLC、播放集、Mod 版本、存档、日期、截图/OCR、月度经济和日志。其它语言只做键完整性、文件头/编码、引用、原始 key 泄漏和简中占位文本校验，结果写「静态校验通过」或「运行时不在范围内」。

主配置同时启用 Nemesis、Shadows of the Shroud，启动前保存实际加载证据，优先走通各核心政体的灵飞＋武灾闭环。缺任一 DLC 的用例作为兼容检查，仍保留基本吞星玩法与原版门槛，不替代主配置组合验收。

## 4. 自然局对照

各核心路线与同版本、同 DLC、同种子/难度的原版灭绝帝国对照，记录 5/10/20/40/80 年的人口量、住房、舒适度、已建/可建区划、矿电食/合金/消费品净收支、三系科研、凝聚力、帝国规模、舰队、首战日期、每次吞星日期和短期殖民地数量。

至少覆盖：优先科研/灵飞、优先首战/武灾、先吃保证宜居星球、连续征服吞星、长期停战、缺 Shroud 或 Nemesis。无 DLC 路线不能用控制台强行解锁替代正常可玩性；隔离探针中的加资源/加速不进入自然局结论。

验收目标是首战和首轮吞星可用普通岗位与原版投入实现，不需要降低产出的专属科研岗位；完成吞星后能在可负担的建设窗口内把新增容量转成住房与有效岗位；灵飞和武灾组合前后资源净流量可维持下一轮战争。初步建议以吞完尺寸 20 后五年内能兑现至少一个新增区划为建设观察线，失败则调整兑换/时间/队列方案并记录原因，不能只拿空容量数字宣称闭环成功。

强度目标已确定为「偏强爽玩」，优先确认吞星回报明显、母星成长可兑现、连续战争可供养；允许明显强于原版，不以原版平均强度作为回调目标。优先解决卡死、重复结算、无效容量和操作负担；无限产出倍率或规模减免仍不属于已选参数。数值修订必须同步设计、候选版本与测试样例。
