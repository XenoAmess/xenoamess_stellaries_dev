# 0.3.2：取消额外开局殖民地、测试与发布

范围更新：[1019 五项需求](requirements-2026-10-19.md)已授权实施，未发布的 0.3.2 并入 0.4.0。本文保留开局调查、工具设计和中间候选证据，不代表最终母舰配置已通过验收。

## 补充授权与母星配置修复设计

用户已明确选择“一并修复母星开局配置，再发布”，并确认 Windows 桌面已解锁。范围扩展为修复新游戏母星在转换为蜂巢／机械世界后，沿用普通世界农村区划数量导致岗位容量翻倍、劳动分配挤占发电岗位的问题。修复候选将升为0.3.2-rc.2；旧存档不追溯调整区划。不得以赠送资源、增加人口、全局减免维护或关闭岗位掩盖赤字。

设计：先完成三类0.3.1原始对照；按原版4.5.2区划与资源特区规则，对新开局的过量农村区划进行最小数量调整，保留母星类型、资源特区和既有建筑。先在隔离的原始存档副本中验证原生 remove_district 对区划级数和岗位的实际效果，再写入一次性开局效果；必要的岗位重新分配仅通过原生经济月结自然完成。普通政体无证据表明需调整时不修改。验收仍要求三类各12次真实月结能源非负，保留旧版失败数据、原生SAV和岗位预算证据，并检查旧存档不受新布局影响。

方案收敛（实施前修订）：独立控制台删区划探针合并到通过open_kaishek后的候选真实开局验收。`remove_district = <type>`在原版农村清理脚本及本Mod已实测的原生吞噬效果中均已有使用；候选直接对初始SAV核对等级变化、资源特区、岗位和人口，再进入月结，比在旧版另造一套布局更直接。具体仅在一次性eep_startup内部、change_pc之后且添加资源特区之前，蜂巢农业区划高于2则逐级减到2，机械矿业高于2则逐级减到2。能源区划及其它建筑不改，不增加岗位优先级或临时就业上限。已有更低区划数时不补建。新旧初始区划和12个月预算不符即保留失败并修订候选，不能通过静态结果越过实机。

原版`species_lithoids.txt`另确认石质物种开局为能源2／矿业5／农业0，不能只减农业覆盖其蜂巢变体。蜂巢母星额外将超过4级的矿业减到4，以保留石质人口所需矿物并释放发电劳动；非石质默认矿业2不受影响。追加一次独立石质蜂巢开局与首月冒烟检查，使用本任务原生自定义帝国副本，不恢复已经停止的噬岩者完整战役，也不宣称该路线完整验收。

蜂巢旧版12个月对照现已完成：首月约-38.91能源/月，年末约-36.05，年中库存耗尽；并非仅额外殖民地维护。原版起始蜂巢农村区划为能源2、矿物2、农业3，转换后资源岗位容量提高，农业占1800劳动、矿业约1100，发电岗位容量1200却接近无人就业。机械旧证据也有发电岗位1800而劳动为0，需用本轮新局确认。

## 授权、目标与范围

2026-10-19用户明确要求按“取消额外开局殖民地，保留三类母星”的建议修改、测试、发布。[前期评估](../../docs/eat-everything-origin-startup-economy-feedback-2026-10-19.md)中的后续实施和发布现已获得授权。本任务采用新版本0.3.2，候选阶段为0.3.2-rc.1；禁止复用成功发布的0.3.1。

新游戏仍按蜂巢／机械智能／其它合格政体给予蜂巢／机械／遗落母星，停止生成额外物理世界、殖民地及赠品人口和设施。保留母舰、母星队列、王庭、危机和自动吞噬默认状态。旧档现有世界及已发生的经营结果保持，不新增删球决议，不补偿人口或资源，不恢复已停止的噬岩者完整战役验收。

## 验收计划与标准

只读验收汇总器设计：新增工具从原始SAV重新提取并核对绑定的运行manifest，而非手填PASS。开局检查0日与首月：殖民地数／三类母星／无赠品凭证、唯一母舰和十船坞、母星队列刷新后为2、危机与王庭、自动吞噬默认关闭、区划和实际发电劳动。经济检查三类新旧各13份真实SAV的实际日期、SHA、12个月能源净额和库存方向，同时保留其它关键资源预算；不使用初始旧缓存代替月结。重载／重复初始化／旧档检查分别比较同日库存、EEP状态、世界和人口、区划、舰队与队列，任何差异均先原样FAIL留证，再单独解释已确认的原生缓存差异；不可静默过滤未知字段。

- 原版0.3.1及候选均先使用open_kaishek按仓库说明检查，记录精确EXE及包指纹，报告PASS后才用于实机。工具若有缺陷先修工具并提交推送后继续。
- 简中、只启用生产吞噬之心，对蜂巢、机械智能、普通灭绝政体各运行一个0.3.1基线与一个候选新开局。记录真实帝国配置、银河设置及差异，不冒称随机新局完全同源。候选每局仅一个自有殖民地、母星类型正确，不存在赠品生成凭证或额外赠品物理星球，且母舰唯一、母星队列两条、危机与王庭正常、自动吞噬默认关闭。
- 每个代表记录开局和连续至少12次实际月结的存档与预算：能源收入、支出、净额、库存，关键资源、岗位及舰船／设施维护和海军容量。允许通过原生日历推进指令缩短等待，但保存和日期必须来自真实游戏；不加资源、不生成Gray舰，不交易、拆舰、关岗位或拆设施掩盖负电。若候选仍有赤字，保留失败并按预算定位，在确认所需变更范围后修正；不得把“取消赠品”直接等同于“全部负电已解决”。
- 候选真实原生重载及重复初始化不再生成赠品、不复制母舰、不丢失绑定与既有数据。加载含赠品的0.3.1原始存档副本并原生重载，检查世界／人口／绑定／资源／任务；只允许记录并解释的原生缓存变化。
- 其它九语言只做静态校验：键完整、文件头／UTF-8 BOM、引用与token、raw key风险、简中占位和旧赠品文案。报告“静态校验通过；运行时不在范围内”。
- 发布前对正式包重跑工具，验证候选字节等价、本版运行证据和发布保护。发布至既有物品3815707212，禁止写只读上游3710613857。远端正文、更新说明、版本、可见性、封面、图库／正文图及独立下载全部文件相符后，提交凭证并创建推送v0.3.2标签。Steam实机保持离线，最后上传／核验阶段在线，收尾恢复离线。
