# 0.3 系列正式发布与创意工坊图文说明

日期：2026-10-15。状态：最终0.3.1发布并远端核验通过；0.3.0图库失败及修复记录保留。Steam已恢复离线。

## 目标与范围

按用户要求将已完成 1015 专项验收的 0.3.0-rc.1 提升为正式版 0.3.0，更新本项目现有创意工坊物品 `3815707212`。同时重写玩法说明，在正文嵌入实机图片，包含本版 changelog，并将实际上传的 BBCode、Change Note、图片清单及发布凭证全部入库。只读上游 `3710613857` 禁止写入，不创建新物品。

## 方案

1. 先建立正式 changelog，统一 VERSION 与 descriptor。正式版 Mod 除 descriptor 版本字段外必须与已验收候选逐字节相同；保留历史 RC 与 0.2.0 验收记录。
2. 正文说明设计主题、战争—吞噬—母星成长循环、女王与武灾成长、三类开局、移动船坞、决议入口、默认关闭的自动吞噬、取消拆解与母星迁移。使用游戏简中正式名称，明确 DLC、兼容范围和验收边界。
3. `workshop/description.bbcode` 是正文唯一来源，UTF-8 小于 Steam 的 8000 字节限制；包含最新 changelog 摘要及完整 changelog 链接。Change Note 从同版正式 changelog 提炼，以 `[v0.3.0]` 开头。
4. 正文使用已经推送的固定提交 `62e273a504a817be3c4037340557c4f1e3e2e522` 中实机图片的公开原始文件地址。上传前校验 HTTP 可访问、图片格式及原始字节，避免浮动分支和未经上传的本地路径。图库保持封面加六张图，替换过时悬浮 UI 截图，历史灵能与矿船截图明确为对应机制展示。
5. 新增现有物品更新入口，保留首次发布工具的保护与旧凭证。固定目标 ID；拒绝已成功上传版本重传、预发布版本、源文件漂移、缺少正式 changelog 或证据的发布。新版状态及独立下载凭证存放 `docs/evidence/publication-0.3.0/`，不得覆盖 0.2.0 发布凭证。
6. 先使用 open_kaishek 执行正式包检查，再验证与候选的字节等价、八项专项凭证及图片、BBCode、发布保护。发布前提交并推送冻结输入；最后才将 Steam 切换在线并上传。
7. 上传后通过 Steam 公共详情、更新记录、图库原始字节及独立 Workshop 下载核验。正文必须与入库 BBCode 完全一致，并确认嵌入图片出现在实际页面。核验成功后提交凭证，再创建并推送 `v0.3.0` 标签，恢复 Steam 离线。

## 验收与声明边界

- 必须通过 open_kaishek；简中运行时证据采用 `acceptance-1015-result-2026-10-15.md` 与 `final-evidence-index.json` 的八项最终专项结果，不将专项测试改称完整自然战役验收。
- 0.2.0 历史完整验收仅焦土蜂巢；其它政体仍开放但完整自然路线未全部完成，噬岩者自然流程已按用户要求停止。0.3.0 三类开局及共用功能专项通过不等于所有政体完整验收。
- 其余九种语言仅静态校验；其它 Mod 联合测试不在范围内。原生重载出现的两个星球 `carrier_binary_flags` 从 1 变为 3 的私有状态差异如实保留，不声称所有原始字段完全相同。
- 正式 Mod 文件清单、版本、标题、物品 ID、可见性、正文、更新说明、封面及六张图库必须与远端相符；独立下载的完整文件清单必须逐字节一致。
- 自动化发布保护需要覆盖错误物品、重复成功版本、未冻结输入、证据变化、正文图片地址与 changelog 不一致等高影响失败路径。
