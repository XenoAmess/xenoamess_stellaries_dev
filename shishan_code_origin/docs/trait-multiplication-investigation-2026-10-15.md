# 全特质独立乘算的原生通道复核

## 调查目标与范围

依照[本轮发布及剩余验收设计](release-0.2.1-and-remaining-acceptance-2026-10-15.md)，复核现有 5% 全特质成长是否存在适合当前 Mod 的原生独立乘算实现。正式版本为 0.2.1；本调查不修改生产或发布身份。用户已允许：没有可靠、兼容的合适方式时，记录证据并按当前加算合同验收。22 个自然新局及长期路线由用户排除，不在本调查中恢复。

目标仍是国内主体谱系真实人口加权 U 加持久补丁 R，T=U+R，每层 5%；全国内岗位资源最终产出独立乘 M=1+0.05T，不改变维护、人口、就业或外国。判定以本机 Stellaris 4.5.2 原版与最新 `20261015T094102Z` 生成文档为主；区分可用语法、尚不明确的数学顺序和不符合范围的替代机制。不将「目前未找到」写成引擎数学普遍不可能。

只读复核候选：国家岗位修正、经济类别、岗位 `produces.mult` 与 `_add`、劳动力和 bonus workforce、按收入补发资源。调查只写本文和 `_runtime/shishan_code/20261015-remaining/` 中独立证据 JSON；不启动游戏、不操作 GUI、不改验收工具或生产代码，不自行提交或推送。

## 方法与验收

记录原版及生成文档的绝对路径、SHA-256、具体行号/摘录；统计原版岗位/inline hook 的实际覆盖，核实维护联动的原版本地化定义。只读证据 JSON 将包含检索范围、实际命中及缺少直接最终乘算接口的有限检索结论。若无法证明一项候选满足全国所有岗位、最终输出、维护不变及兼容性，保留其可能性及所需后续实验，不把未测试实现登记为通过。

最后给出适用结论、方案取舍和用户允许的加算回退验收标准；当前阶段不运行新引擎探针，原生最终结果由主任务后续验收。

## 调查结果

本轮只读调查完成：**在全国岗位、维护与就业不变、不批量覆盖原版/第三方岗位、不用月度资源补贴替代岗位产出的约束下，未找到已获充分证据支持且合适的最终独立乘算通道；本版本采用用户允许的每层岗位产出加算 +5% 回退。** 原生存在乘法语法及经济修正读取接口，不能据此结论断言 Stellaris 引擎数学普遍无法实现乘算。

本轮没有运行新实机探针；结论为接口、范围与维护成本评估，不是新的经济实测 PASS。原目标保留为后续研究，修订后的 TS-05/06、EC/RS/CP 要按下文重新取证后才能通过。

## 方案比较

| 方案 | 评价与当前取舍 |
| --- | --- |
| 单一国家 `planet_jobs_produces_mult=0.05*T` | 全国岗位资源生效，不改劳动力或维护。它与原有同类经济增幅加算；这是本轮采用的明确回退，不称独立乘算。 |
| 新类别、换修正名字或动态 `add_modifier.multiplier=T` | 能改变作用范围或系数，单靠命名与类别继承没有独立最终层证据；新类别要接入既有岗位仍需要调整类别绑定。不能把该方案登记独乘完成。 |
| 在每个岗位的 `produces.mult` 接入 M | 值得保留的原生基值通道。必须修改每个相关岗位及条件分支，正确结合其现有 mult，且证明 `_add` 与多 resource table 的顺序。原版 22 文件中按 category/resources/is_capped_by_modifier 识别到 345 个岗位定义式块（包括 swapped/fake 定义，不代表全都启用），264 个有直接 resources 块，只有 16 个显式引用 `output/` hook；`researcher_output.txt`、`factory_output.txt` 为空且不是全岗位统一 hook。批量覆盖会与原版更新和第三方新增/替换岗位直接冲突，仅支持本 Mod 两岗位也不满足全国范围。当前不采用。 |
| 读取现有经济增幅后按 job/resource 动态补偿 | 数学上可以设补偿量 `D=B*(1+A)`，让 `1+A+D=(1+A)*(1+B)`。原生上述 reader 使它成为可研究方案，不能声称普遍不可能。实际要逐星球、类别/岗位和资源处理所有原有修正，先排除自身补偿，解决缓存/反馈环、条件输出、追加基值及实时更新。原版已经为该读取器记录精度与重算风险；每组人口还可能供给多个岗位，不能给一组套单一 job 的读值。没有已验证的全经济变更即时刷新或无循环协议，新增岗位/资源也会扩大维护矩阵。当前缺少满足成本与正确性的证据，不采用。 |
| 增加 `pop_bonus_workforce_mult` / 岗位效率 | 属于另一层，与普通产出增幅有相乘关系；但不是只乘资源。官方说明同时放大岗位投入与产出，且同层效率已有加成时再加 B 也不是对全部现有效率直接乘 M。按现有合同不允许以额外维护或劳动力变化换收益，当前不采用。 |
| 效率增益加反向维护修正抵消 | 需要逐资源/类别补偿已有维护修正、处理其它效率与额外 upkeep 表；一般经济负倍率有 -90% 下限（`defines:2031–2032`）。以无其它维护加成的基线为例，若效率按 M 放大投入，要抵消需 `1/M`，M>10 时普通负倍率通道不能给出小于 0.1 的系数。这是该抵消路线与无限成长冲突的具体反例，不是所有乘法方案的普遍不可能证明。 |
| 增加实际 workforce、岗位容量或自动劳动力 | 改变岗位供给、就业或人数含义；容量本身也不保证填满。会触及维护员实际 J 与局势速度的独立合同，不能当作岗位资源最终倍增的替代。 |
| 按岗位毛收入月结补发 / duplicate 星球输出 | 可以设计资源补贴，但需要处理收入来源、科研与凝聚力流向、市场贸易转换、月结顺序、补发重复和纳税/附庸等交互。duplicate 星球还缺少限定岗位经济类别的参数。它不使原岗位 UI 与资源表成为乘算结果，当前不采用。 |

上表对 `produces.mult` 与动态补偿保留的是未完成的可行性研究方向；没有本轮静态资料能替代原生隔离实验。若未来放宽批量岗位兼容范围或单独立项测试这些路线，可以重新评估。

## 劳动力与维护联动的一级资料

官方开发者在 [Dev Diary #372](https://steamcommunity.com/games/281990/announcements/detail/502818210084553499)（2025-02-27；可读[官方 Steam 镜像](https://store.steampowered.com/news/posts/?appids=281990&enddate=1742288410&feed=steam_community_announcements)）明确说明：人口组不按工作种类划分，可以同时供给不同岗位；bonus workforce 对应增加的岗位工作量，其岗位投入与岗位产出都扩大。人口自身维护和岗位资源投入是不同费用，不能用「人口没有增加」推断「岗位维护没有增加」。这是 4.0 架构解释，结合当前 4.5.2 暴露的 workforce 接口用于确认重大设计风险；不把历史开发日志冒充本轮新做的 4.5.2 数值实测。

若基线效率为 E，直接增加 B 的相对效率为 `(1+E+B)/(1+E)`；只有 E=0 时它才恰好等于 M。要与所有既有效率独立相乘，还需按实际 E 计算额外量；再叠加维护补偿，并不会变成简单、无联动的全国最终乘区。

## 用户允许的加算验收合同

原独乘目标保持历史记录，修订用例明确标为「用户授权加算回退」，不登记「独立乘算实现 PASS」。新合同验收要求：

1. 计数仍使用国内主体谱系实际正人口组和全部正式物种特质，正负都计；空模板、外国人口和非主体谱系不进入 U。R 单独持久化且迁移幂等。国内没有主体谱系实际人口时，撤销修正、B=0/M=1，R 保留。
2. 有实际主谱系人口时 T=U+R、B=0.05T；只存在一个 `shishan_code_architecture_jobs` 国家实例，multiplier=T，无人为层数上限。成长边界、迁移、重复刷新与重载检查沿用对应独立用例，不能由本调查自动判通过。
3. 收益覆盖本国岗位资源，包括本国内非主谱系人口从事的岗位；「外国不受影响」指外国国家及其岗位，不是禁止国内非主谱系人口受益。非岗位基础收入、空间站、地块、建筑直接产出等按已有资源来源矩阵分别作阴性对照。
4. 对其它因素固定、未触及引擎截断的同一岗位资源，设字面/追加基值与实际劳动力已合并为 Q，原有经济加算为 A，则回退合同为 `Q*(1+A+B)`，不是 `Q*(1+A)*(1+B)`。例如 A=50%、B=50%，结果应为 2Q；相对原有 1.5Q 为 4/3，不能声称「最终收入额外乘 1.5」。至少保留一个 A≠0 的对照，避免只测 A=0 导致两种机制看起来相同。
5. 单独改变 R 或其它受控架构层数来隔离机制，确认本机制不增加任何岗位或人口维护、不改变 workforce/bonus workforce/岗位容量/维护员 J；原奖励特质自身的就业效率、资源消耗等原有效果另行保留，不能将其变化误归因于架构。维护员社会学与凝聚力、非主谱系国内岗位、科研及稀有资源按既有 EC/RS/CP 用例取证。
6. 玩家说明必须写岗位加算，每层 +5%、正负全计、无限成长；统计 M=1+B 只是原独立目标的诊断系数，不能作为实际全量收入比值展示。当前 summary 已明确统计不代表实际独立收入倍率；正式发布措辞由发布主任务统一处理。

验收记录先保留「新合同待实测」，由主任务根据真实来源隔离、维护、权重、重载和性能证据逐项判定。用户排除的自然新局与长期路线不作为阻塞项，也不能改登记为 PASS。本调查不另行增加该范围，非中文只做静态校验。

本调查只新增本文与只读 JSON，没有启动游戏、GUI、Steam 或修改生产/验收工具。源码/文档行号与哈希已落证据；只读扫描 22 个岗位文件全部解析，无解析失败。正式 0.2.1 发布及后续实际验收仍由主任务执行，本调查不宣称发布完成或经济实测完成。
