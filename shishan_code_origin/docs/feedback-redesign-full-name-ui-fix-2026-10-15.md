# 长机制名的正文全文修复

日期：2026-10-15。实施前记录。用户指定全名为「基于低内聚高耦合的旧时代集成服务架构」，不得改成简称。

## 真实问题与修复目标

主任务在冻结的 `0.2.0-rc.2`、实际 1600×900、请求 gui_scale 0.75 的简中实机中观察到，机制详情标题显示为「基于低内聚高耦合的旧时代集...」，悬停没有全文，正文只有统计与规则。已由游戏原生保存 `fb452_mix0`；详情与悬停证据由主任务归档为 `mixed-architecture-details.jpg` 等。本修复不把标题截断本身伪写成引擎支持全文。

目标是通过正常详情、奖励及结果正文提供完整机制名，使正文能使用原生自动换行。保留现有正式全名、各语言译名和事件标题；不修改事件、GUI 定义、生成器、VERSION 或 CHANGELOG。主任务继续运行冻结 rc.2 的其它功能；此源文本修复会在后续 rc.3 重启后重新验收。

## 范围与实现方案

只修改十种语言各自的 `mod/localisation/<language>/shishan_code_feedback_l_<language>.yml`，复用三个现有键：

1. `shishan_code_architecture_summary` 前置 `$shishan_code_architecture_title$\n\n`。完整名称单独作为正文首段，不依赖有限宽度的事件标题。
2. `shishan_code_reward_desc` 在引用上述 summary 前加入 `\n\n`，先显示候选说明，再单独显示完整名称与统计。
3. `shishan_code_reward_repeat_result` 在引用上述 summary 前加入 `\n\n`，先显示增加重复层的结果，再显示完整名称与统计。

名称引用链为正文 → `shishan_code_architecture_title` → `shishan_code_architecture_jobs`。不新增本地化键，不复制硬编码名称；保留各语言已有文本、动态变量和资源/颜色格式。

现有事件路由已只读核对：`.1001` 机制详情与 `.1003` 实体结果直接使用 summary；`.1000` 三选一正文引用 reward_desc；`.1002` 耗尽结果使用 repeat_result。因此一次共享正文修复覆盖四个必要入口，不重复插入名称。

## 验收标准

- 静态确认十语言都具有完整且无环的引用链，四个实际正文入口都能展开一次完整名称，名称后有正文换行。
- 简中展开结果逐字含完整 18 字名称，不含省略号或原始 key；九种外语继续使用各自已存在的名称翻译，不能加入简中占位。
- 键集、语言头、UTF-8 BOM、所有原有动态变量及其它格式 token 保持；除了计划中的引用和换行，不改正文翻译内容。
- 运行既有本地化静态检查，并单独检查全文的传递引用与新增换行。不把静态字符串展开称为真实 UI 显示通过。
- 包级 G1 由主任务在重启前对实际候选统一执行。本任务不调用游戏/Steam/桌面，不修改现有 runtime 文档或正在运行的冻结副本。
- 简中 rc.3 重启后，主任务在同一实际分辨率/缩放复查详情、三选一和两类结果的全文可达、自动换行、滚动与按钮是否受遮挡。标题仍可能原生截断；正文完整可读且可正常到达才满足本项通过线。其它分辨率未运行则保持未运行。
