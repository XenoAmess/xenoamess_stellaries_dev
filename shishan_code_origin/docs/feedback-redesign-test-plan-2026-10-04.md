# 「屎山代码」反馈改版测试方案

日期：2026-10-04。状态：方案已编写，测试未执行，Mod/夹具/自动化尚未实施。

## 1. 目标、范围与合同来源

本方案验收用户已修订的反馈改版：保留原特质预算；局势和维护研究所改善；奖励三选一及三次选择冷却的 reroll；负面阶段减半；领袖白绮科研和凝聚力负担调整；所有正式物种特质参与 5% 无限协同，优先独立乘算，机制名固定为「基于低内聚高耦合的旧时代集成服务架构」，另验长名称显示。

合同来源为[反馈改版稿](../../docs/shishan-code-origin-feedback-redesign-2026-10-04.md)和[协同设计稿](../../docs/shishan-code-origin-trait-synergy-design-2026-10-04.md)，本次方案在提交 `bc88ef4` 的基础上纳入用户最新要求「初始月速不要 3，改为 1」。逐项操作见[测试用例](feedback-redesign-test-cases-2026-10-04.md)。旧版代码基线为 `0.1.3`、初始月速 5，新候选版号在施工时登记预发布版本，本方案不提前修改 `VERSION`。

用户明确选定的硬合同是初始月速 `1`、保留额外 `-6` 特质点、三选一、reroll 冷却为三次选择、所有正式特质计数及每层 `5%`、无限成长，以及上述完整机制名。独立乘算是优先技术目标，尚无引擎可行性证据。其它数值按当前设计建议建立原型预期；如果实施前决定调整，先同步设计与本方案，再冻结测试输入，不能用修改预期掩盖实际失败。

测试分为功能验收和自然体验验收。功能验收要求数字、来源、状态与存档正确；自然体验验收要求正常发展能维护、晚期能救援、收集收益可感知。二者分别报告，任何一类未完成都不能宣称改版完整验收通过。

本轮只设计测试，不运行 `open_kaishek`、启动游戏、制造夹具、改 Mod 或发布 Workshop。紧急止损是设计中的第二轮备选，当前不启用也不写成必测功能。

## 4. 执行闸门与顺序

1. **G0 输入冻结。** 选定原型参数、版本、包与 fixture manifest；用例状态全部 `NOT RUN`。历史证据仅作种子和方法来源，不能继承为本版 PASS。
2. **G1 P 语言与包级检查。** 使用 `open_kaishek` 说明中真实存在的包级入口检查候选、实际使用的 P 语言夹具及必要资源。工具 PASS 后再进入对应探针/实机；失败或不能运行时先处理工具问题。

4. **G3 功能与中文 UI。** 按用例顺序执行起源/阶段/岗位、协同经济来源、奖励与冷却、项目/领袖、重载与迁移。运行必须使用实际正式效果、按钮和项目回调，不能只直接改出最终正确状态。
5. **G4 自然体验。** 在冻结的完整候选包运行正常发展、优先维护、优先清理和拖至 V 的路线，复核反馈是否缓解。
6. **G5 最终包复核。** 对最终包重跑 G1、翻译静态、中文加载及受影响回归，审计证据和未执行项；执行报告落入本目录。修改包哈希后旧结果只能作为历史证据。

### 5.1 避免把特质自身效果混入协同

特质增加或移除时，其原版效果也可能改变科研、效率、维护、宜居度等。**独立乘算对照必须保持真实特质集合不变**：从同一存档分叉，用临时诊断渠道只开关本机制，测出无协同 Y0 和开启后的 Y，再核对 Y/Y0。移除一个负面特质后直接比较总收入，不足以证明 5% 系数。

诊断开关只隔离协同贡献，不修改主体人口、U、R、其它修正或原有特质效果；它不能把预期 Y 写回岗位。正式无开关候选再验证同一结果，诊断夹具不得进入发布包。

### 5.2 数值精度与证据优先级

- 人口计数、特质键集合、n/R、票据、候选、冷却、项目/领袖/局势数量要求精确一致，不设百分比容差。
- U、M 等运算和真实毛产出优先取可审计存档/引擎数据；默认产出误差不超过 `max(0.0001, |预期产出|×0.0001)`，即相对 0.01%。U/M 的绝对偏差不超过 `0.0001`。
- 大层数另验相邻差分：`ΔM=0.05`，绝对误差不超过 0.0001；`ΔY=Y0×0.05`，使用同等产出容差。不能让大总量的相对误差吞掉漏掉一层的错误。
- UI 舍入与 OCR 只作展示证据；只有 UI 时按实际显示精度计算可能区间。观测精度不足以区分加算/乘算或一层变化，结果为 `BLOCKED`，不放宽误差直到“通过”。
- 月结算存量变化必须扣清维护、交易和事件收入，不能以顶部净额替代岗位毛产出。每个配对冻结两边日期、就业和经济输入，确认推进期间未发生人口增长或岗位切换等干扰。

### 5.3 长机制名的测试方法

先执行 UI-02 的完整字符串和本地化引用审计，再用通过 G1 的最小展示探针验证游戏实际渲染，最后在完整正式候选中执行 UI-03—UI-05。本轮只做文档中的名称计数与方案设计，不创建探针、不启动游戏。18 字/54 字节不等于引擎已经接受，更不代表 UI 宽度够用；名称是否支持要同时给出本地化解析与具体界面的结论。

分辨率目标为目标游戏原生可选且可运行的最低分辨率、1920×1080、2560×1440，分别检查合法的最小/默认/最大 UI 缩放。G0 登记引擎实际支持的组合；不支持的组合附设置证据说明范围，必需组合因环境不能执行则 BLOCKED。Windows 显示缩放与游戏 UI 缩放分别记录，不以修改 Windows 缩放代替游戏设置；截图/OCR使用原图物理像素坐标。

先在暂停的同一状态切换组合，再逐个打开国家修正列表/悬停、机制详情、起源/局势说明和维护/优化结果及三选一。全名与系数可分行；正常操作须能读到完整名称、5% 规则、U/R/T/M、覆盖和冷却。人工逐字核对全名，检查文字/图标/按钮边界，保存原图及 OCR；OCR 误识别需人工复核，单凭 OCR 成功不认定无截断。紧凑列表若原生截断，单独报告截断位置及可达全文路径；没有全文路径、溢出遮挡或操作受阻为 FAIL。重启读档后重新确认全名和数值，最小探针结果不能代替正式界面的 PASS。

## 6. 资源和状态覆盖方法

协同至少覆盖能量、矿物、食物（有使用食物的合法机械配置）、合金、消费品（适用政体）、凝聚力、贸易、三系科研与全部实际适用的战略/DLC 岗位资源。按目标游戏的资源和经济类别建立来源表；资源没有岗位来源时只审计该事实与非岗位排除，不伪造“原版岗位”。合法来源受必需 DLC 限制而当前未安装，记 `BLOCKED` 并收窄声明，不能记已通过。

配对的纯岗位、纯非岗位、混合来源、市场/附庸/贸易协定/双边转移分别记录。岗位收益应为 Y0×M，非岗位保持原阶段效果且没有协同；相同劳动力和效率下岗位/人口维护不变。先核对每种资源和类别，再比总收支。

阶段、项目、白绮与存档变更按用例指定的交叉点复测，不机械展开所有变量的笛卡尔积。完整核心矩阵两类政体都执行；昂贵的大层数/模板数量压力在一类跑全量，另一类保留最大压力及 R→R+1 哨兵。被测机制受政体或 DLC 分支影响时不能拿一类代替另一类。

同一个奖励项目需要审计「项目成功一次 → n+1 一次 → 保存候选 → 可重抽一次 → 最终选择一次 → 冷却递减一次 → 正确恢复项目」。如果存在等待选择，月度恢复不得重新发奖。读档至少覆盖重抽前、重抽后未选、冷却剩 2/1/0、待选期间已清理、两层耗尽、白绮恢复中与迁移完成。

## 7. 自然体验路线与通过条件

功能夹具的研究倍率或资源补给不得用于自然局。选尉官、两类机械政体，同一配置与种子下运行下列路线：

| 路线 | 决策约束与主要观察 |
| --- | --- |
| NAT-01 正常发展 | 按经济、殖民和科研需求发展，允许使用维护研究所但不专门极限刷维护员；记录首轮维护日期、传统进度、正常科技中断时间和经济缺口。 |
| NAT-02 优先维护 | 尽早投入社会学并使用研究所处理局势，定期维护、实际选奖励和 reroll；记录每轮研究投入、候选价值、减速机会成本、特质数量与产出收益。 |
| NAT-03 优先清理 | 尽早清理，之后继续优化；观察清理投入、+25% 重构和 5% 协同的组合、至少一次优化结果及奖励流程。 |
| NAT-04 拖至 V | 不维护、不清理、不用维护员减速直到自然到达 V，随后恢复正常投入完成一次维护和一次独立清理分支；记录研究进度、维护费与赤字恢复。 |

最小自然局规模：两政体×四路线×旧版/候选，共 16 局；两政体普通机械起源的正常路线另 2 局，第一种子合计 18 局。以第二种子再重复候选两政体的正常/拖延路线，共 4 局，总计 22 局。第二种子用于验证候选不是仅靠一个幸运开局通过，不用于声称未配对旧版也完成了跨版本比较。

22 局指各自独立的开局与路线；V 后维护/清理复制分支另外保留执行证据。下面的改版通过线只判定候选；旧版和普通起源记录对照结果，不要求它们满足新版功能或体验预期。

普通起源预算或可选栏不同导致配置不能合法完全复用时，记录差异并只作体验参照；主要跨版本判断使用同一个屎山起源的旧版与候选。开局随机事件和外部战争完整保留；显然由外部覆灭导致的样本标明干扰并补同条件样本，不能把起源导致的赤字失败当成外部干扰删除。

所有路线记录开局第 5/10/20/30 年的人口、已分配 J、n/U/R/M、资源毛产出和净收支、三系科研产出与速度、传统数、项目累计研究和局势。拖延路线另加第 50/75/80 年、实际进入 V 及救援前后的采样；默认 2200 开局对应 2250/2275/2280。按初始月速 1，n=0、J=0 的候选理论到 V 约 79.17 年；必须运行到实际 V 后再观察最多 20 年救援窗口，不能以 30 年或 80 年作为固定截止。维护/清理分支提前成功时记录成功日期，无需耗完观察窗口。

自然体验判定线：

1. 两类候选正常路线均在开局 10 年内自然完成首轮维护，不靠临时倍率/控制台；第二种子复验同标准。若失败，记录科研和资源来源瓶颈，反馈调整设计。
2. 自然 V 存档的复制分支分别完成一次维护和清理，最多观察 20 年；期间记录真实研究增长与经济代价。资源或研究长期停滞、到期仍未完成，记 `FAIL`，不能以受控 V 夹具成功替代。
3. 维护/优化结果确实改变有效层数及岗位毛产出，UI 能说明来源；研究所已分配劳动力能明显改变预测时间，额外凝聚力能在收入中追踪。
4. 旧版/候选/普通起源分别列出数据和开发者实玩记录。不能以“所有机械特质都收齐”或“面板百分比变大”独立宣布爽感解决；记录每次选择的用途、被迫中断普通科技的时间及重抽是否有帮助。

无限成长是用户指定目标，不因后期强于普通起源直接判功能失败。长期平衡风险如过早永久压低月速、工程学/社会学与协同组合太强，记录为具体观察和下一轮数值建议；不在测试中擅自加硬上限。

## 8. 证据、结果格式与收口

未来证据目录建议为 `shishan_code_origin/docs/evidence/feedback-redesign/<run-id>/`，不在 `mod/` 内。本轮只声明目录规划，不创建空报告冒充执行结果。每次保存如下结构：

```text
manifest.json                 # 游戏/工具/Mod/夹具身份、政体、语言、输入与包指纹
static/                       # open_kaishek 与本地化静态结果
cases/<case-id>/               # 操作、预期、实测、前后存档/哈希、原始日志、截图/OCR
natural/<government>/<route>/  # 决策记录、日期采样、项目及经济数据
results.json                  # 全部适用用例状态、证据路径、失败/阻塞原因
report.md                     # 面向评审者的功能、体验、边界结论
```

case 结果至少含 `case_id`、`run_id`、合同版本、输入指纹、前置条件、操作、独立计算的预期、实测、容差、状态、证据引用和失败最小复现。运行日志应在重启前归档，使用同一 userdir 时不得让后一次进程覆盖前一次证据。存档必须是真正游戏原生保存并能重载，手工写入的预期数据只可作为夹具输入。

状态只用 `PASS`、`FAIL`、`BLOCKED`、`NOT RUN`；`N/A` 仅适用于有来源/资格审计证明不存在的分支。缺语言运行时属于规定范围之外，不列为实机 PASS。所有其它语言报告为「静态校验通过」或静态失败，并写「运行时不在范围内」。

完整收口需要 G1 通过、独立乘算目标按证据证明或设计明确调整后重测、全部适用核心用例通过、关键迁移重载通过及自然体验判定通过。独立乘算不可行时先报告具体阻塞和兼容代价，不能把加算版本沿用本方案的乘算 PASS。遗留失败、必需能力/DLC/证据缺失或适用核心 NOT RUN 均阻止宣称改版完整验收通过。

修复后重跑失败用例和受影响的邻接矩阵：计数变化重跑乘算/迁移/普通奖励；经济通道变化重跑全资源来源；冷却变化重跑选择/重载/项目恢复；领袖变化重跑死亡/复活/科研/自然救援。测试通过后不因惯性无限扩大重复测试；版本、夹具或包发生新变化时才重新圈定影响范围。
